# ゴール

README.md が、人が読む入口として、目的・構成・インストール・複数アカウント・運用ルール・自動配布の節だけを持っている。README の「意図」の3節(「Claude Code テンプレートの意図」「プロンプト層(CLAUDE.md)の意図」「セッションの役割分割(PL / SE / PG / QA)の意図」)と「3層の守り」の節は無く、その中の、後で同じ機能を変えるときにも守る「なぜ」は、skill のフォルダの CLAUDE.md と、`.claude/rules/` のパス指定のルールに、skill `prompt-structure` の4段で移っている。「3層の守り」の中で「構成」に無いサーバー側の内容は、「運用ルール」にある。見出しの「使い方」は「インストール」になっている。

範囲外: permissions・フック・サンドボックスの変更(CLAUDE.md 原則1 のとおり、利用者に頼まれていない)、`claude/CLAUDE.md`・SKILL.md・settings・hooks・install の中身、「構成」の節のコメントの言い回し、採用済みの ADR の中の「README」の語。

# 設計

決定を1つ足すので、ADR 0020-1(`docs/adr/0020-1-reasons-in-path-rules.md`、状態「提案」)を書いた。書き換える README の行に付いた ADR の番号(0004-1・0005-1・0006-1〜3・0007-1・0009-1〜3・0010-1〜2・0011-1〜2・0012-1〜2)は、どれも README を置き場とする決定ではなく、README の行を消しても決定は変わらない。理由は各 ADR にあるので、「理由は ADR にある」とだけ書いた項目は移さずに消す。採用済みの ADR 0009-1・0011-2 の中の「README」の語は書き換えない。

動きは変わらないので、仕様は変えない。新しい名前は「パス指定のルール」の1つで、用語集に足す。

移し先の決め方:

- skill の規則の「なぜ」は、その skill のフォルダの `CLAUDE.md`。install は各 skill の `SKILL.md` だけをコピーするので、ほかのリポジトリには入らない(`install.ps1`・`install.sh` の Skills の行で確かめた)。
- `claude/CLAUDE.md`・settings・hooks の「なぜ」は、ADR 0020-1 のとおり `.claude/rules/` のパス指定のルール。
- 移した先は、skill `prompt-structure` の4段で書き、利用者の言葉の引用はコミットメッセージに書く(利用者が選んだ)。原則・目的・目指す状態は、README の項目にあった理由から SE が書いた案のまま入れる(利用者が選んだ)。
- 消すだけの項目: 規則やファイルの言い直し、理由が ADR にあるもの、skill の目的がそのまま理由になっているもの(`task-team-messaging` の知らせ方と、QA を fresh で起こすことは、それぞれの skill の「記録を根拠に動く」「独立」の段が理由なので、CLAUDE.md を作らない)、Claude Code の文書で引けること(パターンの書き方)。
