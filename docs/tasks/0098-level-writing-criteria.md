## 要件

### R1 各段に何を書くかの基準を、案を書く前に読む所に置く

- 要件: 今のまま・基準1つ(「下の規則とは別のやり方でも果たせる文にする」)・表全体の3つを、Gemini のタスク 0099 と同じ材料で比べて、置くかを決める。
- 要件: 比べた結果から、skill `prompt-structure` に、今フックにある段の問いの文と、表の「答える問い」の列(命題・原則・目的・規則の4行)を置く(利用者が選んだ「イ」)。
- なぜ: 利用者は、Gemini の PL のセッションに再編の作業をさせたら、この表を見せた瞬間に再編のやり方を見直した、と見ている。
- なぜ: 利用者は、問題の本質を、目的に手段(How)が書かれることではなく、命題・原則・目的・規則をどのような基準で書けばよいかが、Claude の中に無いことと見ている。そのために、5段を4段にするとき、消える「目指す状態」を目的に書き換えれば済むと考えてしまう。
- なぜ: 0095 で基準を足さないと決めたのは、命題・原則・目的・規則という単語から、各段に何を書くかを書かなくてもしかるべき再編ができると踏み、基準は二重記述になると考えたため(AI のジェミニは、単語から表のように分類できていた)。Claude はそのやり方で失敗したので、置かなければならないだろう、と利用者は考えを改めた(ADR 0095-1 の捨てた案2の撤回)。
- 受け入れ条件 R1-1: skill `prompt-structure` の目的「どの規則も、親の段を読めば、…」の下に、設計の「足す文」の2行と表がある
- 受け入れ条件 R1-2: 全体の CLAUDE.md・`claude/rules/claude-md.md`・書き換えた skill `prompt-structure` を渡した新しいセッション5つが、5つとも、命題は何のために存在するか、原則は何を大事にしてぶつかったら何を先にするか、目的はなぜ必要でどうなっていれば良いか、規則は具体的に何をするかを書く段だと答える
- 受け入れ条件 R1-3: 段の見出しを保存すると、skill `prompt-structure` の段の書き方に照らす問いが返る。段の書き方の文は、skill にだけあり、フックに無い

### 置くファイルと名前・データ

`claude/skills/prompt-structure/SKILL.md`(R1-1・R1-2): 「- 段は、命題・原則・目的・規則の順に、上の段が下の段を包含する。」の行の下に、次の「足す文」を置く。2行は、3つの新しいセッションに読ませ、どれも意図どおりに読んだ(「段は」の行は変えない)。

```markdown
- 原則・目的の見出しは、すぐ上の段(原則なら命題)から導き、下の段の手段の言葉を除いた文にする。(ADR 0061-1・0098-1)
- 命題・原則・目的・規則の各段に書くのは、次の表の問いの答え。(ADR 0098-1)

| 段 | 答える問い |
|---|---|
| 命題 | そもそも何のために存在するか |
| 原則 | 何を大事にして、ぶつかったら何を先にするか |
| 目的 | なぜ必要で、どうなっていれば良いか |
| 規則 | そのために具体的に何をするか |
```

- フックにあった文の「手段の言葉を入れない」は、肯定形の「手段の言葉を除いた文にする」に替えた(ADR 0027-1)。表の規則の行は、同じ理由で利用者の表の「/しないか」を除いた。
- 前の文は「段」に優先順位まで毎回書くと読まれたので、主語を「各段に書くのは」にした。原則の段の優先順位は、番号が決める。

`claude/hooks/ask_about_written_lines.py`(R1-3): `LAYER_QUESTION` を次の文に替え、上の注釈の ADR を「0061-1・0095-1・0098-2」にする。

```python
LAYER_QUESTION = "  3. 原則・目的の見出しは、skill `prompt-structure` の段の書き方に照らし、合わない所を直す。"
```

直した仕様(R1-3): `docs/specs/ask_about_written_lines.py.md`・`docs/specs/check_rule_documents_changed_by_shell.py.md`(設計のコミットで直してある)。
