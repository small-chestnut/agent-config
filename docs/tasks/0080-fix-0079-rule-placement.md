## ゴール

0079 で入れた規則と「なぜ」の、次の3か所が直っている。

1. `.claude/rules/global-claude-md.md` に、支える規則がもう無い目指す状態「用語に意味を添える時を、AI に見分けられない条件で決めていない規則になっている」とその下の1行が無い。消したわけは ADR 0079-1 にある。
2. 全体の CLAUDE.md の「IT やその分野の用語がある概念は、和語や一般の語に言い換えていない。(ADR 0079-2)」と「用語の無いものは、辞書どおりの意味の語を組み合わせて指している。(ADR 0079-2)」が、利用者に向けて書く文だけでなく、仕様・チケット・skill の文にも当たる所にある。
3. 原則2の、ファイル名・行番号・コマンド名・エラーメッセージを添える行の条件が、用語の無いものを語の組み合わせで指したときにも当たる。

なぜ: 0079 の SE が、main に入った後に読み直して見つけた。
- 1は、決まりを書く文書には今の決まりだけを置く、に反する。
- 2は、2行が原則2の下にあり、原則2は利用者に向けて書く文にだけ当たる。LogiFee で作った呼び名が広がったのは、仕様・チケット・skill を通ってだった。
- 3は、今の「用語だけでは」が、用語の無いものに当たらない。

SE は、0079 で skill `prompt-structure` を読まずに規則の案を書いていた。

範囲外: 0079 で決めたこと(ADR 0079-1・0079-2)そのもの。

#### 手順1(進捗2): 「なぜ」の文書から、見出しと1行を消す

`.claude/rules/global-claude-md.md` の原則2の中の、次の3行(見出し・空の行・規則の行)と、その後の空の行1つを消す。

前:

```
### 目指す状態: 説明は、利用者が既に目にしたものから始まる規則になっている

- 利用者は、AI の側の言葉から始まる説明を何度聞いても分からず、読む気をなくしかけた。

### 目指す状態: 用語に意味を添える時を、AI に見分けられない条件で決めていない規則になっている

- 利用者が用語を知っているかと、初めて出すかは、AI に見分けられない。

## 目的: 利用者が、説明を読んだあとの判断と操作を誤らないようにする
```

後:

```
### 目指す状態: 説明は、利用者が既に目にしたものから始まる規則になっている

- 利用者は、AI の側の言葉から始まる説明を何度聞いても分からず、読む気をなくしかけた。

## 目的: 利用者が、説明を読んだあとの判断と操作を誤らないようにする
```

消すわけ: 全体の CLAUDE.md に、用語に意味を添える時を決める行がもう無い。この目指す状態は、消した行を消したわけで、ADR 0079-1 の捨てた案1と理由1にある。決まりを書く文書には今の決まりだけを置く。

#### 手順2(進捗3): 用語の2行を、原則3の定石の見出しの下に移す

`claude/CLAUDE.md` の原則2の目指す状態「書く文は、その分野を知らない人にも分かりやすい」から、次の2行を消す。

前:

```
- 人間側の最適化の原則は、利用者に向けて書く文に当てている。
- IT やその分野の用語がある概念は、和語や一般の語に言い換えていない。(ADR 0079-2)
- 用語の無いものは、辞書どおりの意味の語を組み合わせて指している。(ADR 0079-2)
- ファイル名・行番号・コマンド名・エラーメッセージは、用語だけでは二通りに読めるときにだけ添えている。
```

後(手順3の書き換えも入れた形):

```
- 人間側の最適化の原則は、利用者に向けて書く文に当てている。
- ファイル名・行番号・コマンド名・エラーメッセージは、言葉だけでは二通りに読めるときにだけ添えている。
```

同じファイルの原則3の目指す状態「定石が固まった IT の分野では、IT の用語と定石のやり方を使っている」の下に、2行を次の順で入れる。

前:

```
### 目指す状態: 定石が固まった IT の分野では、IT の用語と定石のやり方を使っている

- IT の用語があるか分からない概念は、書く前に調べている。(ADR 0079-1)
- 進め方・仕組み(テスト・リリース・ブランチ運用・CI など)は、決める前に定石を調べ、あれば沿っている。
```

後:

```
### 目指す状態: 定石が固まった IT の分野では、IT の用語と定石のやり方を使っている

- IT やその分野の用語がある概念は、和語や一般の語に言い換えていない。(ADR 0079-2)
- IT の用語があるか分からない概念は、書く前に調べている。(ADR 0079-1)
- 用語の無いものは、辞書どおりの意味の語を組み合わせて指している。(ADR 0079-2)
- 進め方・仕組み(テスト・リリース・ブランチ運用・CI など)は、決める前に定石を調べ、あれば沿っている。
```

2行の文は変えない。

置き場の根拠:
- 原則2の1行目「人間側の最適化の原則は、利用者に向けて書く文に当てている。」で、原則2の下の行は、利用者に向けて書く文にだけ当たる。
- 0079 で消した「言葉は、広く使われている呼び名で書いている。」は、この見出しの下にあった(26f34dd の差分)。2行はその行の後を継ぐ。
- 「なぜ」の文書でも、2行を支える目指す状態「IT の用語がある所に、作った呼び名が無い規則になっている」は原則3の下にある。
- 「その分野の用語」は IT の用語ではないが、2行の主な対象は IT の用語なので、skill `prompt-structure` の「2つの状態にまたがる規則は、主な方の下に1回だけ置く」で、この見出しの下に1回だけ置く。
- 3行の順は、用語があるとき・あるか分からないとき・無いとき。

#### 手順3(進捗4): ファイル名などを添える行の条件を「言葉だけでは」にする

`claude/CLAUDE.md` の原則2の行の「用語だけでは」を「言葉だけでは」にする。前と後は手順2の1つ目の組にある。

わけ: 用語の無いものは、語を組み合わせて指す。「言葉」は、用語と語の組み合わせのどちらも指す。
