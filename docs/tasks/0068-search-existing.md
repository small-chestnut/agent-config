## ゴール

SE が新しい作りを設計する前に、同じことをする既にある機能と、反する決まり(ADR など)を探す手順を、skill `task-team-se` と全体の CLAUDE.md に足す。(目的に反する規則の抜けとして、PL が利用者に聞かずに回すタスク)

なぜ: LogiFee のタスク R-0718 で、SE(Opus 5.5 の medium)が既にある ADR-2842-3 に反する案を出し、製品に既にある入出金の組(`create_pair`)を調べずに、新しい消込の種類と振替の仕訳を設計した。利用者は製品の語で「組にしていく」と言っていた。後者は、Fable に替えた直後の SE が仕様とコードを grep して見つけた。今の決まりでは、SE が設計で読む ADR は書き換える所に付いた番号だけ(ADR 0006-1)で、全体の CLAUDE.md が全体を検索するのは影響を調べるときと原因がモジュールの外のときだけ。新しい作りの前に既にあるものを探す場面が、どちらにも無い。

範囲外: QA の設計レビューの見る所(ADR 0067-3)と、R-0718 の記録のほかの項目(手段を聞き続けた・段階に合わない直し方・数える前に言い切った など)。

## 受け入れ条件

- skill `task-team-se` に、新しい作り(機能・データ・処理の種類)を設計する前に、チケットに出る利用者の語と新しく作るものの名前で、仕様・skill・CLAUDE.md・コードをリポジトリ全体から grep して、既にあるものを探す手順がある。
- skill `task-team-se` に、同じことをする機能があれば、新しく作らずその機能を使う設計にする行がある。
- skill `task-team-se` に、反する決まりがあれば沿う設計にし、沿えなければ置き換えるかを設計の前に利用者に聞く行がある。
- skill `task-team-se` の、設計で読む ADR に、探して当たった所に付いた番号の ADR が入っている。
- 全体の CLAUDE.md に、新しい仕組みを作る前に、同じことをする機能と反する決まりを全体で探す行がある。
- 全体の CLAUDE.md の、リポジトリ全体を検索するときの行が、新しい仕組みの前の探しとぶつからない。

## 設計

### 読んだ ADR と照らした結果

- 書き換える行に付いた番号: 0006-1・0010-2・0006-2(skill `task-team-se` の「設計で読む ADR」の見出しと行)、0045-2(全体の CLAUDE.md の読み始めの行。触らないが隣の行)。
- ADR 0006-1 は「SE は書き換える所に付いた番号の ADR だけを読む」。新しい作りには書き換える所が無いので、反する決まりにたどり着かない。この範囲を広げるので、ADR 0068-1 で 0006-1 の、SE が読む ADR の範囲を置き換える(0006-1 は「採用」のまま)。0006-1 の理由(読む ADR がタスクの数に比例して増えない)は、探す語を新しい作りの語に絞ることで保つ。
- ADR 0067-3(QA の設計レビューで、既にある機能と反する決まりをチケットの語で grep する)とは重なるが、0067-3 の捨てた案5 のとおり SE と QA の2か所で止める。SE は設計を書く前、QA は書いた後で、役が違う。0067-3 は直さない。
- 探す所に `docs/adr/` を入れないのは、今の決まりには ADR の番号が付いた行が仕様・skill・CLAUDE.md・コードにあるため。LogiFee の ADR-2842-3 は仕様 `docs/specs/accounting/消込の流し込み.md` の行に付いていて「消込」で当たり、入出金の組は仕様 `docs/specs/accounting/入出金.md` に「組にする」で当たる(2026-11-12 に grep で確かめた)。
- ADR: [0068-1](../adr/0068-1-search-existing-before-new-design.md)(提案)。

## 実装

## レビュー

- 設計1(手順1・受け入れ条件3): 「沿えなければ、その決まりを置き換えるかを、設計の前に利用者に聞いている」は、決まり(手段)を置き換えるかを利用者に選ばせる問いで、全体の CLAUDE.md の「利用者に聞くのは、目的と「なぜ」だけ」(ADR 0063-1)と「作業するリポジトリの中の手段が反していたら、自分で直すか消している」(ADR 0046-3)に反する。聞くのは、ゴールの「なぜ」とその決まりの「なぜ」がぶつかるときに、前の理由を撤回するか、の形にする(ADR 0068-1 の理由4も合わせて直す)。
- 設計2(手順1・3): 「新しい作りの前に既にあるものを探す」が、skill `task-team-se` の見出しと全体の CLAUDE.md の手順3の3行目の2か所に同じ規則として入る。ADR 0063-1 の理由3は「同じ規則は1か所」。全体の CLAUDE.md は SE も読むので、探す規則と、当たったときにどうするかは CLAUDE.md の1か所に置き、skill には SE だけの手順(探す語の選び方と、当たった所の ADR 番号を集める行)だけを残す形にする。
- 設計3(ADR 0068-1 の理由2): 「読む量は…ADR の総数にもリポジトリの大きさにもよらない」は確かめていない言い切り。grep の当たりはその語を使う行の数で、リポジトリが育てば増える。ADR 0006-1 の理由に照らして言えるのは「ADR の総数とタスクの数によらない」まで。
