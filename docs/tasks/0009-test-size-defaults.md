# ゴール

新しいリポジトリでも、リポジトリの CLAUDE.md に書かずに、小・中・大のテストの中身と、いつどの大きさを流すかが決まる。既定はグローバルの CLAUDE.md 原則3 に置き、リポジトリに決まりがあればそちらに従う。task-team を使わない1つだけのセッションも、同じ時と量で流す。CI が無いリポジトリでも、中と大が一度も流れないことが無い。

範囲外: 各リポジトリに CI を作ることと、`codex/AGENTS.md` にテストの決まりを足すこと。

# 受け入れ条件

1. グローバルの CLAUDE.md(`claude/CLAUDE.md`)原則3 に、小・中・大の中身の既定(使う資源で分け、画面を動かすテストと速さの計測は大)がある。
2. グローバルの CLAUDE.md 原則3 に、中と大にタグで印を付け、印の無いテストを小とする行と、小だけ・小と中・大を流すコマンドをリポジトリの CLAUDE.md に書く行がある。
3. グローバルの CLAUDE.md 原則3 に、書いている間・マージ前・マージ後に流す大きさと、CI が無いときにマージ前に手元で流す大きさがある。
4. `task-team-lead` と `task-team-pg` に、小・中・大の中身を「対象リポジトリの CLAUDE.md に従う」とする行が無い。
5. `task-team-pg` に、CI が無いリポジトリで、QA に頼む前に小と中の全部と変えた使い方の大を流す行がある。
6. `task-team-lead` に、作業ブランチの CI が全部緑になってからマージする行がある。
7. この変更で足した行のうち、ADR 0009-1〜0009-3 で決めた行に、ADR の参照が付いている。
8. README の「セッションの役割分割」の節に、小・中・大の既定の置き場・CI が無いときと1つだけのセッションの流し方と、その理由がある。
9. `docs/用語集.md` の「テストの大きさ」の意味が既定の中身を指し、大きさの印の行がある。
10. どの SKILL.md の箇条書きの行も 60 字以内(`python -m unittest discover -s tests` が通る)。

# 設計

決定は [ADR 0009-1](../adr/0009-1-test-size-by-resources.md)・[ADR 0009-2](../adr/0009-2-test-size-tags.md)・[ADR 0009-3](../adr/0009-3-test-run-stages.md)(どれも採用)。書き換える行に付いた ADR は 0004-1・0005-1 で、ぶつからない。する人は、どの手順も PG。

出典: 大きさの定義は Software Engineering at Google 11章(https://abseil.io/resources/swe-book/html/ch11.html)。テストごとに大きさを書く形は Bazel の `size`(https://bazel.build/reference/test-encyclopedia)。マージ前の分を速く終え、遅いテストを後の段で流すのと、マージ前に手元でテストを通すのは、Martin Fowler「Continuous Integration」(https://martinfowler.com/articles/continuousIntegration.html)。

## 手順: 規則の文書を直す

下の行を、そのとおりの文で入れる。「→」は置き換え、「足す」は新しい行、「消す」は行を消す。フック(`ask_removable_words.py`)が問い返してきても、文は変えない。CLAUDE.md と SKILL.md の箇条書きは `rule_length` で数え済み(足す行はすべて 60 字以内)。main とぶつかったら、main を取り込んで、この設計の文を残す。

### `claude/CLAUDE.md`

原則3 の「### 目指す状態: 変更が意図どおりかを自分で確かめてから、終わったと報告している」の箇条書きの後(「### 目指す状態: 定石が固まった IT の分野では、…」の前)に、次を足す。

```
### 目指す状態: テストの大きさは、テストが使う資源で決まっている(ADR 0009-1)

- 小は、1つのプロセスで終わり、ファイル・DB・ネットワーク・sleep を使わない。
- 中は、1台のマシンで終わり、大に当たらないもの。
- 大は、localhost の外に触るか、ブラウザかアプリの画面を操作するか、速さを測る。

### 目指す状態: テストの大きさが、テストに印で書いてある(ADR 0009-2)

- 中と大には、テストの道具のタグで `medium`・`large` を付けている。
- タグの無い道具では、ファイル名に `.medium`・`.large` を入れている。
- 印の無いテストは小。
- リポジトリ直下の CLAUDE.md に、小だけ・小と中・大を流すコマンドがある。

### 目指す状態: テストは、大きさごとに決まった時に流れている(ADR 0009-3)

- 書いている間は、変えた所の小さいテストだけを流している。
- CI があれば、マージの前に小と中を、後に大を CI が流し、緑を待っている。
- CI が無ければ、マージの前に、小と中の全部と、変えた使い方の大を流している。
```

### `claude/skills/task-team-pg/SKILL.md`

「### 目指す状態: 受け入れ条件ごとに、先に失敗するテストがある」の下:

- 「手元で流すのは、ビルドと、変えた所の小さいテストだけ。」→「書いている間に手元で流すのは、ビルドと、変えた所の小さいテストだけ。(ADR 0009-3)」
- 「中・大のテストは手元で流さない。CI が流す。」→「CI があれば、中・大のテストは手元で流さない。CI が流す。(ADR 0009-3)」
- 「小・中・大の中身は、対象リポジトリの CLAUDE.md に従う。」→「CI が無ければ、QA に頼む前に、小と中の全部と、変えた使い方の大を流す。(ADR 0009-3)」

### `claude/skills/task-team-lead/SKILL.md`

「### 目指す状態: 終わったタスクは、リポジトリに残り、チームは閉じている」の下:

- 「CI の小・中のテストが緑になってから、CLAUDE.md 原則1 のとおりマージして push、できなければ PR。」→ 次の2行。

```
- 作業ブランチの CI が全部緑になってから、CLAUDE.md 原則1 のとおりマージする。(ADR 0009-3)
- マージできなければ PR を作っている。
```

- 「小・中・大のテストの中身と CI の名前は、対象リポジトリの CLAUDE.md に従う。CI が無ければ待たない。」→「CI が無ければ待たない。(ADR 0009-3)」

### `README.md`

「## セッションの役割分割(PL / SE / PG / QA)の意図」の節:

- 「- **テストを流す時と量は、継続的デリバリーのデプロイパイプラインと、テストの大きさ(小・中・大)の定石に沿う**。」→ 太字の後ろ・「。」の前に `(ADR 0009-3)` を付ける。
- その下の「  - メインに入った後か定時: …」の項目(2行)の後に、次の2項目を足す。

```
  - CI が無いリポジトリ: メインに入れる前に、小・中の全部と、変えた使い方の大きいテストを手元で流す(task-team では PG)。
    CI の代わりがほかに無く、流さないと中と大が一度も流れないため
  - task-team を使わない1つだけのセッションも、同じ時と量で流す。決まりはグローバルの CLAUDE.md 原則3 にあり、どのセッションも読む
```

- 「  小・中・大の中身と CI の名前は、リポジトリごとに違うので、各リポジトリの CLAUDE.md に書く。」→ 次の4行。

```
  小・中・大の中身は、Software Engineering at Google のテストの大きさ(テストが使ってよい資源で分ける)に沿い、既定をグローバルの CLAUDE.md 原則3 に置く(ADR 0009-1)。
  ブラウザやアプリの画面を操作するテストと速さの計測は、1台のマシンで終わっても大に入れる。遅く、メインに入れる前の10分に収まらないため。
  大きさは、中と大にだけテストの道具のタグで印を付け、印の無いものを小とする(ADR 0009-2)。PL は、作業ブランチの CI が全部緑になるのを待ってマージする。
  新しいリポジトリの CLAUDE.md にはまだ書かれておらず、大きさが決まらなかったので、既定をグローバルに置いた。リポジトリに決まりがあれば、そちらに従う(ADR 0004-1)。
```

- 「テストの大きさ」の行の意味 → 「テストが使う資源の範囲。小は1つのプロセス、中は1台のマシン、大はその外か画面の操作か速さの計測。既定はグローバルの CLAUDE.md 原則3」
