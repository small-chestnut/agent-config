# ゴール

新しいリポジトリでも、リポジトリの CLAUDE.md に書かずに、小・中・大のテストの中身と、いつどの大きさを流すかが決まる。既定はグローバルの CLAUDE.md 原則3 に置き、リポジトリに決まりがあればそちらに従う。task-team を使わない1つだけのセッションも、同じ時と量で流す。CI が無いリポジトリでも、中と大が一度も流れないことが無い。

範囲外: 各リポジトリに CI を作ることと、`codex/AGENTS.md` にテストの決まりを足すこと。

# 受け入れ条件

1. グローバルの CLAUDE.md(`claude/CLAUDE.md`)原則3 に、小・中・大の中身の既定(使う資源で分け、画面を動かすテストと速さの計測は大)がある。
2. グローバルの CLAUDE.md 原則3 に、中と大にタグで印を付け、印の無いテストを小とする行と、小だけ・小と中・大を流すコマンドをリポジトリの CLAUDE.md に書く行がある。
3. グローバルの CLAUDE.md 原則3 に、書いている間・マージ前・マージ後に流す大きさと、CI が無いときにマージ前に手元で流す大きさがある。
4. `task-team-lead` と `task-team-pg` に、小・中・大の中身を「対象リポジトリの CLAUDE.md に従う」とする行が無い。
5. `task-team-pg` に、CI が無いリポジトリで、QA に頼む前に小と中の全部と変えた使い方の大を流す行がある。
6. `task-team-lead` に、待つ CI を、push したコミットに付いたチェックの全部とする行がある。
7. この変更で足した行のうち、ADR 0009-1〜0009-3 で決めた行に、ADR の参照が付いている。
8. README の「セッションの役割分割」の節に、小・中・大の既定の置き場・CI が無いときと1つだけのセッションの流し方と、その理由がある。
9. `docs/用語集.md` の「テストの大きさ」の意味が既定の中身を指し、大きさの印の行がある。
10. どの SKILL.md の箇条書きの行も 60 字以内(`python -m unittest discover -s tests` が通る)。
