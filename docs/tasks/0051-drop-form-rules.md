## ゴール

`claude/` の規則が、行の位置や問いの数といった形でなく、その規則が守りたい中身を指している。

- skill `task-team-se` の問いの行が、分からないこと1つに問い1つの形になっている。今の「3〜5個」は、分からないことが1つでも問いを3つ作らせ、利用者の答える手間を増やす。AskUserQuestion は1回に4問までなので、5個は1回では聞けない。この行は、説明し直すときに止まっている所を探す全体の CLAUDE.md の行を写したもので、目的が違う。
- 「◯行目」と書いた5か所から、行の位置が外れている。大事なのは順番か、名前で探せる行かで、何行目かではない。
  - 全体の CLAUDE.md の返答の目指す状態と、その下の2行(結論・結論だけの返答)。目指す状態の書き換えは、利用者が合意した。
  - skill `draw-figure` の図の置き場の行。
  - skill `task-team-se` のステータスの行と利用者待ちの行。PL と子セッションは、この2つの行を名前で探していて、位置を見ていない。

なぜ: atcoder のタスク 0007 で、PL が見せた返事の例の行数(3行)を SE が決まりにし、利用者が決めていない形が決まりになった。利用者は、行数は出力の本質ではないと言った。形を決まりにすると、型を守ることが目的になる。

範囲外: 全体の CLAUDE.md の「止まっている所を確かめる問い」の行・skill `task-team-lead` の `git worktree list` の1行目の行・skill `task-team-se` の完了条件の「件数のような」の行・「1行で書く」「1行ずつ並べる」の形の規則。

## 受け入れ条件

1. 全体の CLAUDE.md の返答の目指す状態が「返答は、最初に結論が分かり、1ターンの分をスクロールせずに読み切れる」。
2. 全体の CLAUDE.md の規則に「返答は、結論から書いている。」がある。
3. 全体の CLAUDE.md の規則に「結論だけの返答には、水平線を引いていない。」がある。
4. skill `draw-figure` の規則に「図は、結論の直後、補足の文より先にある。」がある。
5. skill `task-team-se` の規則に「問いは、分からないこと1つに1つ作り、1行で答えられる形で、AskUserQuestion で聞いている。」がある。
6. skill `task-team-se` の規則に「書き足す形なら、「ステータス: 」の行と節を一緒に書き足す。(ADR 0051-1)」がある。
7. skill `task-team-se` の規則に「利用者待ちの行は、待つことが無いとき `- 利用者待ち: なし`。」があり、その次の行は「その下に、サブタスクを…」のまま。
8. `claude/` で「行目」を含む行は、skill `task-team-lead` の `git worktree list` の行の1件だけ。
9. `claude/` で「3〜5」を含む行は、全体の CLAUDE.md の止まっている所を確かめる問いの行の1件だけ。
10. `claude/` で ADR 0024-2 を指していた行は、どれも ADR 0051-1 を指している。
11. ADR 0024-2 の状態が「置き換え済み(0051-1)」。
