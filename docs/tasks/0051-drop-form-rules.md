# 0051-drop-form-rules

ステータス: 未着手

## ゴール

`claude/` の規則が、行の位置や問いの数といった形でなく、その規則が守りたい中身を指している。

- skill `task-team-se` の「問いは、1行で答えられるものを3〜5個、AskUserQuestion で。」が、分からないことの数に合う形になっている。今の行は、分からないことが1つでも問いを3つ作らせ、利用者の答える手間を増やす。AskUserQuestion は1回に4問までなので、5個は1回では聞けない。この行は、説明し直すときに利用者が止まっている所を探す、全体の CLAUDE.md の「止まっている所を確かめる問いは、1行で答えられるものを3〜5個にしている。」を写したもので、目的が違う。
- 「◯行目」と書いた5か所から、行の位置が外れている。大事なのは順番か、名前で探せる行かで、何行目かではない。
  - 全体の CLAUDE.md の目指す状態「返答は、1行目で結論が分かり、…」は「返答は、最初に結論が分かり、…」に、規則「返答の1行目には、結論を書いている。」は「返答は、結論から書いている。」の形になっている(目指す状態の書き換えは利用者が合意した)。「結論の1行だけの返答は、…その1行で出している。」も「結論だけの返答」の形になっている。
  - skill `draw-figure` の「返答の1行目の結論の直後」が「結論の直後」になっている。
  - skill `task-team-se` の「書き足す形なら、1行目を「ステータス: 」にして…」と「1行目は `- 利用者待ち: なし`。」から位置が外れている。PL と子セッションは、この2つの行を名前で探していて、位置を見ていない。

なぜ: atcoder のタスク 0007 で、PL が見せた返事の例の行数(3行)を SE が決まりにし、利用者が決めていない形が決まりになった。利用者は、行数は出力の本質ではないと言った。形を決まりにすると、型を守ることが目的になる。

範囲外: 全体の CLAUDE.md の「止まっている所を確かめる問い」の行(止まっている所を探す目的には3〜5個が合う)・skill `task-team-lead` の「既定のブランチの作業ツリーは、`git worktree list` の1行目。」(git の出力の事実で、位置が中身)・skill `task-team-se` の完了条件の「件数のような」の行(壁打ちの途中)・「1行で書く」「1行ずつ並べる」の形の規則。
