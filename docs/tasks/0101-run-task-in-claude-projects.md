# 0101-run-task-in-claude-projects

ステータス: 未着手

## ゴール

実際の小さいタスク1つを、プロジェクトのクラウドのスレッドで最後まで進め、task-team の手順と規則がどれだけ減らせるかを確かめる。

## 要件

- R1 要件: 実際の小さいタスク1つを、スレッドで最後まで試す(利用者が「続ける」と答えた)。agent-config の決まりは、環境のセットアップスクリプトで届ける(ADR 0100-1)。環境 `agent-config-trial` が残っていれば、それを使う。
  - なぜ: task-team に書いてある手順と規則を、「プロジェクト」機能にカバーさせて減らすため。1回目の試験は、リポジトリの無いプロジェクトで、決まりが届くことだけを確かめた。
- R2 要件: 1回目の試験で確かめなかったもの(リポジトリを付けたプロジェクト・QA の独立・マージの担当)と、確かめきれなかったもの(利用者を待つことが、Overview とプロジェクトの会話のどちらに出るか)を、同じタスクで見る。
  - なぜ: 肩代わりする見込みの 72 行のうち、利用者待ちとかんばんの待ちの行は、肩代わりされるかが決まっていない(ADR 0100-1 の理由4)。公式文書に無い3つは、SE・PG・QA のやりとりの規則が消えるか書き換えになるかを決める(理由5)。
- R3 要件: SE・PG・QA の仕事を、スレッドとサブエージェントのどれに割り振るかは、始める前に利用者に聞く。SE の案は、SE と PG の仕事を同じスレッド1本で、QA の仕事をそのスレッドのサブエージェントでする形。
  - なぜ: SE の案は、ADR 0057-2 の捨てた案3の理由(利用者が開いて止めたり口を挟んだりできなくなる)と、ADR 0007-1 の理由1(SE の会話を知らない別のセッションが読むことが、利用者の代わりの同意になる)と逆向き。0100 では、この2つを利用者に伝えずに案を出した。この2つの理由を撤回するかを、1回だけ聞く。
- 範囲外: この PC が要る仕事。複数のスレッドは、割り振った結果スレッドが2本以上になったときだけ見る。
- 試すタスクを選ぶことと、クラウドの操作をすることは、利用者に聞く。
