## ゴール

QA の指摘を、直さないと通せないものと、直さなくてよいもの(Nit)に分ける決まりを、QA の規則に足す。

範囲外: code-review の skill そのものの出し方と、0085 までに決めたレビューの回数(設計と実装に1回ずつ・直しの確かめ1回)。

## 要件

### R1 直さないと通せない指摘と Nit の境目

- 要件: 直さないと通せない指摘は、要件・受け入れ条件・設計・規則に合わない所。それ以外は Nit。
- なぜ: 無限のレビューにしない。完璧かどうかでなく、変更が目的を果たすかで通す(良いレビューの範囲の定石)。
- 受け入れ条件 R1-1: QA の skill に、要件・受け入れ条件・設計・規則に合わない所だけを直さないと通せない指摘とし、それ以外を Nit とする行がある。

### R2 Nit の印

- 要件: Nit の指摘には、頭に「Nit: 」を付ける(Google の手引きと同じ印)。
- なぜ: R1 と同じ。読む役割が、直さなくてよい指摘を一目で分けられる。
- 受け入れ条件 R2-1: QA の skill に、Nit の指摘の頭に「Nit: 」を付けて書く行がある。

### R3 直しを頼むのは直さないと通せない指摘だけ

- 要件: QA が直しを頼むのは、直さないと通せない指摘だけ。Nit だけなら、指摘が無いときと同じに通す。
- なぜ: R1 と同じ。
- 受け入れ条件 R3-1: QA の skill に、直しを頼むのは直さないと通せない指摘だけで、Nit だけなら指摘が無いときと同じに進める行がある。

### R4 Nit を直すかは作業をした役割が決め、直しの確かめは頼んだ指摘だけ

- 要件: Nit を直すかは、その作業をした役割(設計は SE、実装は PG)が決める。直しの確かめで QA が見るのも、直しを頼んだ指摘だけ。
- なぜ: R1 と同じ。
- 受け入れ条件 R4-1: SE と PG が読む skill に、Nit を直すかは作業をした役割が決める行がある。
- 受け入れ条件 R4-2: QA の skill に、直しの確かめで見るのは直しを頼んだ指摘だけとする行がある。
