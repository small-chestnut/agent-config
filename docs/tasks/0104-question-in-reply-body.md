## ゴール

返答を、利用者が上の結論と、あれば下の質問だけを読めば、分かったことと答えることをつかめる形にする。

範囲外: アプリの wrap_up の指示そのもの(agent-config からは変えられない)。

## 要件

### R1 結論と質問だけを読めば済む

- 要件: 返答は、結論と、あれば質問だけを読めば、分かったことと、何を答えるかと、選ぶのに要ることがつかめる形にする。補足は読み飛ばしてよいものにし、結論と補足の間に水平線を引く。質問は、本文の最後か次の一手の枠(wrap_up)のどちらに出してもよい。
- なぜ: 結論・水平線・補足・水平線・質問の形は、利用者が上の結論と、あれば下の質問だけを読めば済むための仕組み。質問が本文か枠かは本質ではなく、重ならなければ枠だけでよい(利用者、2026-11-27)。0103 の SE の返答には、水平線が無く、どこから読めばよいか分からないもの(「LogiFee で SE を開始するたびに…」)と、答えに要る「まだ決まっていないこと」と選択肢が補足に入っていて読み飛ばせないもの(「「向き」とは…」)があった。
- 受け入れ条件 R1-1: 質問のある返答で、補足を読まずに、結論と質問だけから、何を答えるかと、選ぶのに要ることが分かる。
- 受け入れ条件 R1-2: 補足のある返答で、結論と補足の間に水平線がある。

### 手順

1. (R1・ADR 0104-1)`claude/CLAUDE.md` を次のとおりに直す。行の文は、見出しを足すほかは1字も変えない。
   - 「## 目的: 書く文は、曖昧さが無く、簡潔で、順序立っている(様態の公準)(ADR 0084-4)」の下から、「- 返答は、結論から書く。」「- 補足は、結論の下に水平線を引いて、400 字までで書く。」「- 400 字に収まらない補足は、数ターンに分けて出す。」「- 質問は、補足の下にもう1本水平線を引いて、その下に書く。」の4行を除く。この見出しの下には、「- 説明は、…」「- 数式で表せる概念は、…」「- 画面と印刷物に出るものが変わる提案には、…」の3行が残る。
   - その3行の後、「## 目的: 説明し直すときは、…」の前に、空行を挟んで見出し「## 目的: 利用者が、返答の結論と、あれば質問だけを読めば、分かったことと、何を答えるかと、選ぶのに要ることをつかめる(ADR 0104-1)」を置き、空行の後に、除いた4行を元の順に並べる。
   - 確かめ方: `git diff claude/CLAUDE.md` で、足した行が見出しの1行(と空行)だけで、ほかは4行が移っただけであること。
2. (R1-1・R1-2)利用者が、インストール後の返答を確かめる。
   - 何を: main へのマージとインストール(PL がする)の後に開始した子セッションの、質問のある返答を1つ読む。補足を読まずに、結論と質問だけから、何を答えるかと選ぶのに要ることが分かるか、結論と補足の間に水平線があるかを見る。
   - ゴールにどうつながるか: 変えたのは Claude が読む文で、返答の形が変わったかは、実際の返答を読むほかに確かめられない。
   - なぜ利用者の手でか: 結論と質問だけで答えられるかは、読む利用者にしか言い切れない。
   - 手順: 次に作るチームの SE が、最初に質問を出した返答を読む。
   - 終わったら利用者が返すこと: 答えられたか。答えられなければ、その返答のどこが読み飛ばせなかったか。
   - 元に戻せるか: 戻せる(読むだけ)。
