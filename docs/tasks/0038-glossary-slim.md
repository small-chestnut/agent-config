# ゴール

なぜ: 用語集の目的は、AI がその場で付けた例えや別の呼び名が文書に漏れ、それが語の意味になるのを防ぐこと。コードの名前は検索すれば見つかるので、載せなくてよい。

範囲外: ほかのリポジトリの用語集の書き換え。skill の文の書き換え(用語集の列に触れている skill は無い)。main へのマージ・push・`install.ps1 -Yes`(PL がする)。

# 設計

## 書き換える所と ADR

- `claude/CLAUDE.md` の目指す状態「業務の言葉1つに、コードの名前が1つ対応している」の見出しと、その下の列を決める1行。どちらにも ADR の番号は付いていない。ADR を「用語集」で探して当たった 0022-1 は記録の数え方の話で、読む ADR ではない。
- 用語集の形は、ほかのリポジトリに配る文書の形を決めるので、ADR 0038-1(状態: 提案)に書いた。列を決める1行の末尾に「(ADR 0038-1)」を付ける。`claude/CLAUDE.md` は決まりの文書なので、それ自体が仕様。番号は行にだけ付ける。
- 見出しを替えるのは、前の見出しが、捨てる狙い(言葉1つにコードの名前を1つ対応させる)を言っているから。
- 「クラス・テーブル・列・画面の見出しに…付けた名前は…用語集に入っている」の行も替える。列が無くなると、英語のクラス名などを用語の行として載せる、とも読めるから。新しい行は、載せるのが言葉であって、コードの名前ではないことを言う。
- 見出しの下の残りの4行は、新しい見出しの下でも意味が変わらないので、そのまま残す。
- 「なぜ」は ADR 0020-1 に従い、`.claude/rules/global-claude-md.md` の原則3「言葉」に1行で置く。

## 用語集から消す語と、意味の欄の直し

- 消す7語: タスクの番号・タスク名・ADR の番号・仕様の「ADR」の節・機能の節・テスト一覧・確かめのコマンドの一覧。どれも普通の言葉か、見出しやファイルの名前で、このリポジトリを読まなくても意味が分かる。ADR の番号の形(`0004-1`)は skill `task-team-se` にあり、用語集には要らない。
- 残す23語は、どれもこのリポジトリの決まり・skill・hooks で使われていて(検索で確かめた)、このリポジトリで付けた意味を持つ。
- 「コードの名前」の欄にしか無かった、意味に欠かせないことは、意味の欄に移す。モジュールの「このリポジトリでは skill 1つか hooks のファイル1つ」と、中身の印の「`docs/` を除いた」の2つ。ほかの語の意味の欄は、今の字のまま。
- 表の上の「このリポジトリには画面が無いので、…」の1行は、コードの名前の列の説明なので消す。
