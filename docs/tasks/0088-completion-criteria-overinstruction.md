# 0088-completion-criteria-overinstruction

ステータス: 未着手

## ゴール

skill `task-team-se` の完了条件の規則(「完了条件は、件数のような、確かめて言い切れる事実にしている」と、ADR 0035-4 の「完了条件は、利用者が見る画面に出るもの(一覧の件数など)にしている」)が、SE に「やることの中身」として読まれず、「終わったかを確かめる物差し」として働く形になっている。

なぜ: LogiFee の七海の取り込み(R-0765)で、SE(Opus 5.5)が、管理部が「勘定科目が間違い」と答えた行を、直しても開発者コンソールの未消込の数が減らないという理由で、直す予定から外していた。利用者に言われるまで気づかなかった。この2行を、形まで決めた指示として字面どおりに当てはめ、画面の数に出ない誤りを落とした(LogiFee の SE のフォークからの知らせ)。利用者の言葉:「例えば、「完了条件は、画面に出る件数で書く」と書かずとも、元のモデルの精度を信頼してもいい気がするんよな　無駄とは言わないが、過剰指示って気がする」。利用者は、決まりに例外をいちいち書き足すのは融通が利かない、という考え。同じタスクでは、ほかの決まりも字面どおりに当てはめた誤りが2つあった(仮の移行日を動かせない決まりとして扱った・「元のデータは手を入れずに置く」を先方が誤りと答えた値にまで当てはめた)。

範囲外: LogiFee のリポジトリの直し。
