## ゴール

問題に案を出すとき、一番の原因に対応する案を主にし、原因に触らない楽な迂回策で済ませないことを、全体の規則にする。

範囲外: LogiFee の記憶と ADR-2873 の下書きの扱い(LogiFee の作業)。原因への対応のほかの「楽な方へ」の偏り。

## 壁打ち

### 固まった要件

- 問題には一番の原因に対応する案を出し、原因に触らない楽な迂回策(台数・並列・キャッシュなど)で済ませない。(PL のタスクの文)
- 嫌うのは迂回策そのもので、特定の手ではない。(PL のタスクの文)
- LogiFee だけでなく、どのリポジトリでも効くようにする。(PL のタスクの文)
- 急ぐ場面で迂回策を先にするのはやむを得ないが、それは暫定対応で、恒久対応ではない。迂回策で済ませたことにしない。(利用者の答え)
- 扱うのは問題の原因への対応だけ。ほかの「楽な方へ」の偏り(最初の手段で比べない・テストが通った時点で終える)は入れない。(利用者の答え)

### なぜ

- 原因を残すと、迂回策はすぐ追い越される。LogiFee の UI テストは、台を分けても6週間で約31分に戻る見込みだった。(LogiFee の記憶 `fix-cause-not-throughput.md`)
- 迂回策で済ませた案は、利用者が見抜いて突き返すまで残る。利用者に、AI の出力を疑って見張る負担が来る。(SE のまとめ。README の「なぜ」の、利用者が AI の出力をつかむ認知負荷に当たる。利用者はこの答えを読んで設計に進めると答えた)

### 分かっていること

- `claude/` と `skills/` に、問題の原因への対応を書いた規則は無い(PL と SE が「原因」「迂回」「根本」で検索)。
- 全体の CLAUDE.md は、どの会話でも読まれる。task-team-se だけに置くと、SE を通さない会話(デバッグ・CI の調査など)では効かない。LogiFee で迂回策を出したのは SE だが、同じ偏りは SE に限らない(PL の答えの、文面が満たせる手段で止まる偏り)。
- 同じ規則は文書をまたいでも1か所にだけ置く(skill `prompt-structure`)。全体の CLAUDE.md に置けば、SE の壁打ちにも効く。
- IT の用語は「根本原因分析」(root cause analysis)。迂回策は「ワークアラウンド」(workaround)。
- 障害対応の定石では、原因に触らず症状を止める「暫定対応」(workaround)と、原因を取り除く「恒久対応」(permanent fix)を分け、暫定対応のあとに恒久対応を問題管理で追う(ITIL のインシデント管理と問題管理)。

## 設計

### 書き換える所と、付いた ADR

- `claude/CLAUDE.md` の、原則2(人間側の最適化)の目的「利用者が、説明を読んだあとの判断と操作を誤らないようにする」。目的の見出しに ADR は無い。足す目指す状態の隣の「規則や作りの理由を聞かれた答えは…」には ADR 0046-2 が付くが、その行は書き換えない。
- `.claude/rules/global-claude-md.md` の、原則2(人間側の最適化)。今は上の目的の節が無い。
- 仕様: 全体の CLAUDE.md はプロンプトなので、それ自体が仕様。`docs/specs/` は直さない。
- skill `task-team-se` は直さない。全体の CLAUDE.md は SE の会話でも読まれ、同じ規則を2か所に置かない(ADR 0066-1 の捨てた案2)。

### 手順(する人: PG)

1. `claude/CLAUDE.md` の「### 目指す状態: 手順の説明には、そのとおりにやっても失敗する条件まで入っている」の行の次の空の行のあとに、次の4行と空の行を足す(「### 目指す状態: 規則や作りの理由を聞かれた答えは…」の前に入る)。

```
### 目指す状態: 問題への案は、根本原因を取り除いている(根本原因分析)(ADR 0066-1)

- 案を出す前に、問題の根本原因を確かめている。
- 主な案は、根本原因を取り除く恒久対応にしている。
- 根本原因に触らない回避策は、暫定対応と言い、恒久対応と並べて出している。
```

2. `.claude/rules/global-claude-md.md` の「### 目指す状態: 説明は、利用者が既に目にしたものから始まる規則になっている」の節の終わり(「## 目的: 利用者が、手段と目的の矛盾を探して AI に突きつけずに済む」の前)に、次の節を足す。

```
## 目的: 利用者が、説明を読んだあとの判断と操作を誤らないようにする

### 目指す状態: 問題への案が、根本原因を取り除く規則になっている

- 根本原因を残すと、回避策はすぐ追い越される。
- 利用者は、回避策で済ませた案を見抜いて突き返す役を負いたくない。
- 嫌うのは回避策で済ませることで、特定の手ではない。
- 急ぐ場面の回避策はやむを得ないが、暫定対応で、恒久対応ではない。
```

3. ADR 0066-1 の状態は、設計レビューのあと SE が「採用」にする。PG は直さない。
4. main にマージしたあと、`install.ps1 -Yes` で入れる(PL)。
