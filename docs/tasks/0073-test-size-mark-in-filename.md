## ゴール

全体の CLAUDE.md(`claude/CLAUDE.md`)の、タグの無いテストフレームワークでテストの大きさの印をファイル名に入れる規則が、どのフレームワークでも、印を付けたテストが流れなくならない形になっている。

なぜ: 今の規則は、ファイル名に `.medium`・`.large` を入れる形。Python の unittest の discover は、点を含むファイル名をエラーを出さずに読み飛ばすので、印を付けた中と大のテストが一度も流れなくなる(PL が手元で確かめた)。テストの大きさごとに決まった時に流す、という目指す状態に反する。0072 の SE が見つけ、0072 ではリポジトリの側だけ `medium_test_` を頭に付ける形にした(ADR 0072-1)。

範囲外: 各リポジトリのテストのファイル名の付け替え。

## 要件

### R1 印を付けたテストが、どのテストフレームワークでも拾われる

- 要件: タグの無いテストフレームワークで中と大のテストに付けるファイル名の印は、ファイル名をテストフレームワークが読める名前のままにし、リポジトリ直下の CLAUDE.md の「小と中」「大」のコマンドで選んで拾える形。
- なぜ: `.medium`・`.large` を入れると、unittest がエラーを出さずに読み飛ばし、中と大のテストが一度も流れない。テストサイズごとに決まった時に流す(ADR 0009-3)ことができなくなる。
- 受け入れ条件 R1-1: 全体の CLAUDE.md の、タグの無いテストフレームワークの行は、中と大のテストのファイル名の頭に `medium_`・`large_` を付ける形になっている。

## レビュー

### 設計レビュー

- ADR 0073-1 の理由1と R1 の要件は、頭の `medium_`・`large_` が「テストとして拾う名前の決まりを崩さない」と言うが、unittest の既定の形 `test*.py` では `medium_test_x.py` は拾われない(同じ ADR の理由3のとおり)。拾われるのは、リポジトリ直下の CLAUDE.md の「小と中」「大」のコマンドで形を広げたときだけ。この依存を ADR の理由に書き、R1 の要件の文もそれに合わせる(要件の文は利用者と合意したものなので、利用者に確かめてから)。書かないと、unittest のリポジトリで「小と中」のコマンドを既定の discover にしたとき、中のテストがエラーを出さずに一度も流れず、ゴールで防ぎたい失敗が残る。
  - SE の直し: ADR 0073-1 の理由2に、既定の形が頭を決めるテストフレームワークでは「小と中」「大」のコマンドで形を広げたときだけ拾われることと、`.medium` との違いを書いた。R1 の要件の文も、コマンドで選んで拾える形に直した。R1 はゴールの文から SE が書いたもので、利用者と合意した文ではない(PL が聞かずに進めると添えたタスク)ので、利用者には聞かずに直した。
- Nit: ADR 0073-1 の捨てた案に、決まった頭の後ろに印を入れる形(`test_medium_x.py`)が無い。既定の形でも拾われるが、unittest では小だけを選んで流せない、という比べ方を残すと、頭に付ける理由がはっきりする。
  - SE の直し: ADR 0073-1 の捨てた案2に足した。
- Nit: 「置くファイルと名前・データ」の新しい行の字数は「50 字ほど」でなく、`rule_length` で 58 字(上限 60 字)。
  - SE の直し: 設計の節を 58 字に直した。
- Fable に替える条件(入れた決定を消す・同じ決まりを3回変える)には当たらない(ADR 0073-1 のコミットは 1740c75 の1つだけ)。
- 設計の指摘があるので、ADR 0073-1 は「提案」のまま SE に返す。
