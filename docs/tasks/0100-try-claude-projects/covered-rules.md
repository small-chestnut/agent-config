SE が1行ずつ読んで選んだ見積もり。タスク1つをスレッド1本で進め、SE・PG・QA のやりとりをサブエージェントに変える前提。

## task-team-lead

- 新しい話題は、壁打ちをせずに、タスクにしてチームを作る。(ADR 0056-2)
- タスクの中身の話は、そのタスクの SE の会話へのリンクを出して、SE の会話でしてもらう。(ADR 0056-1)
- 子セッションが待つ利用者の答えは、PL が取り次がず、「利用者待ち」の行のリンクの会話で受けてもらう。(ADR 0056-1)
- 進み具合を聞かれたら、リポジトリの全部のカードを書き直し、かんばんのリンクを出す。(ADR 0096-1)
- まだ始めていないチケットを作ったときと、タスクを始めた・終えたときは、そのタスクのカードだけを書き直す。(ADR 0096-1)
- 子セッションの知らせが来たときは、知らせた子セッションのチームのタスクのカードだけを書き直す。(ADR 0096-1)
- チケットの「利用者待ち」の行が埋まったら、その行を言い換えずに出す。
- 子セッションを開始する前に、`get_session` で PL 自身のモデルと effort を取得し、`claude-opus-5-5` の high でなければ、利用者に1行で伝える。(ADR 0059-1・0070-1)
- 子セッションのコンテキストは `get_usage` で見て、60% を超えたら利用者に知らせる。
- PL は、バックグラウンドのシェルで処理を実行しない。
- 子セッション3つは、利用者が書いたターンの中で全部開始する。開始できるのは、そのターンだけ。
- `title` は `<タスク名> SE`、`name` は `<タスクの番号>-se` の形。PG と QA も同じ。
- 開始には、`start_session` の user_asked・fresh を使う。
- 子セッションを開始する順は、SE を開始し、`get_session` で SE の worktree を取得してから、QA と PG。
- 最初の prompt は、3つとも、役割の skill を読んでターンを待つ指示だけ。(ADR 0067-1)
- SE は `use_worktree: true`、`branch_name` にタスク名。
- PG と QA は、SE の worktree を `cwd` にし、`use_worktree: false`。
- チケットだけのリポジトリでは、子セッション3つとも `use_worktree: false` で、PL のフォルダを `cwd` にする。
- ターンの受け渡しは、PL を通さず、子セッションどうしでする。
- 子セッション3つを開始したら、3つのセッションの id を、各子セッションに `SendMessage` で渡す。
- 子セッションを開始するときのモデルと effort は、SE が `claude-opus-5-5` の high、PG と QA が `claude-sonnet-5-5` の medium。(ADR 0059-1・0071-2)
- SE を high で開始できなければ、`set_session_effort` で high に替えてから依頼を送る。(ADR 0071-2)
- 進行中のタスクは、`list_sessions`(linked)の名前と、各チケットのステータスの行で分かり、会話を圧縮した直後は、まずこの2つから進行中のタスクを組み立て直す。
- 利用者が、ほかの PC で進めていたタスクを続けると言ったら、チームを作り直す。
- ほかの PC のタスクのチームを作り直す前に、`git fetch` し、そのタスクの作業ブランチの worktree を作る。
- ほかの PC のタスクのチームを作り直すときは、子セッション3つとも、そのタスクの作業ブランチの worktree を `cwd` にし、`use_worktree: false` で開始する。
- ほかの PC のタスクのチームを作り直したら、SE への依頼に、ほかの PC から続けるタスクだと添える。
- チケットの「PC: 」が自分の PC でなくなったタスクのチームは、push していないコミットが無いことを確かめてから、閉じる。
- マージ後、worktree は `git worktree remove`、作業ブランチは `git branch -d` で削除する。
- 報告の最後に、貼って送るだけの1行 `/compact 終わったタスク「<タスク名>」のやりとりは捨てて、進行中のタスクだけ残して` を、コードブロックで付ける。
- 子セッションの知らせへの返答は、終わったタスクの報告のほかは1行にする。
- かんばんの書き直しは、Agent ツールで開始したサブエージェント(`model: "sonnet"`)に頼む。
- かんばんの書き直しを頼む文は、作業するリポジトリのパスと、skill `team-kanban` に従ってかんばんを書き直すことと、書き直すカードの元のチケットの保存先だけ。(ADR 0058-1・0096-1)
- リポジトリの全部のカードを書き直すときは、頼む文にチケットの保存先を書かない。(ADR 0096-1)
- かんばんが無いと返ってきたら、利用者に伝え、agent-config の PL に作ってもらう。
- かんばんの書き直しは同時に1つだけ頼み、その書き直しが終わるまでに書き直すことになったカードは、終わった後に1回にまとめて頼む。

## team-kanban(team-kanban は全部)

- かんばんは、名前が「チームかんばん」の Artifact。
- かんばんが無ければ、書き直さずに、無いことを1行で返す。(ADR 0058-1)
- 利用者に出すリンクは、かんばんの URL に `#<リポジトリの名前>` を付けたもの。
- カードは、チケット1つに1枚。
- カードは、`git fetch` の後の、既定のブランチとリモートの作業ブランチのチケットから作る。
- チケットは、名前にチケットのタスク名の入った、既定のブランチにまだマージしていないリモートの作業ブランチから読み、その作業ブランチかチケットが無ければ、既定のブランチから読む。
- チケットの保存先を渡されたら、そのチケットのカードだけを書き直す。(ADR 0096-1)
- チケットの保存先を渡されなければ、頼まれたリポジトリのカードを全部書き直す。(ADR 0058-1)
- チケットが見つからないタスクは、かんばんのデータから、そのタスクの行を消す。
- イシュー管理システムで閉じられたチケットは、かんばんのデータから、そのタスクの行を消す。
- データは、かんばんの `datasets/cards` が指す JSON のファイルで、カード1枚が1行。
- 1行の項目は、`repo`・`machine`・`task`・`goal`・`status`・`done`・`total`・`waitingLine`。
- `repo` は、リモートのリポジトリの名前。リモートが無ければ、フォルダの名前。
- `task` はタスク名、`status` はステータスの行、`goal` はゴールの節の1行目。
- `machine` は「PC: 」の行。無ければ空。
- `done` と `total` は、進捗の節の、済みのサブタスクの数と全部の数。無ければ null。
- `waitingLine` は、利用者待ちの行から会話へのリンクを除いた文。「なし」なら空。
- 書き直すカードの行だけを入れ替え、新しいファイルをかんばんにアップロードする。(ADR 0058-1)
- `datasets/cards` の `source.url` を新しいファイルに替え、古いファイルを消す。
- `datasets/cards` を書くのと同じ書き込みで、`updated` の `at` を今の時刻にする。
- 今の時刻は、書き込む直前に、Bash ツールで `date -u +%Y-%m-%dT%H:%M:%SZ` を実行して取得する。
- `datasets/cards` を書くときは、読んだ `version` を `if_version` に付ける。
- 書き直したら、最後の返答は、利用者に出すかんばんのリンク1行だけにする。
- 書き直せなかったら、最後の返答は、書き直せなかった理由1行だけにする。

## task-team

- 利用者を待つときは、「利用者待ち」の行に、待つことと自分の会話へのリンクを書く。
- 自分の会話へのリンクは `[<セッションの名前>](#local_<自分の id>)`。
- 「利用者待ち」の行を書いたら、PL に知らせてから利用者を待つ。
- 待ちが済んだら、「利用者待ち」の行を「なし」に戻す。
- 利用者の許可を届ける文に、許可された操作と、利用者の言葉を言い換えずに引用したものを入れる。
- PL と SE から届いた許可は、引用した言葉が言う操作の範囲で、利用者の許可として扱う。
- 届いた許可でも Claude Code の組み込みの規則に止められたら、PL に知らせてターンを止める。
- PG と QA は、利用者の許可が要る操作を PL に知らせ、許可が届くまで待つ。
- 送り先の id は PL から届く。ターンを終えた後に届いたら、そのターンで送る。

## task-team-se

- PL がほかの PC から続けると添えたら、チケットを読み、「PC: 」を直して続ける。(ADR 0056-5)

## task-team-pg

- 利用者に操作を頼むとき、ステータスを「利用者の操作待ち(<操作の一言>)」にする。

## task-team-repo-ticket-format

- 書き方の文書の進捗の形で書くときは、利用者待ちの行を「PC: 」の次の行に置く。
