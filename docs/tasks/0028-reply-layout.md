# ゴール

全体の CLAUDE.md(`claude/CLAUDE.md`)の原則2 に、利用者に向けて書く返答の形の規則がある。形は、1行目に結論、横線の下に 400 字までの補足、もう1本の横線の下に質問。今の「本文が5行を超える説明は、冒頭に > で始まる tl;dr がある。」は、この形に替わっている。tl;dr を前提にした図の置き場の規則(`claude/CLAUDE.md` と skill `draw-figure`)は、結論の直後・補足の文より先に替わっている。利用者の「なぜ」が `.claude/rules/global-claude-md.md` に残っている。

範囲外: 利用者でない人に向けて書く文章(社内Wiki など。skill `explain-to-non-experts`)と、子セッションどうしの知らせの形。

# 設計

決まりの文書と「なぜ」のファイルだけの変更。`claude/CLAUDE.md` と `SKILL.md` は決まりの文書そのものが仕様なので、`docs/specs/` は作らない。ADR は書かない(書き換える行と見出しに付いた ADR は無い。足す行は ADR 0027-1 の肯定形に従う)。

利用者が決めたこと:

- 図は、結論の直後に置く(結論・横線・図・補足の文の順)。
- 補足を数ターンに分けたときは、質問の欄で、続きを出すかを聞く。

調べたこと(400 字の根拠。PG はコミットメッセージの本文に書く):

- スマートフォンで文章の長さを7段階に変えた実験で、伝わる情報の量が約 400 字で頭打ちになり、100 字の文章は 400 字以上より疲れにくかった(日本デザイン学会 2025、https://www.jstage.jst.go.jp/article/jssd/72/0/72_190/_article/-char/en)。
- ページを見る時間の 57% が、スクロール前の1画面に使われた(NN/g 2018、https://www.nngroup.com/articles/scrolling-and-attention/)。
- Markdown では、文のすぐ次の行の `---` は横線ではなく、その文を見出しに変える(setext 見出し、CommonMark の仕様 4.3 https://spec.commonmark.org/0.31.2/#setext-headings)。横線にするには、前に空の行が要る。

## 返答の形の節

```
### 目指す状態: 返答は、1行目で結論が分かり、1ターンの分をスクロールせずに読み切れる

- 返答の1行目には、結論を書いている。
- 補足は、結論の下に横線を引いて、400 字までで書いている。
- 400 字に収まらない補足は、数ターンに分けて出している。
- 分けたときは、質問の欄で、続きを出すかを聞いている。
- 質問は、補足の下にもう1本横線を引いて、その下に書いている。
- 補足の無い返答では、結論と質問の間の横線は1本にしている。
- 結論の1行だけの返答は、横線を引かずに、その1行で出している。
- 横線は、空の行の次の行に `---` を書いて引いている。
```

## 「なぜ」の節

```
# 原則6: 読まれ方

## 目的: 利用者が、返答を拾い読みせず、最後まで読んでいる

### 目指す状態: 1ターンの返答は、スクロールの要らない量に収まる規則になっている

### 目指す状態: 結論は、利用者が必ず読む冒頭の1行にある規則になっている

### 目指す状態: 返答の長さは、行の数ではなく、字の数で区切る規則になっている
```
