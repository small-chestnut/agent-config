# ゴール

`tests/` に、`claude/skills/*/SKILL.md` の箇条書きの行がすべて 60 字以内であることを確かめるテストを1つ足す。
字数の数え方は `claude/hooks/check_rule_length.py` と同じ(バッククォートで囲んだコードは1字)。
既にある関数を使い回し、数え方を2か所に持たない。

# 要件

## ゴール

`python -m unittest discover -s tests` を走らせると、`claude/skills/*/SKILL.md` に 60 字を超える箇条書きの行があれば、そのファイル・行番号・字数・本文が出て失敗する。

## 範囲外

- `claude/CLAUDE.md`・`codex/AGENTS.md` など、SKILL.md 以外の文書。
- 字数の数え方と上限(`check_rule_length.py`)を変えること。
- フック(保存したときに数える仕組み)の動き。

## 受け入れ条件

1. どの SKILL.md の箇条書きの行も 60 字以内。
2. 確かめる SKILL.md が1つ以上見つかる(パスを誤って0件で通るのを防ぐ)。
3. 60 字を超える行があるとき、失敗の表示にファイルの場所が出る。

いまの SKILL.md には 60 字を超える行が9行あり、このタスクで短くする(利用者の決定)。

# 設計

## 置くファイルと名前

- テスト: `tests/test_skill_md_bullet_length.py`(新規)。
- クラス名: `SKILL_mdの箇条書きの字数`。
- テスト名:
  - `test_どのSKILL_mdの箇条書きの行も60字以内`(受け入れ条件1・3)
  - `test_確かめるSKILL_mdが1つ以上見つかる`(受け入れ条件2)
- 名前は README とこのリポジトリのテストに既にある、ありふれた言葉(SKILL.md・箇条書き・字数)だけで付ける。用語集は作らない(利用者の決定: 汎用的な語に見直す)。

## 中身

- フックの読み込みは `tests/test_check_rule_length.py` と同じ形(`importlib.util.spec_from_file_location` で `claude/hooks/check_rule_length.py` を読む)。
- 対象は `Path(__file__).resolve().parents[1] / "claude" / "skills"` の `glob("*/SKILL.md")` を `sorted` したもの。
- 各ファイルを `read_text(encoding="utf-8")` で読み、`self.subTest(file=<リポジトリの根からのパス>)` の中で `self.assertEqual(crl.too_long(text, None), [])`。
  - `too_long` の第2引数 `None` は「全部の行」。上限は既定値 `crl.LIMIT`(60)。テストに 60 を書かない。
  - 箇条書きの見つけ方(コードブロックの中を除く)とコードを1字と数えるのは `too_long` の中にあり、テストは数え方を持たない。
- 受け入れ条件2は、上の一覧が空でないことを `assertTrue` で確かめる。

# レビュー(設計)

見た点と結果:

- 受け入れ条件とテスト名: 1・2 はテスト名で言える。3 はテスト名に出ないが、subTest の file と too_long の (行番号, 字数, 本文) で失敗の表示に出る。
- 9行の字数: `too_long(text, None)` を今の HEAD の11個の SKILL.md に掛け、設計の9行(ファイル・行番号・字数)と一致した。置き換え後の15行も `rule_length` で数え、設計の字数と一致した(すべて 60 字以内)。
- 数え方を2か所に持たないか: テストは `too_long` と `LIMIT` だけを使い、正規表現も 60 も持たない。合っている。
- 名前と用語集: `docs/用語集.md` は無く、作らないのは利用者の決定。クラス名・テスト名は README とフックの説明にある語だけ。
- 置き場所(module-layout): `tests/` に平らに置く既にある形に合わせている。
- 原則1(安全): 削除・force push・設定の変更は無い。
- 改行コード: SKILL.md は index が LF、作業ツリーが CRLF(core.autocrlf=true)。`splitlines` で数えるので、テストの結果は変わらない。

指摘:

- 直したい / `claude/skills/restructure-modules/SKILL.md`: 24行を分けた2行目「その仕組みは、DI の自動登録・…など。」は例だけの行で、「〜している」の形でもない(prompt-structure の「例は置かない」「規則は〜でいる形」)。1行のまま「型やファイルを名前空間・パッケージ名で探して登録する仕組み(DI・プラグイン・ORM)を検索して、直している。」(55字)にする案がある。
- 任せる / `tests/test_skill_md_bullet_length.py`: 受け入れ条件3はテスト名に出ないので、コミットの分け方の手順1で9行が落ちたときの表示を「実装」の節に貼り、3の確かめにする。
- 任せる / `claude/hooks/check_rule_length.py`: 同じ行をフックは「決まりの1行」、新しいテストは「箇条書きの行」と呼ぶ。フックの説明が「決まりの1行は、その箇条書き」と定めているので食い違いは無いが、揃えるなら別の変更。
- 任せる / `install.ps1`: 直した SKILL.md が `~/.claude/skills` に入るのは、main にマージして `install.ps1 -Yes` を走らせた後。設計の手順に無いので、PL の締めに入れる。
