# 設計

文書だけの変更。`claude/CLAUDE.md` は決まりの文書そのものが仕様。書き換える見出し(`claude/CLAUDE.md:127`・`.claude/rules/global-claude-md.md:31`)にも行にも ADR の番号は無いので、読む ADR は無い。前の用語集の決まり(0030 などの変更)も ADR を書いていないので、ADR は書かない(決まりの文書の文を直す変更で、「なぜ」は ADR 0020-1 のとおり `.claude/rules/` に置く)。規則の行は ADR 0027-1 のとおり、文の終わりの述語を肯定にしている。

タスクの文が挙げた3行(129〜131)のほか、132 行目「…用語集に書いている」も直す。依頼文の語と違う名前を用語集に書くと、「正しい語は X、Y は使わない」の行になるため。

確かめられる基準は「そのリポジトリを読まなければ意味が分からない語」。広く使われている意味(辞書・IT の用語の定義)のまま使い、そのリポジトリでは置き場や形だけを決めた語は、当たらない。

## コミットの本文

- 利用者の「なぜ」: ユビキタス言語を作るのは、AI がその場で付けた例え(「スキーマ」に「箱」など)が文書に漏れ、例えが語の意味になるのを避けるため。一般の語の説明は、モデルの中にもっと完全な形で既にあり、あるシステムの用語集に載せても意味が無い。用語集に残すのは、そのシステムで固有の意味を持つ語だけ。
- 前の理由 → 新しい理由: 「IT の用語は、リポジトリで形か意味を決めたものだけを載せる」→「一般の語の意味は、モデルが既に持つもっと完全な説明に任せる」。形を決めただけの一般の語も載り、LogiFee の用語集が CLAUDE.md の約 10 倍(83,814 字)に膨らんだのが発端。
