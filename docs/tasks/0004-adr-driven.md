ステータス: 利用者の判断待ち(ADR 0004-1)

# ゴール

task-team で、設計の決定のうち後から変えにくいものを、SE が ADR に「提案」として書き、利用者が「採用」にしてから PG が実装する(ADR駆動)。そのために、タスクの番号・ADR の番号と置き場と中身と状態・提案から採用までの流れ・設計の最初に ADR を引くこと・ADR を書く対象を、task-team の skill・グローバルの CLAUDE.md・README に入れ、既にある3件の記録をタスクの番号付きの名前にする。

あわせて、agent-config の規則(グローバルの CLAUDE.md・skill・AGENTS.md)が、作業するリポジトリの決まりとぶつかったら、必ずリポジトリの方に従う。ADR の番号・置き場・形も、リポジトリに決まりか既にある ADR があれば、そちらに従う。理由: agent-config は利用者が AI 駆動開発のために使う私的な規則で、これによって複数の人間が触るリポジトリの規則を逸脱するわけにはいかないから。

リポジトリの決まりは、リポジトリにコミットされた文書(CLAUDE.md・AGENTS.md・README・CONTRIBUTING.md・`docs/` など)に書かれた決まりと、既にあるファイルの並び(ADR の番号・置き場・形など)。

範囲外: ほかのリポジトリに既にある決定を ADR に書き起こすことと、ADR の形をフックやテストで検査すること。

# 受け入れ条件

1. 既にある3件の記録が、追加した順に `docs/tasks/0001-skill-rule-length-test.md`・`docs/tasks/0002-task-team-ops.md`・`docs/tasks/0003-user-as-worker-briefing.md` になり、0003 の図のフォルダと、記録の中の図へのリンクも `0003-user-as-worker-briefing/` になっている。
2. `task-team-lead` に、PL がタスクの番号(4桁の連番)を振り、記録・子セッション・ブランチの名前の頭に付ける行がある。
3. `task-team-lead` に、ステータスが「利用者の判断待ち(ADR <ADR の番号>)」になったら、ADR のパスと「決めたこと」の1行を出して採用するかを利用者に聞き、返事を言葉を変えずに SE に送る行がある。
4. `task-team-se` に、設計の最初に、直すモジュールの名前か「全体」で ADR の「対象」の行を検索し、状態が「採用」の ADR を読み、ぶつかるなら決定を変えるかを利用者に1回だけ聞く行がある。
5. `task-team-se` に、Nygard の5つ(構造・非機能の特性・依存・インターフェース・作り方の技法)に効く決定を「提案」の ADR に書いたらすぐ、ステータスを「利用者の判断待ち(ADR <ADR の番号>)」にしてターンを終え、利用者の返事で状態を「採用」か「却下」にして設計を続ける行がある。
6. `task-team-se` に、ADR の番号・置き場・中身・状態と、決定を変えるときの書き方の行があり、「複数モジュールに及ぶ決定は ADR に」の行は無い。
7. `task-team-se` と `task-team-qa` の「大きな変更」が、ADR を提案した変更と本番環境に触る変更になっている。
8. グローバルの CLAUDE.md(`claude/CLAUDE.md`)原則3 の ADR の行が、書く対象を Nygard の5つ、中身を状態・日付・対象・決めたこと・捨てた案・理由にしていて、task-team を通さない会話では ADR を書かずにタスクにして PL に回す行がある。
9. このリポジトリの CLAUDE.md に、ADR の「対象」には skill の名前か hooks のファイル名を書き、いくつもに及ぶなら「全体」と書く行がある。
10. README の「セッションの役割分割」の節に、ADR駆動の意図と、利用者の理由(タスクから ADR をすぐ引けるようにするため・人が一覧で見渡せ AI にとっての差は小さいため)がある。
11. `docs/adr/0004-1-adr-driven.md` の状態が「採用」である。
12. `docs/用語集.md` に、タスクの番号・ADR・ADR の番号・ADR の状態・ADR の対象・利用者の判断待ちがある。
13. どの SKILL.md の箇条書きの行も 60 字以内(`python -m unittest discover -s tests` が通る)。
14. グローバルの CLAUDE.md の冒頭と `codex/AGENTS.md` に、この文書と skill の規則が作業するリポジトリの決まり(コミットされた文書に書かれた決まりと、既にあるファイルの並び)とぶつかったら、リポジトリの方に従い、ぶつかった規則と従ったリポジトリの決まり(ファイルと文)を利用者に1行で伝える行がある。
15. `task-team-se` に、リポジトリに ADR の決まりか既にある ADR があれば、ADR の番号・置き場・形をそちらに合わせる行がある。
16. README に、リポジトリの決まりを優先する意図と、利用者の理由(agent-config は AI 駆動開発のための私的な規則で、複数の人間が触るリポジトリの規則を逸脱するわけにはいかないため)がある。
