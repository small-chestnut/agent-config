# ゴール

Stop フック `claude/hooks/require_verify_before_stop.py` の中身の印が、ファイルを前に書いたのと同じ秒の中に同じ大きさで書き換えても変わり、テスト `test_確かめを通すまでStopフックが止め通したら止めない` がときどき落ちなくなる。

発端: main で `python -m unittest discover -s tests` を23回流して2回、174 行目の `self.assertEqual(r.returncode, 2)` が `AssertionError: 0 != 2` で落ちた。

原因: 中身の印を作るとき、本物の index を一時ファイルに中身だけ写すので、一時ファイルの更新時刻が写した時刻になる。git は、ファイルの大きさと更新時刻(秒まで)が index の記録と同じなら中身を読まず、ただし更新時刻が index の更新時刻より前でないときだけは読み直す(https://git-scm.com/docs/racy-git)。テストは、`a.txt` を `1` で書いてコミットし、同じ秒の中に `2` へ書き換える。次の秒に `stop` が index を写すと、一時ファイルの更新時刻が `a.txt` より後になり、git は読み直さず、中身の印がターンの始めと同じになって止めない。手元で、書き換えを1つの秒の中に寄せ、次の秒に印を作ると5回中5回、印が変わらなかった。

範囲外: テストに大きさの印(`medium`)を付けること・テストのファイルを大きさで分けること。

# 受け入れ条件

1. Stop フックは、ターンの始めから中身が変わり、今の中身で通っていない確かめのコマンドがあれば、その頭を並べてターンを止める。
2. Stop フックは、今の中身で一覧の確かめが全部通っていれば止めない。
3. Stop フックは、ターンの始めの印が無いか、ターンの始めから中身が変わっていなければ止めない。
4. 確かめのコマンドの一覧は、空の行と `#` で始まる行を読まない。
5. 確かめのコマンドの頭と同じか、頭と空白で始まるコマンドが Bash か PowerShell で通ると、今の中身でその確かめが通ったと記録される。
6. パイプ・`;`・`&`・改行を含むコマンドと、バックグラウンドで走らせたコマンドは、確かめとして数えない(`2>&1` は数える)。
7. 中身の印は、コミットしても、`docs/` の下だけを変えても変わらない。
8. 中身の印は、まだ追っていないファイルを足すと変わる。
9. 中身の印は、ファイルを前に書いたのと同じ秒の中に、同じ大きさで書き換えても変わる。
10. 確かめの記録を、いくつものフックが同時に書いても、ターンの始めの印と通った確かめは消えない。
11. 確かめの記録が読めないか壊れていれば、フックは落ちずに空として扱う。
12. 確かめのコマンドの一覧が無いリポジトリと、git の外では、フックは何もしない。

1〜8・10〜12 は今の動きで、9 がこのタスクで直す動き。

- 新しいテストは、このバグを再現するテスト。sleep を使わず、更新時刻を `os.utime` で決めて、毎回同じ形にする。流れ:
  1. `T` を、今より 100 秒前の整数の秒にする。
  2. setUp のリポジトリで、`a.txt` に `1` を書き直し、更新時刻を `T` にして、`git add -A` をする(中身は同じなのでコミットはしない。index の `a.txt` の更新時刻が `T` になる)。
  3. index(`<repo>/.git/index`)の更新時刻を `T` にする(index を、`a.txt` と同じ秒に書いた形にする)。
  4. 中身の印を取る。
  5. `a.txt` に `2` を書き、更新時刻を `T` に戻す。
  6. 中身の印が、4 と違う。
- 手元で確かめた: 今のコードでは、この流れで10回中10回、印が変わらない。更新時刻も写すと、10回中0回。
- 既にあるテストは変えない。

lint のコマンドはこのリポジトリに無い。
