# ゴール

用語集に載せる IT の用語と載せない IT の用語の境目が、`claude/CLAUDE.md` の用語集の規則にあり、その境目の理由として利用者が言ったことが README に残っている。

利用者の言葉:「用語集というのは、それを防ぐためのものだよね(リポジトリに例えや比喩が混入するのを防ぐため)。けど、一点気になっているのが、だからといって、用語集に、ITドメインのテクニカルターム、これらをすべて載せるわけにはいかない。当然そうだよね？」。利用者が挙げた例は DB のスキーマで、会話で「箱」と例えても、スキーマにはスキーマという、はっきり定義された用語がある。

利用者が足した理由:「用語集が、ITのテクニカルタームの辞書になってしまっては困る。そんなものを読み切れるわけはないし、そもそも、テクニカルタームの最も正確な定義は、あらためて用語集に書くまでもなく把握している」。

利用者がもう1つ足した言葉:「しかしながら、「用語集」というもの、それを消してしまうことは、いい考えではないと思っている。なら、用語集には、何を残せばいいのだ？」。答えは、用語集を残し、業務の言葉(今の規則の1行目)と、リポジトリで形か意味を決めた IT の用語(足す行)を載せること。

範囲外: 各リポジトリの用語集の行を、この境目に合わせて直すこと(このリポジトリの `docs/用語集.md` の IT の用語の行は、みなリポジトリで形か意味を決めたもので、境目に合っている)。

# 受け入れ条件

1. `claude/CLAUDE.md` の「### 目指す状態: 業務の言葉1つに、コードの名前が1つ対応している」の節の1行目の次に、「- IT の用語は、リポジトリで形(置き場・名前の付け方)か意味を決めたものだけを載せている。」の行がある。
2. README の「プロンプト層(CLAUDE.md)の意図」の節の用語集の項目に、載せる IT の用語の境目と、利用者の言葉と、利用者が挙げた例と、利用者が足した理由が言葉のままある。
3. README のその項目には、利用者の言葉・例・足した理由のほかに理由を書いていない。
4. `claude/CLAUDE.md` と README のほかの行と、`docs/用語集.md` は変わっていない。

# 設計

書き換える行(`claude/CLAUDE.md` の用語集の節と、README の用語集の項目)と、その見出しに ADR の番号は付いていない。境目は、用語集の行を足すか足さないかの判断で、後から1行の書き換えで変えられるので ADR は書かない。

境目は、ユビキタス言語の定石に沿う。ユビキタス言語は、開発者と業務の人が共有する、業務のモデルに基づく言葉で(https://martinfowler.com/bliki/UbiquitousLanguage.html)、広く使われている意味のまま使う IT の用語は、そのリポジトリで決める言葉ではない。リポジトリで置き場・名前の付け方・意味を決めた IT の用語(このリポジトリの「ADR」「モジュール」など)は、そのリポジトリの言葉なので載せる。

`claude/CLAUDE.md` は決まりの文書なので、それ自体が仕様で、別の仕様は直さない。新しい名前は無く、用語集は変えない。

## 手順1: CLAUDE.md に境目の行を足す(する人: PG)

`claude/CLAUDE.md` の「### 目指す状態: 業務の言葉1つに、コードの名前が1つ対応している」の節で、「- 用語集(`docs/用語集.md`)に、業務の言葉・コードの名前(クラス・テーブル・列)・画面に出す字・一言の意味が並んでいる(ユビキタス言語)。」の行の次に、次の行をそのとおりの文で足す。

```
- IT の用語は、リポジトリで形(置き場・名前の付け方)か意味を決めたものだけを載せている。
```

失敗する条件: main に入った他のタスクの変更で、その節の1行目が変わっていたら、main を取り込み、変わった1行目の次に入れる。

## 手順2: README の用語集の項目に、境目と利用者の言葉を足す(する人: PG)

`README.md` の「## プロンプト層(CLAUDE.md)の意図」の節で、「- **用語集(`docs/用語集.md`)に、業務の言葉とコードの名前を1対1で並べる(ユビキタス言語)**。」の項目の、「利用者の理由は「用語集を作っている理由が、…防ぐため」」の行の次に、次の3行をそのとおりの文で足す。

```
  載せる IT の用語は、リポジトリで形(置き場・名前の付け方)か意味を決めたものだけ。利用者の言葉は「だからといって、用語集に、ITドメインのテクニカルターム、これらをすべて載せるわけにはいかない」。
  利用者が挙げた例は DB のスキーマで、会話で「箱」と例えても、スキーマにはスキーマという、はっきり定義された用語がある。
  利用者の理由は「用語集が、ITのテクニカルタームの辞書になってしまっては困る。そんなものを読み切れるわけはないし、そもそも、テクニカルタームの最も正確な定義は、あらためて用語集に書くまでもなく把握している」
```

失敗する条件: main に入った他のタスクの変更で、その項目が動いたか消えていたら、main を取り込み、用語集の項目を探して、その最後の行の次に入れる。項目が無ければ PL に知らせて止める。

## コミット

PG は手順1と手順2を1つのコミットにする。本文に利用者の言葉を書く必要は無い(README に残る)。
