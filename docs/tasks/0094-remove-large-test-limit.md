### R1 large のテストの数に、上限の行を置かない

- 要件: 全体の CLAUDE.md の「large のテストは、利用者の主な使い方1本につき1つまで。(ADR 0005-1)」の行を消す。large のテストの数は、目指す状態「テストは、適正な量になっている」の、ISTQB CTFL シラバスのリスクベースドテストで決まる。

### 調べて分かったこと(2026-11-24)

- この上限を決めたのは ADR 0005-1 の決めたことの2(大は利用者の主な使い方1本につき1つまで)。0005-1 の理由が出典に挙げる本『Software Engineering at Google』11章は、大きさの定義の出典で、この上限の出典は書かれていない。ADR 0009-3 の理由3(CI が無いときに実行する large を変えた使い方の分に絞る理由)と、ADR 0093-1 の理由7が、この上限を引いている。0009-3 の決めたこと(変えた使い方を確かめる large を実行する)は、上限が無くても成り立つ。
- ADR 0092-1 で、画面を操作するテストと速さを測るテストが large になった。速さを測るテストは「使い方」に当たらないので、上限の行では数が決まらない。LogiFee には、画面(WinForms)を操作するテストが、本船管理だけで5つある(`LogiFee.Tests/Modules/Vessels/` の `SailingTabSpeed`・`SailingDetailSpeed`・`VesselChoiceScreen`・`VesselMasterScreen`・`NaccsBrandScreen`)。
- 0093 の試し(ADR 0093-1 の理由5)は、どれもこの行を入れた文で、行が無いときの件数は測っていない。
- 試し(2026-11-24。0093 と同じ道具で、決まりの文書を読まない新しいセッション(`claude-opus-5-5`)に、今の全体の CLAUDE.md の全文か、そこからこの行だけを消した文と、要件を渡し、残すテストの一覧を3回ずつ書かせた。速さの要件は、LogiFee の `LogiFee.Tests/Modules/Accounting/AccountingPerf.cs` の冒頭の説明。道具と結果は `C:/Users/Reo/AppData/Roaming/Claude/side-session-notes/local_cb317e6d-6273-4225-a480-24083a921c9a/0094-trial/`(この PC だけにある))。件数(うち large):

  | 要件 | 行あり | 行なし |

  | gemini 0094 | 32(0)・26(0)・24(0) | 33(0)・34(0)・31(0) |
  | LogiFee の源泉 | 15(1)・9(0)・12(1) | 12(1)・11(1)・10(0) |
  | LogiFee の会計管理の画面の速さ | 5(1)・5(1)・9(2) | 9(3)・7(2)・6(4) |

  - 速さの要件では、行ありの large は、3つの速さ(仕訳500枚の読み込み・経費100件の読み込み・行を替えたときの右の欄)を1つのテストにまとめた(3回目は、2つと1つに)。行なしは、速さごとに1つの large に分けた。行なしの3回目は、描画の回数を数えるテストも large にした。
