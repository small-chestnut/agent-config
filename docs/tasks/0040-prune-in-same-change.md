# ゴール

install スクリプトで各 Claude 設定ディレクトリに入る全体の指示(`claude/CLAUDE.md`)で、AI が、動きを変えるか消す変更の中で、その動きを前提にしたテスト・仕様・コードを直すか消すようになる。消す前に利用者へ対象と理由を伝えるのは、git から戻せないもの(まだコミットしていないもの・リポジトリの外のもの)を消すときだけになる。

なぜ: AI で開発すると、リポジトリの中身は増える一方になり、決まりが無いと AI は自分からは消さない。利用者が判断できるのは見えている仕様(どの機能を残す・変える・消すか)までで、AI しか見ていないテストやコードの消し方は、聞かれても判断材料が無い。そこが正しいかは、別のセッションのレビューとテストで確かめる。

範囲外: 既にある約40件の古いテスト(テストの基準 ADR 0005-1 ができた 2026-10-31 より前に作ったもの)の見直し(別のタスク)。skill `task-team-se`・`task-team-qa` の「仕様を直す」行の書き換え。main へのマージ・push・`install.ps1 -Yes`(PL がする)。

## 書き換える所と ADR

- `claude/CLAUDE.md` の2行。削除の行には ADR の番号が無い。仕様の行には ADR 0010-1 が付いている。見出しにはどちらも番号が無い。読んだ ADR は 0010-1 だけ(「置き換える: 」は無い)。
- 仕様の行の決定は、ADR 0010-1 を置き換えず、広げる。0010-1 の決定(モジュールごとに仕様を1つ置き、動きを変える変更の中で直す)は、そのまま残る。広げた分は ADR 0040-1(状態: 提案)に書き、行の末尾を「(ADR 0010-1・0040-1)」にする。
- 削除の行の決定は、ADR 0040-2(状態: 提案)に書き、行の末尾に「(ADR 0040-2)」を付ける。
- 削除の行は、2行に分ける。1行に収めると 60 字の上限(`check_rule_length.py`)を超えるため。2行目「git にコミット済みのものは、完全に消している。」は今の字のまま。
- 仕様の行の新しい字は 59 字で、上限に近い。「同じ変更で」は、「〜変更では、…も直すか消している」で言えているので、字に入れない。
- 「なぜ」は ADR 0020-1 に従い、`.claude/rules/global-claude-md.md` に置く。今ある原則1〜6 のどの目的にも当たらないので、原則7「整理」を末尾に足す。末尾なので、今ある原則どうしの順は変わらない。
- `claude/CLAUDE.md` は 152 行から 153 行になり、200 行以内(`.claude/rules/global-claude-md.md` の原則2)に収まる。安全の規律は 11 行から 12 行になる。
