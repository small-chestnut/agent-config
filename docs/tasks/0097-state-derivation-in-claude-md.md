## 要件

### R1 段が上から導かれることを、常時読まれる所に明示する

- 要件: 命題が原則を、原則が目的を、目的が規則を導くことを、常時読まれる所に書く。
- なぜ: 今の常時読まれる文からは、上の段が下の段を導くことが分からない。
- 受け入れ条件 R1-1: 全体の CLAUDE.md だけを読んだ新しいセッション3つが、命題から原則、原則から目的、目的から規則が導かれると、文を根拠に答える。

### R2 リポジトリの命題を、常時読まれる所に「命題」と明示する

- 要件: リポジトリの命題は、リポジトリ直下の CLAUDE.md の1行目に「命題」と明示して書く。`docs/概要.md` には使う人と機能の一覧を残す。agent-config の2つ目の命題(拡張パーツ)は、README から agent-config の CLAUDE.md へ移す。
- なぜ: コンテキストに常時入る所に無いと、命題として読まれない。
- 受け入れ条件 R2-1: リポジトリの命題を置く場所が、決まりの文書で、リポジトリ直下の CLAUDE.md の1行目の1か所に決まっている。
- 受け入れ条件 R2-2: agent-config の命題(拡張パーツ)が、agent-config の CLAUDE.md にあり、README に無い。

### R3 原則ごとに、どちらの命題から導くかを決める

- 要件: 安全・人間側の最適化・AI 側の最適化の原則は、どのリポジトリでも全体の命題から導く。リポジトリだけの原則は、そのリポジトリの命題から導く。全体の命題と、どの原則をどちらの命題から導くかも、各リポジトリの CLAUDE.md に、リポジトリの命題の下に書く。
- なぜ: 全体の命題とリポジトリの命題の2つがあり、導くことだけを書くと、どちらから導くかが決まらない。agent-config を使っていない人の Claude には、全体の CLAUDE.md が見えない。
- 受け入れ条件 R3-2: 決まりのとおりに冒頭を書いたリポジトリの CLAUDE.md だけを読んだ新しいセッション3つが、安全の原則は全体の命題から導かれると、文を根拠に答える。
- 受け入れ条件 R3-1: 全体の CLAUDE.md と、命題と安全の原則があるリポジトリの CLAUDE.md を読んだ新しいセッション3つが、安全の原則は全体の命題から導かれ、リポジトリだけの原則はリポジトリの命題から導くと、文を根拠に答える。
