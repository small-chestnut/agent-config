# ゴール

PL が SE に、利用者のタスクの文に加えて、そのタスクの文が受けている PL の返答(PL の答え)を、言葉のまま、決定ではなく材料だと添えて渡す規則が skill `task-team-lead` にあり、その理由として利用者が言ったことが README に残っている。

利用者の言葉:「今更だけど、どうして私の言葉しか送らないの？ 私は、私自身、曖昧な状態のままタスクにしているし、あなたの返答を聞くことによって、タスクの要否を判断することがあるのだけど。例えば、今、用語集について聞いたとき、「AI駆動開発に、ユビキタス言語の策定は有効ではありません」とあなたが返していたなら、用語集自体を廃止するようなタスクを作っていたと思うんだけど」

範囲外: `claude/CLAUDE.md` の「利用者が依頼の中で言った「なぜ」は、言った内容だけを…残している」の行と、PL の答えを記録や README に残すかどうか(PL の答えは SE が設計の材料に使うだけで、残すのは今までどおり利用者の言葉)。

# 受け入れ条件

1. skill `task-team-lead` の「### 目指す状態: 受け渡しの記録が、タスクごとに1つのファイルにある」の節で、PL が子セッションに渡す文が「記録のパスと読む節と、タスクの文と、PL の答えだけ」になっている。
2. 同じ節に、PL の答えは、タスクの文が受けている PL の返答で、無ければ渡さないという行がある。
3. 同じ節に、PL の答えは、言葉のまま、決定ではなく材料だと添えて SE にだけ渡すという行がある。
4. 同じ節で、渡さないものが「PL の答えのほかの見立てと、ほかの子セッションの会話」になっている。
5. 「### 目指す状態: チームは、タスクごとに SE・PG・QA の3セッション」の節で、SE への prompt に PL の答えが入っている。
6. README の「## セッションの役割分割(PL / SE / PG / QA)の意図」の節に、PL の答えも SE に渡す項目があり、利用者の理由と利用者が挙げた例が言葉のままあり、そのほかの理由は無い。
7. 用語集に「PL の答え」の行がある。
8. skill `task-team-lead` の箇条書きの行は、どれも60字以内(既にあるテスト `test_どのSKILL_mdの箇条書きの行も60字以内` が通る)。
9. 上に挙げた行のほかの行は、skill `task-team-lead`・README・用語集で変わっていない。

# 設計

書き換える行(skill `task-team-lead` の2つの節と、README の役割分割の意図の節)と、その見出しに ADR の番号は付いていない。渡す文の中身は skill の数行で決まり、後から書き換えで変えられるので ADR は書かない。設計レビューは無く、PG に回す。

いまの「PL の見立ては渡さない」の行は、コミット 89bedf7 の本文にある利用者の理由「QA は客観的なレビュワーであるべきで、SE の設計段階の思考を QA の文脈に入れてはまずい」から来ている。PL の答えは SE にだけ渡し、QA と PG に渡す文は変えないので、その理由とは逆向きにならない。

skill `task-team-lead` は決まりの文書なので、それ自体が仕様で、別の仕様は直さない。新しい名前「PL の答え」を用語集に足す。

## 手順1: skill `task-team-lead` の渡す文の規則を直す(する人: PG)

`claude/skills/task-team-lead/SKILL.md` の「### 目指す状態: 受け渡しの記録が、タスクごとに1つのファイルにある」の節の、次の2行を、

```
- PL が子セッションに渡す文は、記録のパスと読む節と、利用者のタスクの文だけ。
- PL の見立てと、ほかの子セッションの会話は、子セッションに渡さない。
```

次の4行に、そのとおりの文で置き換える。

```
- PL が子セッションに渡す文は、記録のパスと読む節と、タスクの文と、PL の答えだけ。
- PL の答えは、タスクの文が受けている PL の返答。無ければ渡さない。
- PL の答えは、言葉のまま、決定ではなく材料だと添えて SE にだけ渡す。
- PL の答えのほかの見立てと、ほかの子セッションの会話は、子セッションに渡さない。
```

同じファイルの「### 目指す状態: チームは、タスクごとに SE・PG・QA の3セッション」の節の、

```
- SE への prompt は、skill `task-team-se` に従う指示と、タスクの文と、記録のパス。
```

を、次の行に置き換える。

```
- SE への prompt は、skill `task-team-se` に従う指示と、タスクの文と、PL の答えと、記録のパス。
```

失敗する条件: main に入った他のタスクの変更で、置き換える行が変わっていたら、main を取り込み、変わった行に同じ中身(PL の答えを足す・渡さない見立てを PL の答えのほかに絞る)を入れる。行が見つからなければ PL に知らせて止める。

## 手順2: README に理由を足す(する人: PG)

`README.md` の「## セッションの役割分割(PL / SE / PG / QA)の意図」の節で、「- **ターンの受け渡しは、PL を通さず子セッションどうしが SendMessage でする**。」の項目(最後の行は「QA に SE や PG の思考が入らないようにするため」)の次に、次の項目をそのとおりの文で足す。

```
- **PL は、利用者のタスクの文に加えて、タスクの文が受けている PL の答えを、言葉のまま SE に渡す**。
  決定ではなく材料だと添え、QA と PG には渡さない。PL の答えのほかの見立ては、今までどおり渡さない。
  利用者の理由は「私は、私自身、曖昧な状態のままタスクにしているし、あなたの返答を聞くことによって、タスクの要否を判断することがあるのだけど」。
  利用者が挙げた例は用語集で、「用語集について聞いたとき、「AI駆動開発に、ユビキタス言語の策定は有効ではありません」とあなたが返していたなら、用語集自体を廃止するようなタスクを作っていたと思うんだけど」
```

失敗する条件: その項目が動いたか消えていたら、main を取り込み、同じ節の最後の項目の次に入れる。節が無ければ PL に知らせて止める。

## 手順3: 用語集に「PL の答え」を足す(する人: PG)
