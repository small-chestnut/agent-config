## 要件

### R1 安全の節の、消しても動きが変わらない行を消す

- 要件: 全体の CLAUDE.md(`claude/CLAUDE.md`)の「原則1: 安全」の節の行を1行ずつ確かめ、消しても Claude の動きが変わらない行を消す。
- なぜ: 利用者は、安全の文が今でも要るかを疑い、要らない行なら消したい(2026-11-28、PL の会話で「タスクにする」と答えた)。このリポジトリの命題(ほかのリポジトリで読まれる文章を少なく保つ)に沿う。
- なぜ(見直す節を分けない): 利用者は、どの節も見直しから外さない。節の重要度と、見直せるかどうかは関わらない(2026-11-28)。ADR 0088-1(捨てた案6)と ADR 0090-1(捨てた案3)が、安全の節を見直さない理由とした「行が無くて起きる損失は取り返しがつかない」は撤回した。利用者の理由は、ルールの硬直化はよくないこと。
- 要件(本番の DB の行): 安全の節の「破壊的な DB 操作は、ローカル・開発用の DB にだけする」行は、消すと動きが変わるが消す。
- なぜ(本番の DB の行): この行に残る働きは、利用者が頼んだ本番の DB の操作を断らせることだけで、リポジトリの CLAUDE.md の「利用者が頼んだ本番の作業を断らせる文を置かない」とぶつかる。利用者は、消すと答えた(2026-11-28)。自分の判断でする破壊的な操作は、道具の指示で今どおり確かめる。
- 受け入れ条件 R1-1: 消した行のどれにも、その行が無くても同じ動きになる根拠が、設計に書いてある。
- 受け入れ条件 R1-2: 残した行のどれにも、消すと動きが変わる理由が、設計に書いてある。
- 受け入れ条件 R1-4: 安全の節に、破壊的な DB 操作をローカル・開発用の DB にだけする行が無い。
- 受け入れ条件 R1-3: 全体の CLAUDE.md が字数の上限を超えたときの減らし方の文が、安全の節の行を、消す候補から外していない。

### R2 main にマージ済みの作業ブランチは、リモートからも消す

- 要件: main にマージ済みの作業ブランチは、リモートからも消せるようにし、今リモートに残っているマージ済みの作業ブランチも消す。
- なぜ: 利用者は、完了した作業のリモートのブランチが気になっていて、どこまでのブランチを残すかを、前の現場の慣習でなく広く使われるやり方に沿わせたい。そのやり方が安全の規則に当たるなら、規則の側を見直してよいとした(2026-11-28)。GitHub flow は、マージしたらブランチを消す(https://docs.github.com/en/get-started/using-github/github-flow 。2026-11-28 に調べた)。このリポジトリは作業ブランチをマージコミットで main に入れるので、ブランチを消してもコミットは main の履歴に残る。
- 受け入れ条件 R2-1: main にマージ済みのブランチをリモートから消す push は、フックに止められない。
- 受け入れ条件 R2-2: main にマージされていないブランチをリモートから消す push は、今どおりフックに止められる。
- 受け入れ条件 R2-3: リモートに、main にマージ済みの作業ブランチが残っていない。

## 設計

### ADR

- 0105-1 全体の CLAUDE.md の安全の原則の節の行も、ほかの節と同じ基準で見直す(R1)
- 0105-2 既定のブランチにマージした作業ブランチは、マージの後にリモートからも消す(R2)
- 0105-3 リモートのブランチを消す push は、既定のブランチにマージ済みのときだけフックが通す(R2-1・R2-2)
- 読んだ ADR: 0040-2・0047-3(安全の節の行)、0076-1・0076-2・0088-1・0090-1・0090-6(安全の節を見直さない理由)、0056-3・0056-4・0056-5・0022-2(作業ブランチを push する理由とマージの手順)

### 置くファイルと名前・データ

- `claude/CLAUDE.md`: 安全の節の「破壊的な DB 操作(DROP / TRUNCATE / WHERE なし DELETE)は、ローカル・開発用の DB にだけする。」を消す(R1)
- `tests/medium_test_global_claude_md_length.py`: 失敗の文から「1. 減らすのは、安全の原則の節(800 字前後)のほかの行。」を消し、番号を詰め、2つの ADR の番号の所に 0105-1 を足す(R1-3)
- `claude/hooks/block_history_erasing_push.py`: マージ済みのブランチを消す push を通す(R2-1・R2-2)
- `docs/specs/block_history_erasing_push.py.md`: 「ADR」の節を「- 0105-3」にし、下の動きを書き足す(R2-1・R2-2)
  - リモートのブランチを消す push(`--delete`・`-d`・`:<ブランチ>`)は、消すブランチがみな、リモートの今の先端(`git ls-remote <リモート> refs/heads/<ブランチ>`)を、手元のリモートの既定のブランチ(`refs/remotes/<リモート>/HEAD` が指すもの)が履歴に含むとき(`git merge-base --is-ancestor`)だけ通す。
  - 既定のブランチそのもの・リモートに無いブランチ・先端のコミットを手元に持たないブランチ・`refs/remotes/<リモート>/HEAD` が無いリモートを消す push は止める。
  - 同じ push に、ほかの消す引数(`--force`・`--mirror`・`--prune`・`+` で始まる refspec・`-d` 以外の f か d を含む短いフラグ)があれば止める。
  - git は、コマンドに `-C <フォルダ>` があればそのフォルダ、無ければフックに渡る `cwd` で走らせる。git が失敗したか、20 秒で終わらなければ止める。
  - 止める文には、マージ済みでないなど、止めた理由とブランチの名前を書く。
- `claude/skills/task-team-lead/SKILL.md` の「マージ後、worktree は `git worktree remove`、作業ブランチは `git branch -d` で削除する。」を「マージ後、worktree は `git worktree remove`、作業ブランチは `git branch -d` と `git push <リモート> --delete <作業ブランチ>` で削除する。(ADR 0105-2)」にする(R2)

### 手順

1. 安全の節の9行を、Claude Code 自体の指示(desktop アプリと CLI。引いた文は共有のメモ `0105-cli-default-safety-quotes.md`)・ほかの行・deny とフックと照らした。消すのは8の1行(R1-1・R1-2・R1-4)。

| 行 | 結論 | 理由 |
|---|---|---|
| 1. 作業ブランチ・既定のブランチに直接コミットする例外(ADR 0047-3) | 残す | 前半は道具の「If on the default branch, branch first.」と重なるが、チケットを既定のブランチに直接コミットする例外は利用者の決定で、消すとその動きが無くなる |
| 2. `small-chestnut` のリポジトリでマージして push する | 残す | 道具の指示は「Commit or push only when the user asks.」で、消すと頼まれるまでマージも push もしない |
| 3. 節目ごとにコミットする | 残す | 2と同じく、消すと頼まれるまでコミットしない |
| 4. 未コミットとリポジトリの外は伝えてから消す(ADR 0040-2) | 残す | 道具が確かめるのは戻せない操作だけ。ゴミ箱(6)に移すと戻せる操作になるので、消すと伝えずにゴミ箱へ移しうる |
| 5. git にコミット済みのものは完全に消す | 残す | 6の例外。消すと、コミット済みのものもゴミ箱に移す |
| 6. 削除は `trash` | 残す | 道具の指示に無い |
| 7. Windows の `trash` のパス | 残す | 道具の指示に無い事実 |
| 8. 破壊的な DB 操作はローカル・開発用の DB にだけ | 消す(R1-4) | 自分の判断でする破壊的な操作は、道具の「hard to reverse ... confirm first」で確かめる。この行に残る働きは、利用者が頼んだ本番の DB の操作を断らせることだけで、リポジトリの CLAUDE.md の「利用者が頼んだ本番の作業を断らせる文を置かない」(タスク 0036 で、本番の DB を直す依頼を断られた利用者の苛立ちから置いた)とぶつかる |
| 9. permissions・フック・サンドボックスは頼まれたときだけ・編集は agent-config の側 | 残す | CLI の道具の指示には、Claude が自分で設定やフックを変えることを止める文が無い。deny が止めるのは `settings.json` の Edit だけ。後半は道具が知りえない置き場の事実 |

2. 置くファイルの `claude/CLAUDE.md` と `tests/medium_test_global_claude_md_length.py` を直す(R1・R1-3)。確かめ方: `grep -n "DB 操作" claude/CLAUDE.md` が何も出さず、`grep -n "安全の原則の節" tests/medium_test_global_claude_md_length.py` が何も出さない。
3. テスト一覧の R2 のテストを先に書き、フックと仕様を直す(R2-1・R2-2)。
4. skill `task-team-lead` の1行を直す(R2)。
5. PL が main にマージしてインストールした後、PL が `git fetch --prune` し、`git branch -r --merged origin/main` に出る作業ブランチを、`git push origin --delete <ブランチ>...` でみな消す(R2-3)。確かめ方: もう一度 `git fetch --prune` して `git branch -r --merged origin/main` を見る。消したブランチは、コミットが main の履歴に残るので、名前を付け直せば戻せる。取りやめたタスクのブランチのように main にマージされていないものは、フックが止めるので残る。

### テスト一覧

| テスト名 | テストサイズ | 受け入れ条件 |
|---|---|---|
| 直す: `test_履歴を消すpushは当たった引数を書いて止める`(消す push の3件は、マージ済みでないと返す確かめに差し替えて流す) | small | R2-2 |
| `test_マージ済みのブランチを消すpushは通す`(`--delete`・`-d`・`:<ブランチ>` の3つの形) | small | R2-1 |
| `test_マージしていないブランチを消すpushは止める`(いくつか並べた中に1つでもあれば止める) | small | R2-2 |
| `test_既定のブランチを消すpushは止める` | small | R2-2 |
| `test_消すpushにほかの消す引数が混ざれば止める` | small | R2-2 |
| `test_マージ済みかを確かめられなければ止める`(git の失敗・時間切れ) | small | R2-2 |
| `medium_test_block_history_erasing_push.py` の `test_マージ済みのブランチはリモートから消せる`(手元に作った裸のリモートと clone で) | medium | R2-1 |
| 同じファイルの `test_マージしていないブランチはリモートから消せない` | medium | R2-2 |
| 同じファイルの `test_手元に無いコミットを持つブランチはリモートから消せない`(別の clone から push した先端) | medium | R2-2 |

- small のテストは、git を走らせる確かめを差し替えて、引数の読み方だけを確かめる。git を走らせる所は medium で、本物の git で確かめる(戻せない削除を通すと損失が取り返せないので、本物の git でも確かめる)。
