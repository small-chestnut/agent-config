## 難しさ

- SE: 高(安全の節は、行が無くて起きる損失が取り返しのつかない節で、採用した ADR 2つの理由と逆向きの依頼)

## ゴール

全体の CLAUDE.md の安全の原則の節から消しても動きが変わらない行を消し、main にマージ済みの作業ブランチをリモートからも消せるようにする。

範囲外: R2 に関わらない permissions の deny とフック。

## 要件

### R1 安全の節の、消しても動きが変わらない行を消す

- 要件: 全体の CLAUDE.md(`claude/CLAUDE.md`)の「原則1: 安全」の節の行を1行ずつ確かめ、消しても Claude の動きが変わらない行を消す。
- なぜ: 利用者は、安全の文が今でも要るかを疑い、要らない行なら消したい(2026-11-28、PL の会話で「タスクにする」と答えた)。このリポジトリの命題(ほかのリポジトリで読まれる文章を少なく保つ)に沿う。
- なぜ(見直す節を分けない): 利用者は、どの節も見直しから外さない。節の重要度と、見直せるかどうかは関わらない(2026-11-28)。ADR 0088-1(捨てた案6)と ADR 0090-1(捨てた案3)が、安全の節を見直さない理由とした「行が無くて起きる損失は取り返しがつかない」は撤回した。

- 受け入れ条件 R1-1: 消した行のどれにも、その行が無くても同じ動きになる根拠が、設計に書いてある。
- 受け入れ条件 R1-2: 残した行のどれにも、消すと動きが変わる理由が、設計に書いてある。

### R2 main にマージ済みの作業ブランチは、リモートからも消す

- 要件: main にマージ済みの作業ブランチは、リモートからも消せるようにし、今リモートに残っているマージ済みの作業ブランチも消す。
- なぜ: 利用者は、完了した作業のリモートのブランチが気になっていて、どこまでのブランチを残すかを、前の現場の慣習でなく広く使われるやり方に沿わせたい。そのやり方が安全の規則に当たるなら、規則の側を見直してよいとした(2026-11-28)。GitHub flow は、マージしたらブランチを消す(https://docs.github.com/en/get-started/using-github/github-flow 。2026-11-28 に調べた)。このリポジトリは作業ブランチをマージコミットで main に入れるので、ブランチを消してもコミットは main の履歴に残る。
- 受け入れ条件 R2-1: main にマージ済みのブランチをリモートから消す push は、フックに止められない。
- 受け入れ条件 R2-2: main にマージされていないブランチをリモートから消す push は、今どおりフックに止められる。
- 受け入れ条件 R2-3: リモートに、main にマージ済みの作業ブランチが残っていない。
