- 要件(ベストプラクティス): 安全の節の行は、ベストプラクティスから外れていないかでも照らし、外れた行は直すか消す。

- 受け入れ条件 R1-2: 残した行のどれにも、消すと動きが変わる理由が、設計に書いてある。
- 受け入れ条件 R1-3: 全体の CLAUDE.md が字数の上限を超えたときの減らし方の文が、安全の節の行を、消す候補から外していない。

### R2 main にマージ済みの作業ブランチは、リモートからも消す

- 要件: main にマージ済みの作業ブランチは、リモートからも消せるようにし、今リモートに残っているマージ済みの作業ブランチも消す。
- なぜ: 利用者は、完了した作業のリモートのブランチが気になっていて、どこまでのブランチを残すかを、前の現場の慣習でなく広く使われるやり方に沿わせたい。そのやり方が安全の規則に当たるなら、規則の側を見直してよいとした(2026-11-28)。GitHub flow は、マージしたらブランチを消す(https://docs.github.com/en/get-started/using-github/github-flow 。2026-11-28 に調べた)。このリポジトリは作業ブランチをマージコミットで main に入れるので、ブランチを消してもコミットは main の履歴に残る。
- 受け入れ条件 R2-1: main にマージ済みのブランチをリモートから消す push は、フックに止められない。
- 受け入れ条件 R2-2: main にマージされていないブランチをリモートから消す push は、今どおりフックに止められる。
- 受け入れ条件 R2-3: リモートに、main にマージ済みの作業ブランチが残っていない。

### R3 このリポジトリの命題を、あるべきものを、あるべき量だけ持つことにする

- 要件: リポジトリ直下の CLAUDE.md の命題(このリポジトリ)を「ほかのリポジトリで作業するときに読み込まれる agent-config の文章(全体の CLAUDE.md・skill)は、あるべきものを、あるべき量だけ持つ。」にし、そこから導く原則を2つ置く。正否「文章は、IT のベストプラクティスに沿う。」、要不要「文章は、無くても Claude ができることを持たない。」。
- なぜ: 利用者は、ルールの要不要と正否を別の軸で見る考えを元から意図していたが、命題には要不要だけがあり、伝わらなかった。要不要が命題にあるなら、正否も同じ重さ。「少なく保つ」は、量を減らすことが目指すものになり、あるべき文まで消す向きに働くので怖い。本質は、あるべきものを、あるべき量もつこと(2026-11-28)。
- 受け入れ条件 R3-1: リポジトリ直下の CLAUDE.md の命題(このリポジトリ)の行が、要件の命題の文になっている。
- 受け入れ条件 R3-2: 命題(開発の進め方)の行の次に、要件の原則2つが1行ずつある。
- 受け入れ条件 R3-3: README の「なぜ(このリポジトリの命題)」が、新しい命題の理由になっている。

  - リモートのブランチを消す push(`--delete`・`-d`・`:<ブランチ>`)は、消すブランチがみな、リモートの今の先端(リモートごとに1回だけ走らせる `git ls-remote --heads <リモート>` の結果)を、手元のリモートの既定のブランチ(`refs/remotes/<リモート>/HEAD` が指すもの)が履歴に含むとき(`git merge-base --is-ancestor`)だけ通す。
  - 既定のブランチそのもの・リモートに無いブランチ・先端のコミットを手元に持たないブランチ・`refs/remotes/<リモート>/HEAD` が無いリモートを消す push は止める。
  - 同じ push に、ほかの消す引数(`--force`・`--mirror`・`--prune`・`+` で始まる refspec・`-d` 以外の f か d を含む短いフラグ)があれば止める。
  - git は、コマンドに `-C <フォルダ>` があればそのフォルダ、無ければフックに渡る `cwd` で走らせる。消す push と同じコマンドに `cd`・`chdir`・`Set-Location`・`sl`・`pushd`・`Push-Location`・`popd`・`Pop-Location` があるか、git に `--git-dir`・`--work-tree` があれば、確かめるリポジトリと push するリポジトリが別になりうるので止める。
  - 時間の上限は、フック全体で 20 秒にする。走らせる git ごとに、残りの時間を上限に渡す。git が失敗したか、残りの時間を使い切ったら止める。20 秒は、Claude Code のフックの既定の上限(資料により 60 秒か 600 秒)より短く、ブランチの数によらず上限に届く前に止まる。ブランチごとに走らせる `git merge-base --is-ancestor` は手元だけで済み、ネットワークに出るのはリモートごとの `git ls-remote` だけ。
  - 止める文には、マージ済みでないなど、止めた理由とブランチの名前を書く。
- `claude/skills/task-team-lead/SKILL.md` の「マージ後、worktree は `git worktree remove`、作業ブランチは `git branch -d` で削除する。」を「マージ後、worktree は `git worktree remove`、作業ブランチは `git branch -d` と `git push <リモート> --delete <作業ブランチ>` で削除する。(ADR 0105-2)」にする(R2)

- `README.md`: 「なぜ(このリポジトリの命題)」を「なぜ(このリポジトリの命題): agent-config は、ほかのリポジトリで作業するときの拡張パーツで、そのリポジトリの決まりと一緒に読み込まれる。ベストプラクティスから外れた文は、量によらず、ほかのリポジトリでの作業を誤らせる。無くても Claude ができる文は、その分だけ、ほかのリポジトリでの作業の負担になる。量を減らすこと自体を目指すと、あるべき文まで消す。」にする(R3-3)
