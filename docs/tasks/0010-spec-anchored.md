# ゴール

機能(モジュール)ごとの仕様を1つ残し、そのモジュールの動きを変えるタスクのたびに直す(spec-anchored)。SE が機能の今の動きを知るのに読むのは、その機能の仕様1つで、タスクの数に比例して増えない。仕様には、そのモジュールを縛る ADR の番号を並べ、コードを書き換える SE がその ADR にたどり着ける。

利用者の理由: 利用者は「spec駆動開発の考えは、このリポジトリに取り入れられている？」と聞き、agent-config の目的(新しいシステムを開発するとき、そのリポジトリの CLAUDE.md を作りこまなくても、agent-config の設定を読めば、すぐに AI 駆動開発に最適な環境ができること。利用者の言葉を整えた文)の話のあとで「だから、spec駆動開発が要るんじゃない？って思った」と言った。

範囲外: 既にあるモジュール(agent-config の hooks も)の仕様をまとめて作ることと、仕様の直し忘れをフックやテストで検査すること。

# 受け入れ条件

ADR 0010-1・0010-2 の採用のあとに書く。

# 設計

決定は [ADR 0010-1](../adr/0010-1-spec-per-module.md)・[ADR 0010-2](../adr/0010-2-adr-list-in-spec.md)(どちらも提案)。設計の残りは、採用のあとに書く。
