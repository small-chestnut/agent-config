# ゴール

全体の CLAUDE.md(`claude/CLAUDE.md`)の、利用者の「なぜ」を残す規則が、「利用者が言った内容だけを、まとめた文で残す」としか読めない。その「なぜ」(原文ママでは、利用者が一番やりたいことと言葉がずれうる)が、`.claude/rules/global-claude-md.md` に残っている。

範囲外: PL の skill(`claude/skills/task-team-lead/SKILL.md`)の行と、「なぜ」の置き場の決め方そのもの。

# 受け入れ条件

1. `claude/CLAUDE.md` の「### 目指す状態: 利用者が決めたことと、利用者が言った理由が、リポジトリに残っている」の下に、「- 利用者が依頼の中で言った「なぜ」は、言った内容だけをまとめた文で、同じ変更で残している。」の行がある。
2. 同じ見出しの下に、1 の次に続けて、次の3行がこの順にある。
   - 「- 「なぜ」の置き場は、システムを作る理由なら `docs/概要.md` の冒頭。」
   - 「- 後で同じ機能を変えるときにも守る理由なら、そのモジュールの CLAUDE.md。」
   - 「- その修正で用が済む理由なら、コミットメッセージの本文。」
3. `claude/CLAUDE.md` に、「言った内容だけを、同じ変更で残している。置き場は、」で始まる元の1行が無い。
4. `claude/CLAUDE.md` の、1・2・3 のほかの行は、変える前と同じである。
5. `.claude/rules/global-claude-md.md` の末尾に、「# 原則5: 意図」「## 目的: 残した利用者の「なぜ」が、利用者が一番やりたいこととずれない」「### 目指す状態: 「なぜ」は、言葉どおりではなく、利用者が言った内容をまとめた文で残る規則になっている」「- 「なぜ」を、利用者の言葉を原文のまま書き写して残す規則にしていない。」がこの順にある。
6. `.claude/rules/global-claude-md.md` の、5 のほかの行は、変える前と同じである。
7. `python -m unittest discover -s tests` が全部通る。

# 設計

決まりの文書だけの変更。`claude/CLAUDE.md` は決まりの文書そのものが仕様なので、`docs/specs/` は作らない。書き換える行とその見出しに ADR の番号は無い。足す行には ADR を付けない。ADR は書かない。

元の1行は、字数を数えるフック(`claude/hooks/check_rule_length.py`)の上限 60 字を超えている。書き換えた行は足した行として数えられるので、1行を4行に分ける。4行と手順2の1行は、どれも 60 字以内(数えた値: 44・28・40・27・34)。

利用者の「なぜ」は、この規則を後で変えるときにも守る理由なので、ADR 0020-1 のとおり、`claude/CLAUDE.md` に `paths` を向けた `.claude/rules/global-claude-md.md` に置く。

# 実装

設計どおりに、`claude/CLAUDE.md` の1行を4行に置き換え、`.claude/rules/global-claude-md.md` の末尾に「原則5: 意図」を足した。改行は元のファイルに合わせて CRLF のまま。

- `git diff` は手順1・2の行だけ(12行追加・1行削除)。
- `python -m unittest discover -s tests`: 64件、全部通った(lint のコマンドはこのリポジトリに無い)。
- 保存後に字数のフックが、足した行ごとに「消しても意味が変わらない語」の見直しを求めた。足した行は受け入れ条件 1・2・5 が一字単位で決めているので、変えていない。
