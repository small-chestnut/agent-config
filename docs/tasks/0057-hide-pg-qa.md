## 壁打ち

### 固まった要件

- PG と QA は、今のとおり別のセッションとして起こす。利用者が直接やりとりしないので、サイドバーの一覧に見えなくてよい。
- サイドバーは子だけを別の区切りへ移せないので、SE をピン留めし、利用者が PL の行を畳む形にする。畳んだ PL の下に2行残るのはよい。
- SE のピン留めは、利用者の手でなく、PL がする。
- PL の手順の「なぜ」の「利用者が、チームの動きを見て、口を挟み、止められる」から、PG と QA は外す。見て止める相手は PL と SE で、PG と QA はリンクから開ければよい。

### なぜ

- 利用者がやりとりするのは PL と SE だけで、PG と QA の行は一覧を長くするだけだから。
- AI の出力は人が読み切れる量を越えてきていて、AI 駆動開発の速さを決めるのは、人が AI の出力の概要を早く正確につかめるかだから。AI の調整と並んで、利用者が AI の出力をつかむときの認知負荷を下げることを大事にする。PG と QA を見せないことも、タスクの話をそのタスクの SE の会話だけですることも、この認知負荷を下げる。これはリポジトリ全体の「なぜ」なので、README にも置く(手順6)。

### 調べて分かったこと(2026-11-10、このセッションで確かめた)

- サイドバーは区切りで並ぶ。agent-config・atcoder・ジェミニなどの区切りは、利用者が作った区切り(custom group)。表示を切った区切りは描かれない(`list_sections` の `shown: false`。今は「ルーティン」だけ)。
- PL が起こした SE・PG・QA は、どれも PL と同じ区切り「agent-config」に入っている。
- 区切りを作る(`create_section`)・セッションを移す(`move_sessions`)道具はある。区切りの表示を切る道具は無く、利用者がサイドバーでする。
- PL が起こした子セッションは、サイドバーで PL の下に入れ子になり、子だけを別の区切りへ移せない(PG が `move_sessions` で確かめた)。入れ子は親と一緒に動く。
- サイドバーでは、PL の行に畳む矢印があり、その下に SE・PG・QA が字下げで並ぶ(利用者の画面で確かめた)。畳むと3つが一緒に隠れ、PG と QA だけを畳む所は無い。
- SE をピン留めし、PL の行を畳むと、SE は「ピン留め済み」に出る。畳んだ PL の下には、PG の行と「他に 1 件のネストされたセッション・未読 1 件」の行が残った(利用者の画面で確かめた)。PG の行が残る理由は分かっていない。
- ピン留めは `set_pinned` で AI からできる。ピン留めしたセッションは自動のアーカイブから外れ、`archive_session` も、ピン留めしたセッションはアーカイブしない(道具の説明)。
- 子を入れ子から外す `detach_session` は、起こした PL にしか使えず、元に戻せない。道具の説明では、ほかのセッションと worktree を分け合う子(PG と QA)には使えない。

### 決まっていない問い

- 畳んだ PL の行が、PL が次のタスクのチームを起こしたあとも畳まれたままか。開いてしまうなら、利用者が畳み直す。このタスクでは確かめられないので、次のタスクで見る。
