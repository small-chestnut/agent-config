## ゴール

利用者が直接話さない PG と QA のセッションを、セッションのまま、サイドバーに出さないようにする。

範囲外: PG と QA を SE の中で動くサブエージェントにすること。SE と PL の出し方。

## 壁打ち

### 固まった要件

- PG と QA は、今のとおり別のセッションとして起こす。利用者が直接やりとりしないので、サイドバーの一覧に見えなくてよい。
- PL の手順の「なぜ」の「利用者が、チームの動きを見て、口を挟み、止められる」から、PG と QA は外す。見て止める相手は PL と SE で、PG と QA はリンクから開ければよい。

### なぜ

- 利用者がやりとりするのは PL と SE だけで、PG と QA の行は一覧を長くするだけだから。
- AI の出力は人が読み切れる量を越えてきていて、AI 駆動開発の速さを決めるのは、人が AI の出力の概要を早く正確につかめるかだから。AI の調整と並んで、利用者が AI の出力を分かりやすくすることを大事にする。これはリポジトリ全体の「なぜ」なので、README にも置く(手順5)。

### 調べて分かったこと(2026-11-10、このセッションで確かめた)

- サイドバーは区切りで並ぶ。agent-config・atcoder・ジェミニなどの区切りは、利用者が作った区切り(custom group)。表示を切った区切りは描かれない(`list_sections` の `shown: false`。今は「ルーティン」だけ)。
- PL が起こした SE・PG・QA は、どれも PL と同じ区切り「agent-config」に入っている。
- 区切りを作る(`create_section`)・セッションを移す(`move_sessions`)道具はある。区切りの表示を切る道具は無く、利用者がサイドバーでする。

### 決まっていない問い

- 表示を切った区切りに移したセッションが、ほんとうにサイドバーから消えるか。子セッションは親のセッションの下に入れ子で描かれるので、区切りより入れ子が勝つかもしれない。サブタスク 3 で確かめる。
- 表示を切った区切りのセッションを、PL の「利用者待ち」の行のリンクから開けるか。サブタスク 4 で確かめる。

## 受け入れ条件

1. PG と QA を区切り「PG と QA」へ移し、その区切りの表示を切ると、サイドバーに PG と QA の行が出ない。
2. 表示を切った区切りにある PG の会話を、PL の会話に出た「利用者待ち」の行のリンクから開ける。
3. PL は、PG と QA を起こしたら、区切り「PG と QA」へ移している。
4. PL は、区切り「PG と QA」が無ければ作り、作ったときだけ、表示を切ることを利用者に頼んでいる。
5. PL の手順の「なぜ」は、サイドバーに残るのを PL と進行中のタスクの SE としている。
6. README の目的の下に、人が AI の出力の概要を早く正確につかめることを大事にする「なぜ」がある。

## 設計

ADR: 0057-1(提案)。書き換える行に付いた ADR は無い。

画面: Claude アプリの Code タブの左のサイドバー。「ルーティン」の区切りを切ったのと同じ所で、区切りの表示を切る。

区切りの名前は「PG と QA」にする。表示を切るので、利用者が目にするのは区切りの表示を切り替える所だけで、そこで中身が分かる名前にした。どのリポジトリのチームも、この1つの区切りを使う。

### 手順

1. (PG)区切りを作り、このタスクの PG と QA を移す。
   - `list_sections` で名前「PG と QA」の区切りを探し、無ければ `create_section` で作る。
   - `move_sessions` の `section_id` にその id、`session_ids` に PG `local_6a0eeb82-bf97-48f7-bceb-d4249e98d039` と QA `local_a7efdae1-0cf0-4a40-8339-b3e75833ed86` を渡す。
   - `list_sessions`(linked)で、2つの `group.name` が「PG と QA」になったことを確かめる。
   - 失敗する条件: PG の権限の形が既定(default)だと、ほかのセッションを移すたびに利用者に聞く。そのときは利用者待ちにして、許可してもらう。
2. (利用者)区切り「PG と QA」の表示を切り、PG と QA の行が消えたかと、リンクで PG の会話が開くかを確かめる。サブタスク 3・4。
   - 何を: サイドバーで、区切り「PG と QA」の表示を切る。続けて、PL の会話に出た利用者待ちの行のリンクを押す。
   - ゴールへのつながり: 表示を切った区切りで本当に隠れるかと、隠れたセッションに利用者が行けるかは、アプリの画面でしか確かめられない。この2つが通らなければ、この設計は使えない。
   - なぜ利用者の手でか: 区切りの表示を切る道具が AI の側に無い。リンクを押して開くかも、利用者の画面でしか分からない。
   - 頼み方: PG は「利用者待ち」の行に、この操作と PG 自身の会話へのリンクを書き、PL に知らせる。PL は、その行を言い換えずに利用者に出す(今の手順のまま)。
   - 失敗する条件: PG と QA の行が PL の下に入れ子で出続ける。リンクを押しても PG の会話が開かない。どちらでも、PG は手順3に進まず、実装の節に見えたとおりを書いて SE に知らせる。
   - 終わったら利用者が返すこと: リンクで開いた PG の会話で、「行は消えた・消えない」と「リンクで開いた」の2つ。
   - 元に戻すには: 区切りの表示を入れ直し、`move_sessions` で PG と QA を区切り「agent-config」へ戻す。元に戻せない操作は無い。
3. (PG)`claude/skills/task-team-lead/SKILL.md` の、目的「利用者が、PL 1つと話すだけで、どのタスクがどこまで進んだかをつかめる」の下、目指す状態「利用者の入口は PL 1つで…(ADR 0056-1)」の次に、次の段を足す。

   ```
   ### 目指す状態: サイドバーには、利用者が話す PL と SE だけが出ている(ADR 0057-1)

   - PG と QA は、起こしたら、区切り「PG と QA」へ `move_sessions` で移している。
   - 区切りは `list_sections` の名前で探し、無ければ `create_section` で作っている。
   - 区切りを作ったときだけ、表示を切ることを利用者に頼んでいる。
   ```

4. (PG)`claude/skills/task-team-lead/CLAUDE.md` の、目指す状態「役割は、利用者が開いて話しかけられるセッションで回っている」の下の行を、次の2行に替える。コミットメッセージの本文に「前の理由 → 新しい理由」を書く。
