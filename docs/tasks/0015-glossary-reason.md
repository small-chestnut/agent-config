# ゴール

用語集を作る理由として利用者が言ったことが、言った内容だけ、README の「プロンプト層(CLAUDE.md)の意図」の節に残っている。

利用者の理由:「用語集を作っている理由が、これもまた、ユビキタス言語を策定することによって、リポジトリ内に、例えや比喩が混入することを防ぐため」。

範囲外: 用語集と例えの規則(`claude/CLAUDE.md` の原則2・原則3)の文を変えること。

# 受け入れ条件

1. README の「プロンプト層(CLAUDE.md)の意図」の節に、用語集(ユビキタス言語)の項目があり、利用者の理由が言葉のままある。
2. その項目には、利用者の理由のほかに理由を書いていない。
3. `claude/CLAUDE.md` は変わっていない。

# 設計

置き場は README の「プロンプト層(CLAUDE.md)の意図」の節。グローバルの CLAUDE.md の規則は、後で同じ機能を変えるときにも守る理由をモジュールの CLAUDE.md に置くと書くが、agent-config では CLAUDE.md の規則を置く理由をこの節に書いてきた(モジュラーモノリスの項目)ので、リポジトリの決まりに合わせる。

決定は新しく足さないので ADR は書かない。書き換える行に付いた ADR の番号は無い。新しい名前は無く、用語集は変えない。動きは変わらないので、仕様も変えない。

## 手順: README に項目を足す(する人: PG)

`README.md` の「## プロンプト層(CLAUDE.md)の意図」の節で、「- **ソースは業務のまとまり(モジュール)ごとのフォルダに置き、…(モジュラーモノリス)**(ADR 0012-1・0012-2)。」の項目(「AI が読む量が減るという理由は、…agent-config が組み立てたもの」の行まで)の次に、次の項目をそのとおりの文で足す。

```
- **用語集(`docs/用語集.md`)に、業務の言葉とコードの名前を1対1で並べる(ユビキタス言語)**。
  利用者の理由は「用語集を作っている理由が、これもまた、ユビキタス言語を策定することによって、リポジトリ内に、例えや比喩が混入することを防ぐため」
```

失敗する条件: main に入った他のタスクの変更で、モジュラーモノリスの項目が動いたか消えていたら、main を取り込み、「CLAUDE.md の原則3「開発」は、…」の項目の後の、ほかの項目の間に入れる。

## コミット

PG は README の変更を1つのコミットにする。本文に利用者の理由を書く必要は無い(README に残る)。

## テスト一覧

文書だけの変更なので、テストは作らない。確かめ方を下に並べる。

| 確かめ方 | 大きさ | 受け入れ条件 |
|---|---|---|
| `git diff main -- README.md` を読み、上の2行が上の位置にそのまま入り、ほかの行が変わっていない | — | 1・2 |
| `git diff main --stat -- claude` が空 | — | 3 |
| `python -m unittest discover -s tests` が通る(既にあるテスト。終わる前の確かめとして流す) | 小 | — |

lint のコマンドはこのリポジトリに無い。
