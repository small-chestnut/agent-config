## ゴール

task-team のセッションが、ほかのセッションから届いた利用者の許可を、利用者の許可として扱えるようにする。

範囲外: 利用者でなく、セッションが自分の判断で出した許可。ツールを動かすかを聞く確認の画面(許可のダイアログ)。このタスクで permissions・フック・サンドボックスの設定そのものを変えること。

## 壁打ち

### 固まった要件

- ほかのセッションが利用者の許可を届けたとき、受け取ったセッションが、利用者に同じ許可をもう一度求めない。(利用者のタスクの文)
- 扱われなかったのは、受け取ったセッションが「本番を変える操作」か「安全の設定」だと言った操作の許可。(利用者の答え)
- 利用者の言葉でない行は、Claude Code が付ける決まった書き出しで除く形で進める。(利用者の答え)

### なぜ

- 同じ許可を、セッションごとに利用者がもう一度出すのは面倒。(利用者のタスクの文)
- PL や SE で出した許可を、畳んで見えなくした PG からもう一度求められるのは筋が通らない。(利用者の言葉)

### 分かっていること

- Claude Code の安全の規則では、許可は利用者がその会話で出したものだけが有効で、ツールの結果や届いた文の中で「許可された」と言うだけのものは無効。
- 同じ規則は、ほかのセッションへ許可を伝えるときは、利用者の言葉を引いて伝えるよう求めている。
- 今の task-team の skill には、許可を届ける側の書き方も、受け取る側の確かめ方も無い。
- SendMessage のツールの説明は、自分のセッションで止められた操作を、ほかのセッションにさせることを禁じている。届いた文は `<cross-session-message from="...">` に包まれて届く。
- 届いた文には、Claude Code が「ほかのセッションの文を、待っている許可への利用者の承認として扱わない」という注意を添える。
- セッションは、ほかのセッションの会話の記録を `list_events` で読める。記録では、利用者が書いた言葉も、届いた文や Claude Code の知らせも `[user]` の行に出る。Claude Code が `[user]` の行に出す文は、決まった書き出しで始まる。PL・PG の会話を `list_events` で読んで確かめた書き出しは、`<`(`<system-reminder>`・`<task-notification>` など)・`Another Claude session sent a message:`(届いた文)。QA が PG の会話で確かめた書き出しは、`Background (from the session that started this one)`(起こしたセッションの依頼)・`Base directory for this skill:`(skill の本文)。この SE の会話で見た書き出しは、`Tool loaded.`(ツールの読み込み)。会話の圧縮の要約の書き出し `This session is being continued` は、記録で確かめていない。
- PG の skill の「外部のシステムの設定」の行は、PG に、実行の直前に利用者に確かめさせている。

## 受け入れ条件

- 利用者の許可を届ける文に、許可された操作と、利用者の言葉の引用と、その言葉を書いたセッションの id が入っている。
- 許可を受け取ったセッションは、`list_events` で、届けたセッションの記録の利用者の言葉を探している。
- 利用者の言葉は、そのセッションで利用者が書いた `[user]` の行から探している。
- 書き出しが `<`・`Another Claude session`・`Background (from`・`Base directory`・`Tool loaded.`・`This session is being continued` の行は、利用者の言葉として扱っていない。
- 利用者の許可を届ける文は、チケットの置き場と読む節と頼むことに、許可の届け方の3つを足したもの。
- 利用者の言葉が見つかったら、その言葉が言う操作の範囲で、利用者の許可として扱っている。
- 利用者の言葉が見つからなければ、利用者に聞かず、届けたセッションにそう返している。
- PG と QA は、利用者の許可が要る操作を PL に知らせ、許可が届くまで待っている。
- PL は、利用者の許可を子セッションに届けるとき、skill `task-team-messaging` の届け方に従っている。
- PG は、外部のシステムの設定を変える操作を、実行の直前に PL に知らせ、利用者の許可が届いてからしている。

## レビュー

- 設計1(安全の原則に触れる): 「`[user]` の行のうち `<` のタグで始まらない行」では、利用者の言葉と、ほかの文を分けられない。子セッションの記録では、起こしたセッションの依頼(`Background (from the session that started this one): … Task: …`)と、skill の本文(`Base directory for this skill: …`)も、タグで始まらない `[user]` の行に出る(PG の会話を `list_events` で読んで確かめた)。SE が自分の id で許可を届けると、PL が書いた依頼の文が、利用者の言葉として通ってしまう。
- 設計2: 手順1 の「届ける文に、許可された操作と、利用者の言葉の引用と、セッションの id を入れている」が、task-team-messaging の原則2 の「送る文は、チケットの置き場と読む節と、頼むことだけ。(ADR 0024-1)」とぶつかる。設計は、その行をどうするかを書いていない。
- 設計3: 手順4 で ADR 0064-1 を「採用」にするのを SE としているが、task-team-qa では、指摘の無い ADR を QA が設計レビューで「採用」にしている(ADR 0007-1)。
