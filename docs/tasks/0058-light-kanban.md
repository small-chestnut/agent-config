## ゴール

PL がかんばんを書き直すときに、PL の会話に入る量を減らす。

目的とのずれ: skill `task-team-lead` の原則2 は、PL のコンテキストを進行中のタスクの分だけにする。今は、子セッションの知らせ1回ごとに、PL がかんばんの書き直しで道具を6〜7回呼ぶ(fetch・データの行を読む・ファイルを読む・行を組む・上げる・指し替える・古いファイルを消す)。タスク 0057 では、書き直しが9回あった。

PL が、リポジトリの決まりで聞かずに回すタスク(ADR 0046-3)。

範囲外: かんばんのページ(`.claude/skills/team-kanban-page/index.html`)と、カードのデータの形(項目)は変えない。

### 試運転の手順(サブタスク 4。する人: PG)

1. チケットのステータスを「実装中」にしてコミットし、作業ブランチを push する。カードはリモートの作業ブランチのチケットから作られるので、push しないと 0058 のカードは「実装中」にならない。
2. SE からの SendMessage で始まったターンの中で、Agent の道具を `model: "sonnet"` で呼び、次の文で頼む。「`<この worktree のパス>` のリポジトリのかんばんのカードを、`<この worktree のパス>/claude/skills/team-kanban/SKILL.md` に従って書き直して」。まだ install していないので、skill の名前でなくファイルのパスで指す。
3. サブエージェントの最後の返答が、かんばんのリンク1行だけかを見る。
4. そのリンクを開き、agent-config のタブに 0058 のカードが「実装中」で出ているかを見る。開けなければ、チケットの「利用者待ち」の行に書いて、利用者に画面で確かめてもらう。

失敗する条件:

- 子セッションの知らせで始まったターンでは Agent の道具が使えない: ADR 0058-1 の前提が崩れるので、直さずに SE に知らせる。
- サブエージェントが、Artifact や ArtifactData の書き込みの許可を利用者に求めて止まる: 止まったことと、どの道具かを SE に知らせる。
- 同じ時に PL が今の手順でかんばんを書き直すと、書き込みが断られることがある。手順どおり読み直してやり直すので、失敗ではない。
