## ゴール

- どのリポジトリでも、書いている途中の確かめでは、AI が変えた所のテストだけを、リポジトリの CLAUDE.md にあるコマンドの形で流す。
- agent-config の CLAUDE.md に、全部のテストのコマンドと、変えた所のテストだけを流すコマンドの形がある。
- 範囲外: フックの変更と、マージの前に全部を流す決まり(ADR 0009-3)。

## 受け入れ条件

1. 全体の CLAUDE.md に「変えた所のテストだけを流すコマンドの形も、リポジトリ直下の CLAUDE.md に書き足している。」の行がある。
2. 全体の CLAUDE.md に「その形は、テストのコマンドと同じ頭で始めている。(ADR 0011-2)」の行がある。
3. agent-config の CLAUDE.md に、全部のテストのコマンドの行と、変えた所のテストだけを流すコマンドの形の行がある。
4. その形でテストのファイルを1つ指すと、そのファイルのテストだけが流れて通る。
5. その形のコマンドは、`.claude/verify-commands.txt` の頭 `python -m unittest` で始まる(Stop フックが確かめとして数える)。

## 設計

### 直すファイル

| ファイル | 直すこと |
|---|---|
| `claude/CLAUDE.md` | 「### 目指す状態: 変更が意図どおりかを自分で確かめてから、終わったと報告している」の節の、「テストと lint のコマンドの頭は、`.claude/verify-commands.txt` にも1行ずつ書いている。(ADR 0011-2)」の行の次に、下の2行をこの順で足す |
| `CLAUDE.md`(このリポジトリの直下) | 下の「agent-config の CLAUDE.md」のとおり、1行を書き換え、その次に1行を足す |

この2つのほかは直さない。仕様: `claude/CLAUDE.md` はプロンプトなので、その文書が仕様(この変更で直す)。ADR は書かない(ADR 0009-3 の「書いている間は変えた所の小」を、どのリポジトリでも流せるようにする手段で、決定を変えない)。

### 全体の CLAUDE.md に足す2行

```
- 変えた所のテストだけを流すコマンドの形も、リポジトリ直下の CLAUDE.md に書き足している。
- その形は、テストのコマンドと同じ頭で始めている。(ADR 0011-2)
```

- 1行目を「ある」でなく「書き足している」にするのは、テストのコマンドが既にあるリポジトリでも AI が足すようにするため。「テストと lint のコマンドが無いリポジトリには、最初の作業で足している」は、テストのコマンドが1つでもあるリポジトリ(agent-config など)では効かない。
- 2行目は、Stop フック(`require_verify_before_stop.py`)が、`.claude/verify-commands.txt` の頭で始まるコマンドだけを確かめとして数えるため。頭が違うと、変えた所だけ流しても Stop フックに止められ、AI は全部を流すことになる。頭が同じなら、フックを変えずに済む(ADR 0011-2 の理由2が、絞って流すことを頭の一致で受けている)。
- 字数(`check_rule_length.py` の数え方): 1行目49字、2行目36字。上限60字以内。

### agent-config の CLAUDE.md

書き換える行:

```
- テストは、リポジトリのルートで `python -m unittest discover -s tests`。
```

を、次の2行にする:

```
- 全部のテストは、リポジトリのルートで `python -m unittest discover -s tests`。
- 変えた所のテストだけは、`python -m unittest tests/<テストのファイル>.py`(いくつもなら空白で並べる)。
```

- 字数: 21字・28字。
- `python -m unittest tests/a.py tests/b.py` の形で、ファイルを並べて流せることを確かめた(`test_check_rule_length.py` と `test_skill_md_bullet_length.py` を並べて12件が通った)。
- どのテストのファイルを選ぶかは AI が決める。選び漏れは、マージの前に全部を流すとき(ADR 0009-3、skill `task-team-pg` の「CI が無ければ、QA に頼む前に、小と中の全部…」)に見つかる。
