## ゴール

PL が SE に送る文が、タスクを始めるときとタスクの途中の場面ごとに、何を送り何を送らないかまで決まっていて、PL が設計の中身を決めて SE に渡すことが無い。

## 壁打ち

### 今の決まり(skill `task-team-lead` の行番号)

PL が設計方針を決めて SE に渡すのは、今の決まりでも禁じている。PL が持つのは「話題がどのタスクに当たるかまで」で、タスクの中身には答えない(18行目・ADR 0056-1)。

| 場面 | PL が SE に送るもの | 決まっているか |
|---|---|---|
| 開始前: 利用者が頼んだタスク | skill `task-team-se` に従う指示・タスクの文(利用者の文のまま)・チケットの保存先(55・57・66行目) | 決まっている |
| 開始前: 聞かずに進めるタスク | 上に、聞かずに進めると添える(67行目) | 決まっている |
| 開始前: コミットされていないチケットで始める | 上に、チケットのパスを添える(109行目) | 決まっている |
| 開始前: ほかの PC から続ける | 上に、ほかの PC から続けると添える(118行目) | 決まっている |
| 開始前: PL が見つけたタスク | 「PL が書いた文」(57行目)。何を書くか(ゴール・なぜ・見つけた事実だけか、直し方まで書くか)は決まっていない | 決まっていない |
| 途中: 利用者が PL にタスクの中身を話した | 送らない。利用者に SE の会話へのリンクを出す(15・37行目) | 決まっている |
| 途中: 利用者の許可を届ける | 許可された操作と、利用者の言葉の引用(82行目・ADR 0064-2) | 決まっている |
| 途中: ほかのタスクが main に入り、進行中のタスクが前提にする規則やコードが変わった | 何も決まっていない | 決まっていない |

### 決まっていない問い

1. 利用者が「まずい」と思ったきっかけの場面(PL の送り文に設計の中身が入っていた、など)があったか。
2. ほかのタスクが main に入って前提が変わった場面を、このタスクに入れるか。
