# ゴール

task-team の skill(`task-team-lead`・`task-team-se`・`task-team-pg`・`task-team-qa`)を、コードの無いタスク(情シス的な作業、特定のリポジトリに紐づかないタスク)でも同じ仕組みで回せるようにする。

# 要件

## ゴール

README・`claude/CLAUDE.md`・skill 3つ(lead・se・pg)に、コードの無いタスクの受け皿・読み替え・外部のシステムの設定を変える操作の扱いが書いてあり、`python -m unittest discover -s tests` が通る。

## 範囲外

- `task-team-qa` の skill(利用者の決定: 足さない)。
- 記録だけを置くリポジトリ(例: `tasks`)そのものを作ること。
- main へのマージ・push・`install.ps1 -Yes`(PL がする)。
- フックとテストのコードを変えること。

## 受け入れ条件

1. README の「セッションの役割分割」の節に、リポジトリに紐づかないタスクの受け皿が書いてある。
2. `task-team-se` と `task-team-pg` に、目指す状態「コードの無いタスクも、同じ節と順で回っている」と読み替えの3行がある。
3. `task-team-se` の同じ目指す状態の下に、手順を設計に書く1行がある。
4. `task-team-pg` に、目指す状態「外部のシステムの設定は、利用者が直前に認めた操作でだけ変わっている」と2行がある。
5. `task-team-lead` に、記録だけのリポジトリでの子の起こし方と、main への直接コミットの2行がある。
6. どの SKILL.md の箇条書きの行も 60 字以内(`python -m unittest discover -s tests` が通る)。
7. `task-team-qa` の SKILL.md は変わっていない。
8. コミットメッセージの本文に、利用者の理由の文がそのままある。
9. `claude/CLAUDE.md` 原則1の作業用のブランチの行に、記録だけのリポジトリを除く例外がある。

# 設計

## 決めたこと(利用者の決定)

- 記録だけのリポジトリでは、記録を main に直接コミットする。子が同じフォルダで動くため。
- その例外は `claude/CLAUDE.md` 原則1に足す(安全の規則の変更を、利用者の依頼として扱う)。
- PG の規則の対象は、外部のシステムの設定を変える操作すべて(元に戻せるかを PG に判断させない)。
- QA の skill には足さない。
- 読み替えは、SE と PG の原則1に新しい目指す状態を足し、その下に置く。文は下のとおり(利用者が合意した文)。
- SE に、設計の節に手順を操作ごとに書く1行を足す(QA が手順をレビューできるように)。
