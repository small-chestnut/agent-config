## 要件

### R1 仕様をコードから作るとき、業務の状態を業務の分野の定義と照らす

- 要件: skill `task-team-se` の「作るときは、そのタスクで読んだコードの今の動きを書いている。」を、業務の状態を書く行は業務の分野の定義と照らし、違う所を「決まっていない問い」にする形にする。
- なぜ: 仕様がコードの分かれ方を写すと、コードの取り違えが仕様に入り、仕様と照らすレビューでも見つからない(LogiFee R-0822)。
- 受け入れ条件 R1-1: 仕様の無い機能の仕様を作る SE は、コードの業務の状態が業務の分野の定義と違う所を、決まっていない問いにする

### R2 決まりの1行を、決まりの文書を読まない3つのセッションに読ませて確かめる

- 要件: 決まり(CLAUDE.md・skill・ほかの AI への指示)の1行を追加する・修正するときに、その1行だけを、決まりの文書を読まない3つの新しいセッションに渡し、答えた意味が3つとも同じで、書いた意図と合うときだけ通す手順を、全体の側に作る。
- なぜ: 3つの答えが割れる決まりは、読むたびに違う決まりとして働く。3つがそろっていても意図と違うことがあり、書いた本人は前後の事情を知っているので本人が読む確かめは甘くなる。どのリポジトリの決まりにも要る確かめなので、全体の側に置く。
- 受け入れ条件 R2-1: 決まりの1行を追加する Claude は、決まりの文書を読まない3つのセッションの答えが同じ意味で意図と合うまで、その行を入れない
- 受け入れ条件 R2-2: 決まりの文書を読まないセッションは、サインイン情報を写さずに起動する

### R3 決まりの1行は、その1行だけを読んで利用者が意味を分かる文にする

- 要件: skill `prompt-structure` に、決まりの1行は、見出しもほかの行も読まずにその1行だけを読んで、利用者が意味を分かる文にすることを入れる。
- なぜ: 決まりを管理するのは利用者で、その1行だけで読めない決まりは、Claude に効いていても、残すか直すかを利用者が決められない。
- 受け入れ条件 R3-1: skill `prompt-structure` を読んで決まりの1行を書く Claude は、その1行だけで意味が分かる文にする
