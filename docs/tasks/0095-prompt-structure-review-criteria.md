## ゴール

決まりを規則から上へさかのぼって確かめるとき、どの段でも、すぐ上の段に合っているかを判断できる形に、Claude が決まりを組むよう、skill prompt-structure を直す。

範囲外: LogiFee の決まりを組み直すことと、原則を1語にする LogiFee の決まり(LogiFee のリポジトリの作業)。

## 要件

### R1 段は4段にし、見直しの基準を足さない

- 要件: 決まりの段は、命題 → 原則 → 目的 → 規則の4段にし、目指す状態の段を無くす。規則を見直すための基準(語尾変換チェック・別手段テスト・1段ズレチェックなど)は、skill に足さない。
- なぜ: 目的と目指す状態の区別は、人にも分かりにくい。5段でも認知負荷がかかっているのに、基準を足すと、利用者の負荷がさらに上がる。
- 受け入れ条件 R1-1: skill prompt-structure に、目指す状態の段と、見直しの基準の行が無い。

### R2 目的は、下の規則とつながる粒度で書く

- 要件: 4段の目的は、下の規則が合っているかを、目的の文から判断できる粒度で書く。目指す状態の段を抜いて、抽象的な目的だけを残さない。
- なぜ: 規則から上へ確かめるとき、途中の段で判断できないと、意図がそこで途切れる。
- 受け入れ条件 R2-1: 組み直した後の、規則とすぐ上の目的の組で、目的の文から規則が合っているかを決められない件数が、組み直す前(規則とすぐ上の目指す状態)より増えていない(新しいセッションの採点で)。

### R3 今ある文書も4段に直す

- 要件: agent-config に今ある文書(全体の CLAUDE.md・rules・skill。目指す状態の見出し 125)を4段に組み直す。段の見出しを見るフック(`ask_about_written_lines.py`)も4段に合わせる。利用者は、フックの問いの文も変わると聞いたうえで「直す」と答えた。1つのタスクで進める。
- なぜ: 決まりの型と、型の見本になる今ある文書を合わせる。
- 受け入れ条件 R3-1: 全体の CLAUDE.md・rules・skill に、目指す状態の見出しが無い。

### ADR

- [0095-1 プロンプトの段は、目指す状態を無くし、命題・原則・目的・規則の4段にする](../adr/0095-1-four-levels-without-states.md)(状態「提案」)

### 置くファイルと名前・データ

- 全部の見出しの直し: `headings.md`(チケットと同じ名前のフォルダ)。どの文書も、この表のとおりに直す。(R2・R3)

- `claude/hooks/ask_about_written_lines.py`: `LAYER_HEADING` から `### 目指す状態` を除き、`LAYER_QUESTION` を「3. 原則・目的の見出しは、すぐ上の段(原則なら命題)から導いた文にし、下の段の手段の言葉を入れない。」にする。冒頭の docstring は、今のまま合う。(R3)
- `docs/specs/ask_about_written_lines.py.md`: 18行目を「問う行に原則・目的の見出しがあれば、…」にし、「ADR」の節に 0095-1 を足す。(R3)

### 手順

1. フックの正規表現と問いの文を直し、下のテスト2つを直してから動かす。(R3)
2. `headings.md` のとおり、skill prompt-structure・全体の CLAUDE.md・rules・ほかの skill を、この順で直す。1つの skill ずつコミットする。(R1・R2・R3)
3. 字数のテスト(`tests/medium_test_global_claude_md_length.py`)・small と medium を通す。(R3)
4. `grep -rn "目指す状態" claude .claude README.md CLAUDE.md docs/specs` に、ADR 以外の当たりが無いことを確かめる。(R1-1・R3-1)
5. 共有フォルダの `0095-trial/run5.py` の `judge` を、組み直す前後の agent-config の規則とすぐ上の見出しの組に当て、判断できない件数を比べる。`parse` に渡すのは、直す前と後の CLAUDE.md と SKILL.md の文。件数を「実装」の節に書く。(R2-1)
