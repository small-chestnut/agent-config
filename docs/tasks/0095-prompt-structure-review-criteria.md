## ゴール

決まりを規則から上へさかのぼって確かめるとき、どの段でも、すぐ上の段に合っているかを判断できる形に、Claude が決まりを組むよう、skill prompt-structure を直す。

範囲外: LogiFee の決まりを組み直すことと、原則を1語にする LogiFee の決まり(LogiFee のリポジトリの作業)。

## 要件

### R1 段は4段にし、見直しの基準を足さない

- 要件: 決まりの段は、命題 → 原則 → 目的 → 規則の4段にし、目指す状態の段を無くす。規則を見直すための基準(語尾変換チェック・別手段テスト・1段ズレチェックなど)は、skill に足さない。
- なぜ: 目的と目指す状態の区別は、人にも分かりにくい。5段でも認知負荷がかかっているのに、基準を足すと、利用者の負荷がさらに上がる。
- 受け入れ条件 R1-1: skill prompt-structure に、目指す状態の段と、見直しの基準の行が無い。

### R2 目的は、下の規則とつながる粒度で書く

- 要件: 4段の目的は、下の規則が合っているかを、目的の文から判断できる粒度で書く。目指す状態の段を抜いて、抽象的な目的だけを残さない。
- なぜ: 規則から上へ確かめるとき、途中の段で判断できないと、意図がそこで途切れる。
- 受け入れ条件 R2-1: 命題から規則までのすぐ上の段との組で、上の段の文から合っているかを決められない組の割合が、組み直す前より増えていない(新しいセッションの採点で)。

### R3 今ある文書も4段に直す

- 要件: agent-config に今ある文書(全体の CLAUDE.md・rules・skill。目指す状態の見出し 125)を4段に組み直す。段の見出しを見るフック(`ask_about_written_lines.py`)も4段に合わせる。利用者は、フックの問いの文も変わると聞いたうえで「直す」と答えた。1つのタスクで進める。
- なぜ: 決まりの型と、型の見本になる今ある文書を合わせる。
- 受け入れ条件 R3-1: 全体の CLAUDE.md・rules・skill に、目指す状態の見出しが無い。

## レビュー

### 設計レビュー

- R2 と ADR 0095-1: ADR は「目的は、下の規則が合っているかを判断できる粒度で書く(詳しい文は skill `prompt-structure`)」と言うが、`headings.md` はその文を skill に足さず、今ある「どの規則も、親の段を読めば、なぜあるかが分かる」だけが残る。ゴールは、Claude がその形に組むよう skill を直すこと。粒度の文を skill に足すか、フックの問いに任せて ADR の指す文を直すかを決める。
- R2: 「AI の費用対効果を最適化する」の目的を消すと(task-team-model-assignment・task-team-se・task-team-qa)、費用の意図が段から消える。「各役割は、…難しさに合うモデルと effort になっている」のすぐ上が「最善の性能を出せる」になり、規則「低は `claude-sonnet-5-5` の high」が合うかを上の段から判断できない(ADR 0059-1 の理由は使用量を損なわないこと)。
- R2・R3: task-team-qa の目的「指摘が、チケットとコードだけを根拠にしている」を消すと、同じことを言う規則がほかに無く、決まりが1つ無くなる。
- ゴール・R2-1: ゴールは「どの段でも」だが、採点は規則とすぐ上の目的の組だけ。抽象的な目的を消して、目的のすぐ上が原則に変わる組は、確かめる手順が無い。
- R2-1: ec7f2a6 で、受け入れ条件が「決められないものが無い」から「件数が増えていない」に緩んでいる。利用者が緩めることに合意したかが、チケットにもコミットメッセージにも無い。
- 手順5(R2-1): `run5.py` は読み込むだけで生成と採点が走り、共有フォルダの答えと `judge5.json` を上書きするので、`judge` と `parse` だけは使えない。`parse` は SKILL.md の front matter と、task-team-se のテンプレートの見出しと箇条書きも組にする。採点の回数・多数決・前後を混ぜるかも決まっていない。PG の難しさは「低」。
- skill `task-team-se`「動きを変えるときは、設計のコミットで仕様を直す」: `docs/specs/ask_about_written_lines.py.md` を、設計で直さず PG に残している。
- ADR 0095-1 の「置き換える: 」に、決めたことが目指す状態の段に触れている採用の ADR 0046-3・0066-1 が無い。
- ADR 0095-1 で決めた行に番号が付かない所がある: 全体の CLAUDE.md の3行目(今は 0090-3 だけ)と、`LAYER_HEADING` のコメント(今は 0061-1 だけ)。
- Nit: ADR 0095-1 の理由4の「5段では、5段の中のほかの段の組の言い直しが8(47)」は、「5段+フックの、規則のほかの組」と書くと表と合わせて読める。

### 設計レビュー(ADR 0095-2)

- 利用者の合意(skill `prompt-structure`「命題・原則・目的は、利用者が合意したものだけ」): チケットにあるのは「利用者は、原則の文を替えると決めた」で、2つの文そのものに合意したかが無い。AI 側は候補が2つあり、SE が片方を捨てている(ADR 0095-2 の捨てた案3)。文に合意したかを確かめて、「サブタスクの前提」に書く。
- ADR 0061-2 の理由3(原則を命題の面の名前にすれば、どの規則も、命題のどの面に効くかで照らせる): 人間側の新しい文「自分の意図どおりに AI を動かせる」と、AI 側の新しい文「利用者の意図どおりに作業を終えられる」が、同じ「意図どおり」を受け持つ。たとえば skill prompt-structure の目的「…規則に無いことでも AI が利用者の意図どおりに動ける」(AI 側の下)は、人間側の文にもそのまま合い、どちらの面の目的かを決められない。2つの面が別のものを受け持つ文にする。
- Nit: ADR 0095-2 の理由1は今の文の判断できない組を AI 側 64/76・人間側 20/42、理由2は 76/76・24/42 と書く。同じ文で値が違うので、理由2は別の回の採点だと書き、回ごとのぶれの幅を添える。
