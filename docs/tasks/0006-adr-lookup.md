# ゴール

SE が1つのタスクで読む ADR の数が、タスクの数に比例して増えない。そのために、ADR で決めた所にその ADR の番号を付け、SE は設計で書き換える所に付いた番号の ADR と、それが置き換えた古い ADR だけを読む。新しい ADR には置き換えた古い ADR の番号を書き、1つの ADR には決定を1つだけ、どの決定かが分かる1行で書く。QA は番号の付け忘れを見る。既にある ADR 0004-1・0005-1 は書き換えず、それらで決めた行に番号を付ける。

利用者の理由:「タスクがスケールしたときに、1番目のタスクと3000番目のタスクで、一次関数的に、あなたが見るADRが増えてしまうと、私が破産する」。

範囲外: ほかのリポジトリの既にある ADR に番号を付けることと、番号の付け忘れをフックやテストで検査すること。

# 受け入れ条件

1. `task-team-se` の、設計の最初に ADR を引く行が、書き換える所に付いた番号の ADR と、そこから「置き換える: 」でたどった古い ADR だけを読む行になっていて、「対象: 」の行を検索する行が無い。
2. `task-team-se` に、ADR で決めた所に番号を付ける行(プロンプトは行の末尾・コードは決定を守らせる所か形にした所の1か所・どれにも当たらなければモジュールの CLAUDE.md の行)がある。
3. `task-team-se` の ADR の形の行に、置き換える ADR の行と、1つの ADR に決定を1つ・「決めたこと」を1行にする行がある。
4. `task-team-qa` に、ADR で決めた所に番号が付いているかを見て、付け忘れを指摘に足す行がある。
5. グローバルの CLAUDE.md(`claude/CLAUDE.md`)原則3 の ADR の行が、決定を1つ・「決めたこと」を1行にしていて、ADR で決めた所に番号が付いていることを言う行がある。
6. ADR 0004-1・0005-1 で決めた行(skill・グローバルの CLAUDE.md・`codex/AGENTS.md`・README)に番号が付き、`docs/adr/0004-1-adr-driven.md` と `docs/adr/0005-1-test-criteria.md` は変わっていない。
7. この変更で足した行と変えた行のうち、ADR 0006-1〜0006-3 で決めた行に、その番号が付いている。
8. README の「セッションの役割分割」の節の ADR駆動の項目に、番号から読むやり方と利用者の理由がある。
9. `docs/用語集.md` に、ADR で決めた所に付ける番号と、置き換える ADR の行がある。
10. どの SKILL.md の箇条書きの行も 60 字以内(`python -m unittest discover -s tests` が通る)。
