# ゴール

SE が1つのタスクで読む ADR の数が、タスクの数に比例して増えない。そのために、ADR で決めた所にその ADR の番号を付け、SE は設計で書き換える所に付いた番号の ADR と、それが置き換えた古い ADR だけを読む。新しい ADR には置き換えた古い ADR の番号を書き、1つの ADR には決定を1つだけ、どの決定かが分かる1行で書く。QA は番号の付け忘れを見る。既にある ADR 0004-1・0005-1 は書き換えず、それらで決めた行に番号を付ける。

利用者の理由:「タスクがスケールしたときに、1番目のタスクと3000番目のタスクで、一次関数的に、あなたが見るADRが増えてしまうと、私が破産する」。

範囲外: ほかのリポジトリの既にある ADR に番号を付けることと、番号の付け忘れをフックやテストで検査すること。

# 受け入れ条件

1. `task-team-se` に、設計の最初に、書き換える行とその見出しに付いた ADR の参照を集め、コードを書き換えるときはそのモジュール・テスト・lint の設定を「ADR」で検索して、書き換えるコードに効く所の参照も集め、その番号の ADR と、「置き換える: 」でたどった古い ADR だけを読む行があり、「対象: 」の行を検索する行が無い。
2. `task-team-se` に、ADR で決めた所に ADR の参照を付ける行(プロンプトは行か見出しの末尾・コードは決定を守らせる所か形にした所の1か所・どれにも当たらなければモジュールの CLAUDE.md の行)がある。
3. `task-team-se` に、新しい ADR に置き換える ADR の行を書き、古い ADR の状態を「置き換え済み(<新しい番号>)」にする行と、一部だけを置き換えるときの行がある。
4. `task-team-se` の ADR の形の行に、1つの ADR に決定を1つ・「決めたこと」を1行にする行があり、「各1〜3行」は捨てた案と理由だけにかかっている。
5. `task-team-qa` に、ADR で決めた所に ADR の参照が付いているかを見て、付け忘れを指摘に足す行がある。
6. グローバルの CLAUDE.md(`claude/CLAUDE.md`)原則3 に、1つの ADR に決定を1つ・「決めたこと」を1行にする行と、ADR で決めた所に ADR の参照を付ける行がある。
7. ADR 0004-1・0005-1 で決めた行(skill・グローバルの CLAUDE.md・`codex/AGENTS.md`・README)に、設計の表のとおり ADR の参照が付き、`docs/adr/0004-1-adr-driven.md` と `docs/adr/0005-1-test-criteria.md` は変わっていない。
8. この変更で足した行のうち、ADR 0006-1〜0006-3 で決めた行に、設計のとおり ADR の参照が付いている。
9. README の「セッションの役割分割」の節に、ADR の参照から ADR を読むやり方と利用者の理由がある。
10. `docs/用語集.md` に、ADR の参照と置き換える ADR の行があり、ADR の対象の意味に「SE が設計の最初に検索する」が無い。
11. どの SKILL.md の箇条書きの行も 60 字以内(`python -m unittest discover -s tests` が通る)。

## ADR の参照の形

- 形は `(ADR <ADR の番号>)`。2つ以上なら `(ADR 0004-1・0006-1)` と「・」で並べる。括弧は半角。
- 箇条書きと地の文の行は、行の一番後ろ(「。」の後ろ)に付ける。
- 見出しは、見出しの文の後ろに付ける。見出しの番号は、その下の行みなに効く。下の行が自分の番号も持つときは、両方が効く。
- README の項目は、既にある `**(ADR 0005-1)。` に合わせ、太字の後ろ・「。」の前に付ける。
