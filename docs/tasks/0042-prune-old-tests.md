## check_rule_length.py

1. プロンプトを保存して、HEAD から足した決まりの行に 60 字を超える行があれば、その行番号を並べて Claude に返す。
2. HEAD からある決まりの行は、60 字を超えていても知らせない。
3. git にまだ入っていないプロンプトは、全部の決まりの行を数える。
4. UTF-8 でないプロンプトも、落ちずに数える。
5. 決まりの行は、行頭の空白の後に「- 」が続く行で、コードブロックの中の行は除く。
6. 字数は「- 」より後ろを数え、60 字までは知らせず、61 字から知らせる。
7. `…` で囲んだコードは1字と数える。
8. 名前が CLAUDE.md・AGENTS.md・SKILL.md のファイルは、プロンプト。
9. `.claude/rule-documents.txt` に書いた glob に当たるファイルもプロンプト。その一覧の空の行と `#` で始まる行は読まない。
10. git の外のファイルは数えない。

## ask_removable_words.py

11. プロンプトを保存すると、HEAD から足した行のうち、この保存で書いた文字列を含む行だけを、行番号付きで並べて Claude に返す。
12. この保存で書いた文字列が行の一部でも、その行を問う。
13. HEAD から変わっていない行は、この保存で書いた文字列を含んでいても問わない。
14. 空の行とコードブロックの中の行は問わない。
15. この保存で書いた文字列は、Edit では new_string、MultiEdit では各編集の new_string、Write では content。

## block_history_erasing_push.py

16. Bash・PowerShell の git push が、--force・--delete・--mirror・--prune、f か d を含む短いフラグ、+ か : で始まる refspec を含めば、当たった引数を理由に書いて止める。
17. --force-with-lease を含む git push は、どの位置にあっても利用者の確認に回す。
18. &&・||・;・|・改行でつないだコマンドは、1つずつ見る。止める push と確認に回す push が両方あれば止める。
19. ふつうの git push と、push 以外の git のコマンドは、何も返さずに通す。

## 大きさ

- 一時的な git リポジトリを作るテストは、ファイルと別のプロセスを使うので中(ADR 0009-1)。字数と問い返すフックは git を読むので、入口から確かめる一番小さい大きさが中。
- push のフックは git もファイルも読まないので、同じプロセスの中で `main()` を呼び、小にする。呼ぶ前に `sys.stdin`・`sys.stdout`・`sys.stderr` を `io.TextIOWrapper(io.BytesIO(…), encoding="utf-8")` に替え、`finally` で戻す。標準出力・標準エラーは flush してから `.buffer.getvalue()` を UTF-8 で読む(SE が手元で、止める・確認・通すの3通りが取れることを確かめた)。
- このリポジトリの中のテストには、まだ大きさの印が無い。印を付けるのは範囲外(ADR 0009-2 のファイル名の印は、unittest の discover がドットを含む名前を読まないので、そのままでは使えない)。
