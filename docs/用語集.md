# 用語集

このリポジトリには画面が無いので、「コードの名前」には、ファイル名と、記録・ADR に書く字を書く。

| 業務の言葉 | コードの名前 | 画面に出す字 | 意味 |
|---|---|---|---|
| タスクの番号 | `<番号>`(例: `0004`) | — | PL が振る4桁の連番。タスク名の頭に付く |
| タスク名 | `<タスク名>`(例: `0004-adr-driven`) | — | タスクの番号とハイフンと英語の短い名前。記録・子セッション・ブランチの名前に使う |
| ADR | `docs/adr/<ADR の番号>-<英語の短い題>.md` | — | 決定の記録。後から変えにくい設計の決定と、捨てた案と、理由を残す |
| ADR の番号 | `<タスクの番号>-<そのタスクの中の連番>`(例: `0004-1`) | — | ADR を書いたタスクと、そのタスクの中の順 |
| ADR の状態 | `状態: 提案`・`採用`・`却下`・`廃止`・`置き換え済み(<ADR の番号>)` | — | その決定がいま効いているか |
| ADR の対象 | `対象: <モジュールの名前>` か `対象: 全体` | — | その決定が効くモジュール |
| ADR の参照 | `(ADR <ADR の番号>)`(2つ以上は `(ADR 0004-1・0006-1)`) | — | ADR で決めた所(行・見出し・コードの1か所)に付ける、その ADR の番号。SE はこれをたどって ADR を読む |
| 置き換える ADR | `置き換える: <ADR の番号>`(一部なら `置き換える: <ADR の番号> の<決めたことの番号>`) | — | 新しい ADR の「対象: 」の次の行。その ADR が置き換えた古い ADR |
| 利用者の判断待ち | `ステータス: 利用者の判断待ち(ADR <ADR の番号>)` | — | 記録のステータスの1つ。提案した ADR を利用者が採用するかを待っている |
| テスト一覧 | 記録の設計の節の `## テスト一覧` の表 | — | 作るテストの名前・大きさ・受け入れ条件の表。SE が書き、PG はそのとおりに作る |
| テストの大きさ | 小・中・大 | — | テストが触る範囲。中は外部とのつなぎ目、大は本物の環境で画面から通す。中身はリポジトリの CLAUDE.md |
| テストの基準 | `task-team-se` の、テスト一覧の2つの目指す状態 | — | 作るテストと作らないテストと、大きさの決め方。QA がレビューで比べる |
| モジュール | 規則の中では `modules/<モジュール>/`。このリポジトリでは skill の名前か hooks のファイル名 | — | 業務のまとまり。画面のナビの行き先ごと、画面が無ければ扱うデータのまとまりごとにあり、そのフォルダに画面・処理・データの出し入れを置く(ADR 0012-1) |
| 公開の入口 | モジュール直下の1つのファイル(`index.ts`・`__init__.py`・`<モジュール>Api`) | — | ほかのモジュールが使ってよいものだけを出すファイル。入口の外は、ほかのモジュールから直接使わない(ADR 0012-2) |
| リポジトリの決まり | — | — | 作業するリポジトリにコミットされた文書に書かれた決まりと、既にあるファイルの並び。agent-config の規則とぶつかったら、こちらに従う |
