# 0095-1 プロンプトの段は、目指す状態を無くし、命題・原則・目的・規則の4段にする

状態: 採用
日付: 2026-11-24
対象: 全体
置き換える: 0061-1 の、段を5段にする所・0045-1・0046-3・0048-1・0066-1・0084-4・0087-2・0090-3・0093-1・0093-2 の、目指す状態の段に触れる所

## 決めたこと

プロンプトの段は「命題 → 原則 → 目的 → 規則」の4段とし、目指す状態の段を無くして、規則のすぐ上の段に目的を置く。目的は、読めば下の規則がなぜあるかが分かる粒度で書く(skill `prompt-structure` の目的「どの規則も、親の段を読めば、なぜあるかが分かり、…」)。

## 捨てた案

1. 5段のまま、目指す状態を見直す基準(語尾変換チェック・別手段テスト・1段ズレチェック)を足す: 5段でも認知負荷がかかっていて、基準を足すと利用者の負荷がさらに上がる(利用者の理由)。
2. 4段にして、目的を見直す基準も足す: 1と同じ。試しでも、基準を足すと規則がすぐ上の目的から判断できない組が増えた(理由4)。
3. 5段のまま、目的と目指す状態の違いを書いた定義を戻す: 目的と目指す状態の区別は、人にも分かりにくい(利用者の理由)。2026-11-17 に消した段の定義を足し戻した試しで、言い直しは減らなかった。
4. 5段のときの抽象的な目的を残し、目指す状態だけを抜く: 規則とつながらない目的だけが残る(利用者の理由)。

## 理由

1. 利用者の理由: 目的と目指す状態の区別自体が、人に分かりにくい。段を足して延命するより、段を減らす。
2. 段が少ない方が、Claude が段を書くときの迷いが減る(どちらの段に書くかを選ばずに済む)。
3. 目指す状態の段は、Claude が段を埋めようとして、規則の語尾を変えた文を書く場所になっていた。
4. 試し(2026-11-24。LogiFee の規則8つを、決まりの文書を読まない新しいセッション(`claude-opus-5-5`)に組ませ(3回)、どの組み方かを知らない別のセッションに3回ずつ採点させた(多数決)。件数は、規則と、すぐ上の見出しの組 24 の、言い直し・判断できない):

   | 組み方 | 言い直し | 判断できない |
   |---|---|---|
   | 5段(今の skill) | 9〜12 | 0 |
   | 4段 | 4〜7 | 0 |
   | 4段+見直しの基準 | 0 | 5〜6 |
   | 4段+今あるフックの段の問い(skill に足す文は無い) | 0 | 2 |
   | 5段+今あるフックの段の問い | 0 | 3 |

   今あるフックの段の問いは、段の見出しを足すと「すぐ上の段から導いた文にし、下の段の手段の言葉を入れない」と問い返すもの(ADR 0061-1)。4段では、命題から目的までの組でも、判断できない組は1(33)で、言い直しは2だった。5段+今あるフックの、規則のほかの組は、言い直しが8(47)。3回ずつの試しなので、件数は向きを見る材料。
5. 目的を規則とつながる粒度で書く理由: 規則から上へ、目的・原則・命題に合っているかを確かめるとき、途中の段で判断できないと、意図がそこで途切れる。
6. 目指す状態の見出しは、どの skill も数が多く(125)、フックとテスト・仕様も同じ形に依存している。型と、型の見本になる今ある文書を、同じ変更で合わせる。
7. ADR 0061-1 のうち、命題を頂点に、すぐ上の段から導いて書くことは変えない。
