# 0087-1 規則の1行は、決まりの文書を読まない3つのセッションにスクリプトで読ませ、答えが同じ意味で意図と合うまで直す

状態: 採用
日付: 2026-11-15
対象: prompt-structure

## 決めたこと

規則の行を足す・直すときは、先に意図を1文で書き、その行だけを、skill `prompt-structure` のフォルダのスクリプト `ask_rule_line_meaning_in_fresh_sessions.py` で、CLAUDE.md・設定・skill・道具を読まない3つの `claude -p` に読ませ、3つの答えが同じ意味で意図と合うまで直す(詳しい文は skill `prompt-structure` と仕様 `docs/specs/ask_rule_line_meaning_in_fresh_sessions.py.md`)。

## 捨てた案

1. LogiFee の試しのやり方(ホームの写しにサインイン情報を写し、ユーザーのフォルダの外から起動する): サインイン情報を写して置くことになり、利用者に頼まれてからの操作になる。環境変数で CLAUDE.md を読ませずに起動できるので、写す理由が無い。
2. 書いた本人(今のセッション)が、その1行だけを読み直す: 書いた本人は前後の事情を知っているので、確かめが甘くなる。
3. フックで、規則の行を保存するたびに読ませる: 下書きの保存のたびに3つのセッションが走る。答えを意図と照らす判断はフックにはできない。フックを変えるのは利用者に頼まれたときだけで、頼まれていない。
4. スクリプトを作らず、`claude -p` のコマンドを Claude が毎回組む: 起動の指定(環境変数・空のフォルダ・4つのオプション・標準入力)が7つあり、1つ抜けると条件が崩れる。設計中の試しでは、標準入力を閉じ忘れたため、`claude -p` がほかの行まで読み込み、1行だけを読ませる条件が崩れた。

## 理由

1. 環境変数 `CLAUDE_CODE_DISABLE_CLAUDE_MDS=1` を付けると、サインイン情報を写さずに、CLAUDE.md を読まないセッションが起動する(2026-11-15 の試し。付けると CLAUDE.md の内容は「無し」と答え、付けないと全体の CLAUDE.md の最初の見出しを写した)。`--setting-sources ""`・`--disable-slash-commands`・`--tools ""` を足すと、skill の一覧も「無し」と答えた。
2. 3つの答えが割れる規則は、読むたびに違う規則として働く。LogiFee の試し(R-0830)では、4行のうち2行を3つのセッションがみな意図と違う意味に読み、字を直すと3つとも意図どおりに読んだ。3つがそろっても意図と違うことがあるので、意図とも照らす。
3. 意図を読ませる前に書くのは、答えを見てから意図の方を答えに合わせないため。
4. どのリポジトリの規則にも要る確かめなので、規則を書く前に読む全体の skill `prompt-structure` に置く。
