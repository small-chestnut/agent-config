# 0097-3 安全・人間側の最適化・AI 側の最適化の原則は開発の進め方の命題から、リポジトリだけの原則はそのリポジトリの命題から導く

状態: 採用
日付: 2026-11-24
対象: 全体

## 決めたこと

どのリポジトリでも、安全・人間側の最適化・AI 側の最適化の原則は、開発の進め方の命題「AI 駆動開発の最適化」(全体の命題)から、リポジトリだけの原則は、そのリポジトリの命題から導き、どちらから導くかと開発の進め方の命題を、リポジトリの CLAUDE.md にも書く。

## 捨てた案

1. どの原則も、リポジトリの命題から導く: 開発の進め方の原則は、製品の姿を言うリポジトリの命題(LogiFee なら、社員の仕事が LogiFee だけで済むこと)から導けない。
2. どちらから導くかを書かない: 新しいセッションは、どちらの命題から導くかを推測で答えた。書くと、安全が全体の命題から導かれると文を根拠に答えたのは 0/3 から 3/3 になった。
3. 開発の進め方の命題を、全体の CLAUDE.md だけに書く: agent-config を使っていない人の Claude は、安全がリポジトリの命題から導かれると答えた(3/3。つながりは推測)。
4. リポジトリの命題を「命題: 」とだけ書く: 2つの命題のうちどちらを指すかは推測だと答えたものがあった(2/3)。「命題(このリポジトリ)」と「命題(開発の進め方)」に書き分ける。
5. 全体の命題の行に、面と制約条件(ADR 0061-2)を書き足す: 答えは変わらなかった(3回)。

## 理由

1. 利用者は、安全・人間側の最適化・AI 側の最適化の原則を全体の命題から導くと決めた。
2. 原則は、命題の面か制約条件の名前にしてある(ADR 0061-2)。この3つは、命題「AI 駆動開発の最適化」の面と制約条件で、どのリポジトリでも変わらない。atcoder の「上達」のようなリポジトリだけの原則は、そのリポジトリの命題の面になる。
3. 試しは、2026-11-24 に `claude-opus-5-5` の新しいセッションに3回ずつ読ませた。
