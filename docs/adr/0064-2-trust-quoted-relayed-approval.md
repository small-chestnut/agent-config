# 0064-2 PL と SE から引用付きで届いた利用者の許可は、受け取ったセッションが確かめずに利用者の許可として扱う

状態: 提案
日付: 2026-11-11
対象: task-team-messaging・task-team-lead・task-team-pg
置き換える: 0064-1

## 決めたこと

利用者の許可を届ける PL と SE は、許可された操作と、利用者の言葉を言い換えずに引いたものを送り、受け取ったセッションは記録で確かめずに利用者の許可として扱う。PG と QA は、許可を利用者に直接求めず、PL に知らせて待つ(詳しい文は skill `task-team-messaging`)。

## 捨てた案

1. 受け取ったセッションが、届けたセッションの会話の記録で利用者の言葉を確かめる(ADR 0064-1): 記録では、利用者の文と、届いた文・skill の本文・起こしたセッションの依頼が同じ `[user]` の番に出て、見分ける規則に穴が3回見つかり、そのたびに行が増えた。
2. 引用を付けずに、許可が出たことだけを届ける: 言い換えると、読み違いがそのまま次のセッションに伝わる。Claude Code の組み込みの規則も、許可を伝えるときは利用者の言葉を引くよう求めている。
3. 今のまま、受け取ったセッションが利用者にもう一度許可を求める: PG と QA は、畳んだ PL の行の下に置いて利用者の目から外している(ADR 0057-2)。

## 理由

1. 利用者の理由: PL や SE で出した許可を、見えなくした PG からもう一度求められるのは筋が通らない。許可の扱いはややこしくせず、単純な形にする。
2. 届いた許可が Claude Code の組み込みの規則に止められるかは、どの形でも入れて試すまで分からない。分からないなら、一番単純な形で試す方が、規則を足して穴をふさぐより早い。
3. 許可を届けるのは、利用者が話す PL と SE だけで、どちらも利用者のチームのセッション。言葉を言い換えずに引けば、読み違いの多くは防げる。
