# 0061-1 プロンプトの段は、命題を頂点に、すぐ上の段から導いて書く

状態: 提案
日付: 2026-11-11
対象: prompt-structure・ask_about_written_lines.py

## 決めたこと

プロンプトの段は「命題 → 原則 → 目的 → 目指す状態 → 規則」の入れ子とし、下の段はすぐ上の段から導いて書き、段の見出しを書いた保存では導いたかをフックが問い返す(詳しい文は skill `prompt-structure`)。

## 捨てた案

1. 目的の下に目指す状態を2つ以上置く規則にする: 問題は目的と目指す状態のスコープが同じことで、数ではない。状態が1つでも一段上の目的は書け、2つあっても1つの言い換えの目的は書ける。
2. 目的を書いた後に、目指す状態の側から確かめる手順(手段の言葉が入っていないか・別の状態を挙げられるか)だけを置く: 目指す状態から上へ抽象化する向きのままで、目的のよしあしを親の段でなく子の段で決めることになる。
3. 原則を体言1つのままにする: 「開発」のような1語からは、命題のどの面を受け持つかが読めず、目的を導けない。
4. skill と QA のレビューだけにし、フックを足さない: どちらも Claude が読んで従うもので、読んでいても書く手が下から上へ向くことがある。書いたその場で問いを出せるのはフックだけ。

## 理由

1. 段を入れ子にしているのは、下の段を上の段から導くため。目指す状態を見て目的を書くと、目的が目指す状態の言い換えになり、親の段を読んでも目指す状態がなぜあるかが分からない。
2. 今の型は「原則は、下に置く目的すべてと適合するものにする」「目的は、下の状態がそろえば達成したと言える文にする」と、どちらも子の段から決める向きで、目指す状態が1つなら言い換えが最も素直に規則を満たす。点検した目的 50 個のうち 15 個が、目指す状態と同じスコープだった。
3. 段の頂点に、リポジトリを一言で説明する命題を置けば、原則がどの面を受け持つかを命題から決められ、目的のよしあしを利用者のその時の好みでなく親の段で決められる。
4. 段は今後も足していくので、今ある段を直すだけでは、足すたびにまた壊れる。
