# 0007-1 ADR は、利用者ではなく QA の設計レビューが採用にする

状態: 提案
日付: 2026-10-31
対象: 全体
置き換える: 0004-1 の1

## 決めたこと

SE が提案した ADR は、QA の設計レビューで指摘が無ければ QA が、指摘があれば直した SE が「採用」にし、利用者には採用を聞かない。

## 捨てた案

1. PL が採用にする: PL は設計を読まない決まりなので、読まずに通すだけになり、受け渡しも1回増える。
2. SE が提案と同時に採用にする: 別の目が入らず、レビューの指摘で直すときに、採用した ADR を書き換えるか置き換えることになる。
3. 今のまま利用者が採用にする: 利用者が「AI駆動開発　"AI"ですよ？人間じゃなくて」と言い、採用も聞かなくてよいと答えた。

## 理由

1. ADR を提案した変更は、もとから QA の設計レビューを受ける。SE の会話を知らない別のセッションが読むので、利用者の代わりの関係者の同意になる。Nygard は、関係者が同意したら「採用」とする(https://www.cognitect.com/blog/2011/11/15/documenting-architecture-decisions)。
2. 0004-1 の1 のうち置き換えるのは、誰が採用にするかだけ。ADR に書く対象と、task-team を通さない会話では ADR を書かないことは、0004-1 のまま。
