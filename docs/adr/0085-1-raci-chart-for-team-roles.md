# 0085-1 task-team の作業ごとの役割の表を、利用者の列を足した RACI チャートにする

状態: 採用
日付: 2026-11-14
対象: 全体

## 決めたこと

skill `task-team` の、作業ごとに受け持つ役割の ◯/✕ の表を、利用者・PL・SE・PG・QA の列に R・A・C・I を置き、どの行にも A を1つだけ置く RACI チャートにする。利用者だけがして AI のセッションが関わらない作業は、表に載せない。

## 捨てた案

1. 今の ◯/✕ の表に、利用者の列だけを足す: 作業をする役割と、結果を決める役割・意見を聞かれる役割・知らされる役割が見分けられず、ADR 0083-1 の発端になった、決める役割の取り違えが表に出ない。
2. 利用者が見せた、ほかの AI が作った表(利用者を全部の工程の A に置く表)を使う: 利用者に聞くのは目的と「なぜ」だけにする ADR 0063-1 と逆で、利用者の確かめる量が増える。タスク分解・テスト・コードレビューを受け持つ役割も、今のチームと違う。
3. 1つの行に A を2つ以上置いてよいことにする: どちらが決めるかが表から分からなくなり、取り違えが残る。

## 理由

1. 利用者の「なぜ」は、AI のセッションが受け持ちを取り違えず、各セッションが自分の役割を分かっているようにすること。
2. RACI チャートは責任分担表(responsibility assignment matrix)の定石の形で、作業をする役割(R)・結果を決める役割(A)・意見を聞かれる役割(C)・知らされる役割(I)を分け、1つの行に A を1つだけ置く(https://en.wikipedia.org/wiki/Responsibility_assignment_matrix ・ https://www.mindtools.com/?p=58822 。2026-11-14 に読んだ)。
3. ADR 0083-1 の発端は、SE が手段の決めを PL に求め、PL が答えたこと。A の列は、どの作業を誰が決めるかを1つの役割に示す。
4. skill を読むのは AI のセッションなので、AI のセッションが関わらない作業は、書いても振る舞いを変えない。利用者は、利用者だけがする作業を skill に書かないと決めた。
