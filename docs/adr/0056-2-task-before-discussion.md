# 0056-2 新しい話題は壁打ちの前にタスクにしてチームを起こし、設計は利用者が進めると言ってから始める

状態: 採用
日付: 2026-11-10
対象: task-team-lead・task-team-se

## 決めたこと

新しい話題は、PL が壁打ちをせずにタスクにしてチーム(SE・PG・QA)を起こし、SE が最初にチケットを作って壁打ちをし、設計は、利用者が SE に設計へ進めると言ってから始める。エラーや決まりと違う動きを直す依頼と、聞かずに回すタスクは、壁打ちをせずに設計を始める。

## 捨てた案

1. PL と壁打ちをし、利用者がタスクにすると言った後にチームを起こす(前の形): 壁打ちが PL の会話に入って、ほかのタスクの話と混ざる。PL がまとめて SE に渡す受け渡しで、ずれが入る。
2. 話題が来たら SE だけを起こし、PG と QA は設計に進むときに起こす: PG と QA を起こすのが SE の会話の中になり、チームを起こす所が2か所に分かれる。子セッションを起こす役は、PL に集めてある。
3. 壁打ちの間はチケットを作らず、設計に進むときに作る: 壁打ちの間、PL は何の話かをチケットから読めず、話題を当たるチームに案内できない。進み具合にも載らない。

## 理由

1. 壁打ちは、その話題しか入っていない会話で進み、設計に進んだ後も、同じ SE がそのまま続けられる。
2. 作り始めを止める所は、チームを起こす時から設計を始める時に移るだけで、利用者の理解が曖昧なまま作り始めないことは変わらない。
3. チケットが最初からあれば、PL はゴールの1行目で話題を振り分けられ、壁打ち中のタスクも進み具合に載る。
4. 代わりに、タスクにならずに終わる話題にも、チームが1つずつ立つ。そのチームは、閉じれば済む。
