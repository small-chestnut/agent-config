# 0070-2 難しさが低の仕事に、Sonnet 5.5 の medium でなく high を割り当てる

状態: 採用
日付: 2026-11-12
対象: task-team-se
置き換える: 0059-1 の低の割り当て

## 決めたこと

難しさが低の仕事は、Sonnet 5.5 の medium でなく、Sonnet 5.5 の high で動かす(詳しい文は skill `task-team-se`)。

## 捨てた案

1. Sonnet 5.5 の medium のまま: Anthropic の社内のエージェントのコードの課題で 62.7% と、high より約15ポイント下。費用は1回 $0.16 で high の約半分だが、安いモデルの費用は失敗した仕事で決まる。
2. Opus 5.5 の low: 同じ課題で 74.8%、1回 $0.35 で、Sonnet 5.5 の high(77.8%、1回 $0.33)より点が低く、費用は高い。SWE-bench Pro では Sonnet 5.5 の high と測るたびの揺れの中で同じで、解けた1件あたりの費用は約7%高い。
3. Opus 5.5 の medium: 同じ課題で 86.6% だが、1回 $0.84 で Sonnet 5.5 の high の約2.5倍。低は書いてあるとおりにやれば済む仕事で、利用者は、SE が全手順を決めきっているなら PG は今の割り当てでよいと答えた(ADR 0069-3 の捨てた案2)。設計とのずれは、QA の実装レビューが設計の節と照らして見つける(ADR 0069-2)。
4. Sonnet 5.5 の xhigh: 同じページに、エージェントのコードの課題での数字が無い。xhigh と max では、Sonnet 5.5 が仕事を終えたあとに自分でレビューを始め、時間とトークンが増える、と書いてある。
5. 決める前に、このリポジトリの低の仕事で設定を比べて測る(同じページの勧め): 測るには、同じ低の仕事を2つの設定で流して比べる仕組みが要り、このタスクの範囲を越える。このリポジトリで低の PG が動いた記録は、タスク 0069 の1件だけ。

## 理由

1. Anthropic の社内のエージェントのコードの課題(370件)で、Sonnet 5.5 の medium は 62.7%(1回 $0.16)、high は 77.8%(1回 $0.33)。Opus 5.5 は medium と high の差が約1.8ポイントで、Sonnet 5.5 だけ、effort を下げると大きく落ちる(https://platform.claude.com/docs/en/about-claude/models/optimizing-for-cost-and-intelligence.md 。2026-11-12 に読んだ。数字は Anthropic の社内の測定で、目安)。
2. PG と QA の仕事は、skill の手順に沿って道具を何度も呼ぶ作業で(ADR 0059-1 の捨てた案5)、1件の課題を解く SWE-bench Pro より、エージェントのコードの課題に近い。ADR 0059-1 が低を Sonnet 5.5 の medium にした根拠は、SWE-bench Pro の数字だけだった。
3. 同じページは、安いモデルの費用は、そのモデルが失敗した仕事で決まると書いている。失敗した仕事にもトークンがかかり、やり直しが続くから。このチームでは、PG の失敗は、Opus 5.5 の high の QA の実装レビューと直しを、一回り増やす。
4. Sonnet 5.5 の既定の effort は high(同じページ)。
5. 利用者は、測定の数字を見るかぎり、Sonnet 5.5 の high の方がよさそうだと見た(利用者の答え)。
