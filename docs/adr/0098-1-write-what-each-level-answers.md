# 0098-1 命題・原則・目的・規則の各段に何を書くかを、skill `prompt-structure` に置く

状態: 提案
日付: 2026-11-25
対象: prompt-structure
置き換える: 0095-1 の、目的を書く基準を足さないとした所(捨てた案2・3)

## 決めたこと

命題・原則・目的・規則の各段が答える問いの表と、原則・目的の見出しをすぐ上の段から導いて手段の言葉を除く文を、段を書く前に読む skill `prompt-structure` に置く。

## 捨てた案

1. 今のまま、命題・原則・目的・規則という単語だけに任せる(0095 で利用者が選んだ形): Claude は目的を「実現したい状態」と答え(6/6)、5段を4段にするとき、消える目指す状態の文をそのまま目的に移す。agent-config の今の目的 124 のうち 73 が、前の目指す状態とほぼ同じ文だった。
2. 表全体(Why・What・How の列と、判断のときの使い道の列も)を置く: よい目的は 80% で、問いの列だけの形(85〜90%)より低い。利用者の Gemini で効いたのは、案を出した後に見せた場合(91%)。
3. 基準1つ(目的は、下の規則とは別のやり方でも果たせる文にする)だけを置く: よい目的は 81%。目的が「なぜ」に答えることは言っていない。
4. フックの段の問いの文だけを置く: 出来上がる案は同じくらいよい(90%)が、目的の「なぜ」を答えられたのは 0/5 で、目的を状態と取る根が残る。
5. 目的の行だけ(「目的には、なぜ必要で、どうなっていればよいかを書く」)を、4 に足す: 二重記述は最も少なく、「なぜ」も 5/5 で答えるが、目的の 33% が「〜ので」「〜ように」と理由を付けた文になった(問いの列では 0%)。
6. 表の「規則」の行を、利用者の表のまま「何をするか/しないか」にする: 規則は、することを肯定形で書く(ADR 0027-1)。

## 理由

1. 利用者の理由: 問題の本質は、目的に手段が書かれることではなく、4段をどのような基準で書けばよいかが Claude の中に無いこと。0095 で基準を足さなかったのは、単語からしかるべき再編ができると踏み、基準を二重記述と考えたため。Claude はそのやり方で失敗したので、置く。
2. 試し(2026-11-24・25。Gemini の 0099 で直す前の CLAUDE.md と skill 3本と、atcoder の CLAUDE.md の5段の文書を、4段に組み直す案を、決まりの文書を読まない新しいセッション(`claude-opus-5-5`)に3回ずつ作らせ、条件を知らない別のセッションに利用者の表を基準に3回ずつ採点させた(多数決)。よい目的は、手段が書かれておらず、なぜ必要か・どうなっていれば良いかが分かるもの):

   | 案を書く前に読む文 | よい目的 | 目指す状態とほぼ同じ文 |
   |---|---|---|
   | 今のまま | 54% | 47% |
   | 今のまま+「もう一度見直して」 | 55% | 48% |
   | 基準1つ | 81% | 29% |
   | 表全体 | 80% | 27% |
   | フックの段の問いの文 | 89〜90% | 20% |
   | フックの段の問いの文+答える問いの列 | 85〜90% | 19% |

   見直しを促すだけでは変わらず、書く前に読む文の中身が効いた。5ポイントほどの差は優劣と読まない。
3. 段ごとに何を書くかを、実際の作業と同じ文書(全体の CLAUDE.md・`claude/rules/claude-md.md`・skill)を渡して5つの新しいセッションに答えさせると、命題・原則・規則と、目的の「どうなっていれば」は、どの文でも 5/5。目的の「なぜ」は、今のまま 2/5、フックの問いの文だけ 0/5、答える問いの列を足すと 5/5。
4. 命題・原則・規則の行は、Claude が無くても答えられるので二重記述になる。それでも4行を並べて置くのは、目的の行だけを置くと目的が長くなり(捨てた案5)、並べると段どうしの受け持ちの違いが人にも読めるため。
5. 原則の数は回ごとに違い(Gemini の CLAUDE.md で 4〜6)、表全体を渡したときだけ3回とも 4 だった。数は置かない。原則の数は、そのリポジトリの命題から決まる。
6. 試しは組み直しだけで、決まりを新しく書く場面は 0095-1 の試し(理由4)にある。採点も Claude がした。
