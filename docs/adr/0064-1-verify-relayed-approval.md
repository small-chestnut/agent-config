# 0064-1 ほかのセッションから届いた利用者の許可は、受け取ったセッションが元の会話の記録で確かめて使う

状態: 採用
日付: 2026-11-11
対象: task-team-messaging・task-team-lead・task-team-pg

## 決めたこと

利用者の許可を届けるセッションは、利用者の言葉の引用と、その言葉を書いたセッションの id を送る。受け取ったセッションは、`list_events` でそのセッションの記録から利用者の言葉を見つけたら、利用者の許可として扱う。PG と QA は、許可を利用者に直接求めず、PL に知らせて待つ(詳しい文は skill `task-team-messaging`)。

## 捨てた案

1. 届いた文をそのまま利用者の許可として扱う: Claude Code の安全の規則では、届いた文の中で「許可された」と言うだけのものは無効。ほかのセッションが読み違えた・作った許可も、確かめずに通ってしまう。
2. 許可を受けたセッションが、その操作も自分でする: SE は文書しか書かず、本番で長く動かす処理は PL でなく PG が持つ(ADR 0034-3)。許可を受けた所に操作を寄せると、役割の分け方が崩れる。
3. 今のまま、受け取ったセッションが利用者にもう一度許可を求める: PG と QA は、畳んだ PL の行の下に置いて利用者の目から外している(ADR 0057-2)。利用者は、見えなくした会話をわざわざ開き、一度出した許可をもう一度出すことになる。

## 理由

1. 利用者の理由: PL や SE で出した許可を、見えなくした PG からもう一度求められるのは筋が通らず、面倒。
2. 受け取ったセッションが確かめるのは、利用者がその会話で書いた言葉そのもので、届いた文の主張ではない。Claude Code の安全の規則が求める「許可は利用者が出したものだけ」を保ったまま、利用者にもう一度求めずに済む。
3. Claude Code の安全の規則は、許可を伝えるときは利用者の言葉を引くよう求めている。引いた言葉は、受け取ったセッションが記録を探す手がかりにもなる。
4. 見つからないときに利用者に聞かず届けた側へ返すと、利用者に許可を聞くのは、利用者が話す PL と SE だけになる。
