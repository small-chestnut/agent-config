# 0056-5 進行中のチケットを節目ごとに push し、ほかの PC でチームを起こし直して続けられるようにする

状態: 採用
日付: 2026-11-10
対象: task-team-lead・task-team-se・task-team-messaging

## 決めたこと

SE は壁打ちで固まったことをチケットに書き、子セッションはチケットをコミットするたびに作業ブランチを push し、チケットにチームのいる PC を書いて、ほかの PC の PL が、その作業ブランチでチームを起こし直してタスクを続けられるようにする。

## 捨てた案

1. 作業ブランチは、タスクが終わるときにだけ push する(前の形): 進行中のチケットがほかの PC から見えず、タスクを始めた PC でしか続けられない。
2. セッションの会話を、ほかの PC に移す: セッションはその PC にあり、会話をまるごと移す手段が無い。
3. PL が、子セッションの知らせのたびに push する: 壁打ちの間は利用者が SE と直接話すので、PL には知らせが来ない。

## 理由

1. チケットに要点があり、それが GitHub にあれば、新しい SE は、チケットを読んで続きから進められる。会話の記憶は移せないが、決まったことは移せる。
2. チームのいる PC がチケットにあれば、2台で同じタスクを同時に進めていることに気づける。前の PC の PL は、自分の PC でなくなったタスクのチームを閉じられる。
3. リモートに上げた作業ブランチは、その PC が使えなくなっても残る。
