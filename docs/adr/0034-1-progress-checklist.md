# 0034-1 タスクの進み具合は、記録の「進み具合」の節のチェックリストで示し、PL はそれだけを出す

状態: 提案
日付: 2026-11-04
対象: task-team-lead・task-team-se・task-team-pg・task-team-messaging

## 決めたこと

タスクの進み具合は、SE が設計で書く記録の「進み具合」の節(利用者待ちの行と、確かめられる済んだ印を付けた段階のチェックリスト)で示し、段階を済ませた子セッションが印を付け、PL は聞かれたらその節だけを言い換えずに出す。

## 捨てた案

1. PL が記録を読んで、進み具合を文で説明する(今の形): 2026-11-04 の LogiFee で、利用者は何度確かめても理解できず、PL が見込みの数を事実として話す取り違えも起きた。
2. 進み具合を「ステータス: 」の1行だけで示す: チームのどこにいるかしか分からず、ややこしい作業のどこまで済んだかが分からない。
3. PL がタスクごとの進み具合を覚えて更新する: PL の会話が長くなり、要約で細部が落ちる。

## 理由

1. LogiFee で、進み具合をチケット1枚の本文にまとめたら、利用者は見やすくなった。
2. 済んだ印を件数のような確かめられる事実にし、印を付けるときにその場で数えた値に書き換えれば、見込みと事実が混ざらない。
3. 段階を書くのは作業を一番知っている SE で、印を付けるのはその段階を済ませた子セッション。PL は読むだけで、細部を覚えない。
4. ファイルでない記録では、ADR 0024-2 のとおり手順の文書の進み具合の示し方に従い、利用者待ちの行だけを足す。LogiFee の `ops-ticket` は、本文のチェックボックスを進み具合にしている。
