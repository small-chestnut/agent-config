# 0093-1 作るテストと残すテストを、ISTQB CTFL シラバスのリスクベースドテストで決め、リスクレベルの高いプロダクトリスクにだけ置く

状態: 提案
日付: 2026-11-24
対象: task-team-test-list
置き換える: 0091-5

## 決めたこと

作るテストと残すテストは、ISTQB CTFL シラバスのリスクベースドテストで決め、リスクレベルの高いプロダクトリスクにだけ置き、ほかのプロダクトリスクは受容すると、文献の名前と文献の用語だけで書く(詳しい文は skill `task-team-test-list`)。

## 捨てた案

1. ADR 0091-5 のまま、損害の種類を並べた「コードを直しても取り返せない損害」で決める: 文献の害の大きさ(影響)を、Claude が言い換えた線で、参照する文献が無い。
2. 文献の名前だけを書く: gemini の 0094 の 61 行のうち、本『Software Engineering at Google』だけなら 59〜60 行、Khorikov の本だけなら 50〜52 行、ISTQB CTFL だけなら 54〜57 行、Khorikov と ISTQB CTFL なら 56〜58 行が残り、テストが増え続ける。どの文献も、どこまでテストを省くかの線を決めていない。
3. 文献の名前に、価値がコストを大きく上回るものだけという線を足す: 0094 の 61 行のうち 44〜46 行が残る。
4. リスクレベルを5段に分けた一番高い段だけにする: 0094 は 3〜4 行になるが、LogiFee の源泉・負の請求書・立替の税区分の 34 行も 4〜7 行しか残らない。
5. Khorikov の本がユニットテストを書くとするコードのうち、リスクレベルの高いものに限る: LogiFee の権限の 135 行が 15〜26 行に減り、今の行(37〜47 行)より大きく落ちる。文献が2つになり、行も長くなる。
6. 同値分割・境界値分析の行を、文献の名前で書いて残す: ISTQB CTFL を基準にすれば、行が無くても使われる。足すと 0094 の「作る」が 15〜24 行に増える。

## 理由

1. 利用者の理由: 出典の内容を、Claude がよく分からないまま言い換えるから、わけが分からなくなる。明確な出典があるなら、規則に書き直さなくてよい。用語集に、知られている IT の用語を載せないのと同じ。テストサイズ(ADR 0092-1)と同じ形にする。
2. ADR 0091-5 の利用者の理由(テストが作業のたびに増え続けると困る。過剰なテストはパフォーマンスを落とす)は変えない。「ただし」から後ろの線が要るのは、このため。
3. 定石(ISTQB CTFL v4.0.1 5.2、https://www.istqb.org/wp-content/uploads/2024/11/ISTQB_CTFL_Syllabus_v4.0.1.pdf 。2026-11-24 に読んだ): プロダクトリスクのリスクレベルは、可能性と影響で決まる。リスク分析の結果で、テストの範囲・技法・量を決める。リスクへの対応には、テストによる軽減のほかに、受容がある。どのレベルから受容するかは決めていないので、その線だけを行に書く。
4. 1冊にするのは、範囲(リスク)も値の選び方(同値分割・境界値分析)も ISTQB CTFL にあるから。Khorikov の本(1章、https://enterprisecraftsmanship.com/files/Unit-Testing-Chapter-1-Excerpt.pdf 。2026-11-24 に読んだ)は、業務の規則に集め、価値が維持の手間を大きく上回るものだけを残すとするが、どこまで上回るかも、値の選び方も決めていない。
5. 試し(2026-11-24。決まりの文書を読まない新しいセッションに、目指す状態の見出しと基準の行と、テストの名前の一覧を渡し、3回ずつ分けさせた): gemini の 0094 の 61 行は 16・19・15 行、gemini の標本 101 件は 12・7・12 件、LogiFee の会計の 34 行は 17・18・16 行、LogiFee の権限の 135 行は 56・63・57 行。見出しを付けずに分けさせた LogiFee の API の標本 137 件は 53・41・32 件、画面の標本 103 件は 10・13・8 件。同じ一覧で、ADR 0091-5 の行より 0094 は 10〜14 行多く、源泉の逆算・仕訳・売掛金の残・立替の税区分は3回とも残った。存在しない源泉の率と出金への源泉を断る2行は、ほとんどの回で落ちた。
6. 文の読み(2026-11-24): 3つの新しいセッションが、リスクを可能性と影響で見積もり、高いものにだけテストを置き、ほかはテストを作らず、今あれば消す、と読んだ。「高い」の境目は決まらないと答え、「中」は受容と読んだ。
7. small と medium だけでなく large にも当たる。large は、その上に、利用者の主な使い方1本につき1つまで(ADR 0005-1 の2)。
