# 0105-1 全体の CLAUDE.md の安全の原則の節の行も、ほかの節と同じ基準で見直す

状態: 提案
日付: 2026-11-28
対象: 全体
置き換える: 0090-1 の、安全の節をほかの節と同じ基準で消さない所・0076-2 の、安全の原則の節の行を減らす候補から外す所

## 決めたこと

全体の CLAUDE.md の安全の原則の節の行も、ほかの節と同じく、消しても Claude の動きが変わらなければ消す(上限を超えたときの減らし方は、テスト `tests/medium_test_global_claude_md_length.py` の文)。

## 捨てた案

1. 今どおり、安全の節を見直しから外す: 利用者は、どの節も見直しから外さないとした。見直しから外した節には、今の決まりと食い違う行が残る。本番の DB の行は、リポジトリの CLAUDE.md の「利用者が頼んだ本番の作業を断らせる文を置かない」とぶつかったまま残っていた。
2. 安全の節の行だけ、消しても動きが変わらないと言い切れなければ残す、厳しい基準にする: タスク 0105 で9行を照らすと、どちらの基準でも消す行と残す行は同じだった。節ごとに基準を分けると、その分だけ規則が硬くなる。
3. 上限を超えたときに、安全の節の行を skill に移す候補にも入れる: 安全の節の行は、どの作業でも deny とフックに届く前に効いていなければならない(ADR 0076-2 の理由3)。移す候補は今どおり「特定の作業でだけ要る行」で、安全の節の行はそれに当たらない。

## 理由

1. 利用者の理由: ルールの硬直化はよくない。節の重要度と、見直せるかどうかは関わらない(2026-11-28)。
2. ADR 0088-1・0090-1 が安全の節を外した理由は、行が無くて起きる損失は取り返しがつかないことだった。損失の重さが効くのは、消す前にどこまで確かめるかの方で、見直すかどうかではない。消すのは、無くても同じ動きになる行だけなので、消しても動きは変わらない。
3. 止めなければならない操作は、今どおり deny とフックが止める。消した行は git の履歴から戻せる(ADR 0088-1 の理由6)。
