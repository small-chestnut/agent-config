# 0061-2 原則は、安全・人間側の最適化・AI 側の最適化の3つとし、この順に先にする

状態: 提案
日付: 2026-11-11
対象: 全体

## 決めたこと

agent-config の規則の文書の原則は、命題「AI 駆動開発の最適化」の制約条件の安全と、2つの面の人間側の最適化・AI 側の最適化の3つとし、ぶつかったときはこの順に先にする(詳しい文は skill `prompt-structure` と README の命題の行)。

## 捨てた案

1. 文書ごとに、今の原則の名前(開発・確定・軽さなど)を残す: 1語からは命題のどの面を受け持つかが読めず、目的を原則から導けない(ADR 0061-1)。
2. 人間側と AI 側を同じ重みにし、順を文書ごとに決める: ぶつかったときにどちらを先にするかが文書ごとに変わり、同じ判断が文書によって逆になる。
3. AI 側を人間側より先にする: AI の出力が速く多くなっても、人が読み切れなければ開発は速くならない。

## 理由

1. 安全は、最適化の中で破らない制約条件なので、どれだけ良くなる案よりも先にする。
2. README の「なぜ」のとおり、AI 駆動開発の速さを決めるのは、人が AI の出力の概要を早く正確につかめるか。人間側の面がつまる所なので、AI 側より先にする。
3. 原則を命題の面の名前にすれば、どの規則も、命題のどの面に効くかで照らせ、字面でなく命題から取捨できる。
