# 0074-1 自分の文の意味を問われるか食い違いを指摘されたときと、一般の語を辞書と違う意味で説明しかけたときに、自分の文の誤りを疑い、誤りなら認めて言い直す

状態: 採用
日付: 2026-11-13
対象: 全体

## 決めたこと

全体の CLAUDE.md の「書く文には、いまの問題に要ることだけがあり、事実として書くことは確かめてある」の下に、自分の文の意味を問われるか食い違いを指摘されたら説明する前にその文の誤りを疑う行と、一般の語を辞書や同じ答えの中の使い方と違う意味で説明しかけたら前の文の誤用を疑う行と、自分の文の誤りに気づいたら誤りと認めてから言い直す行を置く(詳しい文は全体の CLAUDE.md)。

## 捨てた案

1. 誤った呼び名を直す今の行(「誤った呼び名と、文書に漏れた例えは、用語集に足さず、その文書を直している」)を、会話の返答にも広げる: その行は、リポジトリだけの言葉を用語集の1つの意味で使う目指す状態の下にあり、用語集に何を載せるかの規則。会話で一般の語を誤って使うことは、用語集と関わらない。
2. skill に置く: skill は description に当たったときだけ読まれる。問い返しはどの会話でも起きるので、どの会話でも読まれる全体の CLAUDE.md に置く。
3. 返答のたびに、フックで、使った言葉を辞書と照らさせる: 問い返される前にも止まれるが、毎回の返答が遅くなる。フックを変えるのは利用者に頼まれたときだけ(全体の CLAUDE.md の安全の原則)で、利用者は頼んでいない。
4. 新しい目指す状態を立てる: 全体の CLAUDE.md は 200 行ちょうどで、見出しと空の行の2行がさらに要る。言葉の誤用は、事実として書くことを確かめずに書いた誤りで、既にある目指す状態に入る。
5. 原則2 の目的「利用者が、未知の概念を取りこぼさずに理解できるようにする」の行を直し、問い返しを「知らないから聞いている」と読ませないようにする: その目的の下の行に、問い返しを知らないからと読ませる文は無い(2026-11-13 に読んで確かめた)。直すべき行が無いので、新しい行で「説明する前に誤りを疑う」と順を決める。
6. 問い返されたときだけにする: 利用者の理想は、問い返される前に Claude 自身で立ち止まること。一般の語を辞書と違う意味で説明しかけた時点は、問い返される前でも Claude が書きながら見分けられる。

## 理由

1. LogiFee で、利用者は「入出金のデータに『入出金が無い』という指摘が書かれているので、意味が分からなかった」と、文の食い違いを指摘した。Claude は前の文を見直さず、「『入出金』は、その行と逆向きのお金の動き(返金や戻り)のことです」と意味の説明から始めた。この意味は辞書にも LogiFee の用語集にも無い。LogiFee の用語集では、「入出金」は画面の名前で、通帳・口座のお金の出入りを指す(LogiFee の `docs/用語集.md` の「入出金の権限」の行。2026-11-13 に読んで確かめた)。
2. 同じ答えの表で、Claude は「入出金」の列に「入金」と書き、普通の意味で使っていた。説明と同じ答えの中の使い方の食い違いは、Claude がその答えを書く間に見分けられた。
3. 意味の問いと食い違いの指摘は、外から見える、決まった時点なので、「説明する前に誤りを疑う」という手順を結び付けられる。
4. 利用者は、ミスに嘘を重ねられると、Claude の説明を信じて判断できなくなる。説明を信じられなければ、利用者は Claude の出力を疑って見張ることになり、README の「なぜ」にある、利用者が AI の出力をつかむときの認知負荷が増える。
