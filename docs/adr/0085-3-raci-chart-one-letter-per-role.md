# 0085-3 task-team の作業ごとの役割の表を、利用者の列を足し、1つの行で1つの役割に1文字だけを置く RACI チャートにする

状態: 採用
日付: 2026-11-14
対象: 全体
置き換える: 0085-1

## 決めたこと

skill `task-team` の、作業ごとに受け持つ役割の表を、利用者・PL・SE・PG・QA の列を持つ RACI チャートにし、どの行にも A を1つだけ置き、1つの行で1つの役割に付ける文字を1つだけにする(文字の意味は skill `task-team`)。

## 捨てた案

1. 今の ◯/✕ の表に、利用者の列だけを足す: 作業をする役割と、承認する役割・意見を求められる役割・知らされる役割が見分けられず、ADR 0083-1 の発端になった、決める役割の取り違えが表に出ない。
2. 利用者が見せた、ほかの AI が作った表(利用者を全部の工程の A に置く表)を使う: 利用者に聞くのは目的と「なぜ」だけにする ADR 0063-1 と逆で、利用者の確かめる量が増える。タスク分解・テスト・コードレビューを受け持つ役割も、今のチームと違う。
3. 1つの行に A を2つ以上置いてよいことにする: どちらが承認するかが表から分からなくなり、取り違えが残る。
4. 作業をする役割が承認もする行に「A/R」と書く(0085-1 の形): 作業をした役割が自分の作業を承認することになる。利用者は、兼務のような曖昧な分担は AI の逃げ道になると言った。出典も、1人に2つ以上の文字を割り当てると、役割の分担をはっきりさせるという RACI チャートの価値が減ると書いている。
5. A を「作業の結果を最後に決める役割」と書く(0085-1 の形): 出典の定義は、R に作業を任せ、R の作業を承認し、成果物とタスクが正しく終わることに最終的に責任を負う役割で、違っていた。
6. 作業の中身を読まない役割を A に置く(タスクの分け方の A を PL にする): 読まずに通すだけになる(ADR 0007-1 の捨てた案1 と同じ)。

## 理由

1. 利用者の「なぜ」は、AI のセッションが受け持ちを取り違えず、各セッションが自分の役割を分かっているようにすること。
2. RACI チャートは責任分担表(responsibility assignment matrix)の定石の形で、実行責任者(R)・説明責任者(A)・協業先(C)・報告先(I)を分け、1つの作業の A は1人だけにする(https://en.wikipedia.org/wiki/Responsibility_assignment_matrix 。2026-11-14 に読んだ。日本語版の定義は利用者が示した)。
3. ADR 0083-1 の発端は、SE が手段の決めを PL に求め、PL が答えたこと。表の PL は、タスクの中の作業では、知らされる役割(I)だけになる。
4. skill を読むのは AI のセッションなので、利用者だけがして AI のセッションが関わらない作業は、書いても振る舞いを変えない。利用者は、利用者だけがする作業を skill に書かないと決めた。
