# 0093-1 テストが適正な量になることを目指し、作るテストと残すテストは、ISTQB CTFL シラバスのリスクベースドテストで決める

状態: 提案
日付: 2026-11-24
対象: 全体
置き換える: 0091-5

## 決めたこと

目指す状態を、テストが適正な量になっていることとし、作るテストと残すテストは、ISTQB CTFL シラバスのリスクベースドテストで決める(詳しい文は全体の CLAUDE.md)。

## 捨てた案

1. ADR 0091-5 のまま、損害の種類を並べた「コードを直しても取り返せない損害」で決める: Claude が引いた線で、参照する文献が無い。少なすぎる(理由5の表)。
2. 基準を書かない: 多すぎる(理由5の表)。
3. リスクレベルの高いプロダクトリスクにだけ置き、ほかは受容するという線を足す: 線は文献に無く、Claude が引いた線になる。数を減らすことが目的になる。
4. ほかの文献にする: 本『Software Engineering at Google』と Khorikov の本は、読んだ範囲では、テストの量をリスクに合わせる決め方を書いていない。0094 のテスト一覧 61 行を分けさせると、59〜60 行・50〜52 行が残り、ほとんど減らない。
5. 同値分割・境界値分析の行も、文献の名前で書く: 0094 の 61 行を分けさせると、40〜48 行が残り、足さないとき(SE と QA の6回で 31〜41 行)より多い。
6. 目指す状態を、少なすぎず多すぎず、無駄のない適正な量と書く: 0094 の要件から 21〜27 件で、適正な量とだけ書いたときの 18〜19 件より、回ごとの差が大きい。「適正な量」に同じ意味が入っている。

## 理由

1. 利用者の理由: どのリポジトリのテストも、少なすぎず多すぎず、無駄のない適正な量のケースになること。減らすことは目的でない。手段は、Claude に任せる。
2. 利用者の理由: 出典の内容を、Claude がよく分からないまま言い換えるから、わけが分からなくなる。明確な出典があるなら、規則に書き直さなくてよい。テストサイズ(ADR 0092-1)と同じ形にする。
3. ADR 0091-5 の利用者の理由(テストが作業のたびに増え続けると困る。過剰なテストはパフォーマンスを落とす)は、撤回していない。多すぎる側の理由として続く。
4. 定石(ISTQB CTFL v4.0.1 5.2、https://www.istqb.org/wp-content/uploads/2024/11/ISTQB_CTFL_Syllabus_v4.0.1.pdf 。2026-11-24 に読んだ): プロダクトリスクのリスクレベルは、可能性と影響で決まる。リスク分析の結果で、テストの範囲・技法・量を決める。リスクへの対応には、テストによる軽減のほかに、受容がある。テストの量をリスクに合わせる文献なので、「適正な量」の基準になる。
5. 試し(2026-11-24。決まりの文書を読まない新しいセッション(`claude-opus-5-5`)に、決まりと要件だけを渡し、残すテストの一覧を3回書かせた。件数):

   | 渡した決まり | gemini 0094 の要件 | LogiFee の源泉の要件 |
   |---|---|---|
   | なし | 47・39・37 | 27・23・16 |
   | 前の skill の全部の行(ADR 0091-5) | 5・6・6 | 8・8・8 |
   | 前の skill の、見出しと基準の行をこの決定に替えたもの | 19・18・19 | 11・7・11 |
   | 前の全体の CLAUDE.md(テストの量の決まりが無い) | 49・57・45 | 17・23・24 |
   | 全体の CLAUDE.md に、目指す状態の見出し・この決定の行・large の行を足したもの | 33・31・29 | 11・9・10 |

   件数は回ごとに割れる(全体の CLAUDE.md に、コードを変えるときに消す行も足した文では、SE と QA の6回で、0094 は 18〜29 件、源泉は 7〜11 件)。ADR 0091-5 の行の1回目の一覧は、0094 の着替え・脱衣・情景との組み合わせを確かめるテストが1件も無い。全体の CLAUDE.md に足したものは、どの回も、0094 の絵に入るタグの並び・着替え・表を壊さないことと、源泉の逆算・仕訳・合わない行を候補のまま残すことを確かめ、断る場合を1件ずつでなくまとめて確かめた。
6. 文の読み(2026-11-24): 3つの新しいセッションが、基準の行を、リスクを可能性と影響で見積もり、リスクの高い所のテストを作って残し、リスクの低い所のテストは作らず、今あるものは消す、と読んだ。
7. small と medium だけでなく large にも当たる。large は、その上に、利用者の主な使い方1本につき1つまで(ADR 0005-1 の2)。
