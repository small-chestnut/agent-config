# 0012-1 ソースを、業務のまとまり(モジュール)ごとのフォルダに置く(モジュラーモノリス)

状態: 採用
日付: 2026-10-31
対象: 全体

## 決めたこと

新しく作るファイルは、1つのアプリの中で、業務のまとまり(モジュール)ごとのフォルダに置く。

## 捨てた案

1. 技術の層ごとのフォルダ(`models/`・`views/`・`controllers/`)に置く。
2. 業務のまとまりごとに、別のサービスに分ける(マイクロサービス)。
3. 要求1つごとのフォルダ(vertical slice)だけで分け、業務のまとまりのフォルダを置かない。

## 理由

1. 利用者の理由:「AI駆動開発で大事なのは、コードのスケールと同時に、あなたが見るコンテキストまでスケールしないように、極力抑えることが命題で、そのためにモジュラーモノリスや、ADRの配置があると思っているのだけど、違う？」。モジュールのフォルダなら、1つの作業で読む量はそのモジュールの大きさで決まり、コード全体が増えても増えない。
2. 層ごとのフォルダでは、1つの機能を変える作業で、層の数だけフォルダを開き、それぞれのフォルダはコード全体とともに大きくなる。
3. マイクロサービスでは、1つの機能がリポジトリとネットワークをまたぎ、読む範囲も、動かして確かめる手間も増える。
4. 要求ごとのフォルダだけでは、いくつもの要求が使う業務の規則とデータの置き場が決まらない。モジュールの中を要求ごとに分けることは妨げない。
5. 機能ごとにまとめて変更を1か所に収める形は、人の開発の定石に沿う(vertical slice の「slice の間の結合を小さく、中の結合を大きく」https://www.jimmybogard.com/vertical-slice-architecture/ 、Shopify のモジュラーモノリス https://shopify.engineering/shopify-monolith )。AI の読む量が減るという理由は、実践者のブログで言われているだけで比べた調査は無く、agent-config が組み立てた理由。
