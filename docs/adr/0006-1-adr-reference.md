# 0006-1 ADR で決めた所にその番号を付け、SE は書き換える所の番号の ADR だけを読む

状態: 提案
日付: 2026-10-31
対象: 全体

## 決めたこと

ADR で決めた所(プロンプトの行・コードの1か所・どちらも無ければモジュールの CLAUDE.md の行)に「ADR <番号>」を付け、SE は設計で書き換える所に付いた番号の ADR と、それが置き換えた古い ADR だけを読む。

## 捨てた案

1. 設計の最初に、`docs/adr/` の「対象: 」の行を、直すモジュールの名前か「全体」で検索し、採用中の ADR を全部読む(0004 で入れたやり方)。
2. ADR の一覧(索引)のファイルを置き、SE が設計のたびにそれを読む。
3. ADR を、モジュールごとのフォルダに分けて置く。

## 理由

1. 利用者の理由:「タスクがスケールしたときに、1番目のタスクと3000番目のタスクで、一次関数的に、あなたが見るADRが増えてしまうと、私が破産する」。「全体」の ADR はどのタスクの検索にも当たるので、案1では読む量がタスクの数に比例して増える。
2. 案2の索引も ADR の数に比例して長くなる。案3でも「全体」の ADR は毎回読む。
3. 番号は決めた所そのものに付くので、読む ADR の数は書き換える所の数で決まり、ADR の総数によらない。
