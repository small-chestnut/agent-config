# 0022-1 PL がマージするタスクの記録は、マージの前に作業ブランチで消す

状態: 提案
日付: 2026-11-01
対象: task-team-lead

## 決めたこと

PL が自分でマージするタスクの記録(と記録のフォルダ)は、push とマージの前に作業ブランチで消し、`small-chestnut` が所有しないリポジトリと、記録だけのリポジトリでは消さない。

## 捨てた案

1. 終わった記録を残す: リポジトリ全体の検索に、古くなった設計の文が混ざる。
2. 次のタスクを始めるときに、その作業ブランチで消す: 利用者がマージの前を選んだ。
3. 記録だけのリポジトリでも消す: 利用者が、そこでは残すと決めた。
4. `small-chestnut` が所有しないリポジトリでも消す: PR が squash でマージされると、記録を足したコミットが main の履歴に残らず、タスクの番号がまた振られる。

## 理由

1. 残す価値のあるものは、マージの時点でほかの置き場(ADR・仕様・各モジュールの CLAUDE.md・コミットメッセージ)にあり、終わった記録は SE・PG・QA の受け渡しを終えて読まれない。
2. 2026-11-01 の `docs/tasks` は22件・3,439行・約29万字で、リポジトリ全体を「用語集」で検索すると当たる24ファイルのうち20ファイルが終わった記録だった。
3. 消した記録は git の履歴から取り出せる。タスクの番号は main の履歴にある記録の名前から振るので、消しても重ならない。
