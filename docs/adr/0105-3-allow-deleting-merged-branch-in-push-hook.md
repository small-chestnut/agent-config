# 0105-3 リモートのブランチを消す push は、既定のブランチにマージ済みのときだけフックが通す

状態: 採用
日付: 2026-11-28
対象: block_history_erasing_push.py

## 決めたこと

フック `block_history_erasing_push.py` は、リモートのブランチを消す push のうち、消すブランチのリモートの今の先端が、リモートの既定のブランチの履歴に含まれるものだけを通し、ほかは今どおり止める(詳しい文は仕様 `docs/specs/block_history_erasing_push.py.md`)。

## 捨てた案

1. 消す push を、利用者の確認に回す: PL がタスクを終えるたびに、利用者が確認を求められる。マージ済みかどうかは機械で確かめられるのに、その判断を利用者に負わせることになる。
2. 消す push を、どれも通す: マージしていないブランチを消すと、そのコミットはどこにも残らず、戻せない。
3. permissions の deny と allow の書き分けで通す: deny と allow はコマンドの字の形しか見ないので、マージ済みかどうかを確かめられない。
4. 手元のリモート追跡ブランチ(`refs/remotes/<リモート>/<ブランチ>`)の先端で確かめる: ほかの PC が後から push したコミットを fetch していなければ、手元ではマージ済みに見えても、リモートの先端はマージされていない。

## 理由

1. 既定のブランチの履歴に含まれるブランチは、消してもコミットが残るので、全体の CLAUDE.md の安全の原則の目的(消したものは、いつでも元に戻せる)を満たす。フックが止めたいのは、戻せない消し方だけ。
2. リモートの今の先端は `git ls-remote` で読む。その先端のコミットを手元に持っていなければ、マージ済みとは言えないので止まる。確かめられなかったとき(git が失敗した・時間切れ)も止めて、戻せない消し方を通さない。
3. 既定のブランチそのものは、自分の履歴に含まれるので、名指しで止める。
