# 0094-1 large のテストの数に上限を置かず、ほかのテストと同じくリスクベースドテストで決める

状態: 採用
日付: 2026-11-24
対象: 全体
置き換える: 0005-1 の2 の、大を利用者の主な使い方1本につき1つまでとする所

## 決めたこと

全体の CLAUDE.md から「large のテストは、利用者の主な使い方1本につき1つまで。」の行を消し、large のテストの数も、ADR 0093-1 の ISTQB CTFL シラバスのリスクベースドテストで決める。

## 捨てた案

1. 行を残す(今のやり方): 「利用者の主な使い方1本」が何を指すかが決まらず、文献にも無い(理由1・2)。
2. 「主な使い方」と「1本」の意味を書き足す: 文献に無い線を、Claude がさらに書き足すことになる(理由2)。
3. 文献の上限か割合を探して置く: 本『Software Engineering at Google』は、テストサイズの割合の目安を挙げるが、ADR 0005-1 が、どの規則を確かめたかを問わない数字として捨てた(0005-1 の捨てた案1・理由2)。

## 理由

1. 利用者の理由: 「利用者の主な使い方1本」では、何を指すかが決まらない。
2. 利用者の理由: この上限は文献に無く、Claude が作った基準。
3. Claude が調べたこと: ADR 0005-1 を足したコミット(d459ffa)は、利用者が採用した PL の案のとおりに書いたとし、上限の出典は書いていない。本『Software Engineering at Google』11章と14章では、使い方ごとの件数の上限は見つからなかった(2026-11-24。一部は要約での確認。ほかの文献は調べていない)。出典のある決まりは、文献の名前で書く(ADR 0093-1 の理由2)。
4. ADR 0092-1 で large になった速さを測るテストは、「使い方」に当たらず、この行では数が決まらない。
5. 試し(2026-11-24。ADR 0093-1 の理由5と同じ道具で、決まりの文書を読まない新しいセッション(`claude-opus-5-5`)に、今の全体の CLAUDE.md の全文か、そこからこの行だけを消した文と、要件を渡し、残すテストの一覧を3回ずつ書かせた。件数(うち large)):

   | 要件 | 行あり | 行なし |
   |---|---|---|
   | gemini 0094 | 32(0)・26(0)・24(0) | 33(0)・34(0)・31(0) |
   | LogiFee の源泉 | 15(1)・9(0)・12(1) | 12(1)・11(1)・10(0) |
   | LogiFee の会計管理の画面の速さ | 5(1)・5(1)・9(2) | 9(3)・7(2)・6(4) |

   gemini と源泉の要件では、large は行が無くても増えなかった。gemini の全部の件数は増えた。速さの要件の large は、1・1・2 から 3・2・4 に増え、行なしの3回目には、描画の回数を確かめる large もあった。速さの要件では、行ありは、3つの速さを1つの large にまとめ(3回目は2つと1つに)、行なしは、1回目と3回目は速さごとに1つの large に分け、2回目は読み込み2つをまとめた。要件は SE が選んだ1つで、増える幅は言えない。
6. ADR 0009-3 の決めたこと(CI が無ければ、変えた使い方を確かめる large を実行する)は、この上限が無くても成り立つ。変えていない使い方は前のマージで確かめてある(0009-3 の理由3の後ろ半分)。
7. ADR 0005-1 の2のほかの所は変えない。
