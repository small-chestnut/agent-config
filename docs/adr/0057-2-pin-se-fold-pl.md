# 0057-2 PL は SE をピン留めし、PG と QA は畳んだ PL の下に置く

状態: 採用
日付: 2026-11-10
対象: task-team-lead
置き換える: 0057-1

## 決めたこと

PL は、起こした SE をピン留めしてサイドバーの上に出し、タスクを終えるときにピン留めを外してから閉じる。PG と QA は、利用者が畳んだ PL の行の下に置く。

## 捨てた案

1. PG と QA を、表示を切ったサイドバーの区切りへ移す(0057-1): PL が起こしたセッションは PL の下に入れ子になり、子だけを別の区切りへ移せなかった。
2. PG と QA を `detach_session` で PL から外してから移す: 外すと元に戻せず、PL に子のターンの終わりが届かなくなる。道具の説明では、ほかのセッションと worktree を分け合う子には使えない。
3. PG と QA を、SE の中で動くサブエージェントにする: 利用者が開いて止めたり口を挟んだりできなくなり、PG が利用者に操作を頼むタスクで、利用者が PG と話せない。
4. 利用者が SE を手でピン留めする: タスクを始めるたびに、利用者の手が要る。

## 理由

1. 利用者がタスクで話すのは PL と SE だけで、PG と QA は PL の会話のリンクから開ければよい、と利用者が決めた。
2. PL の行を畳むと、その下の子は、利用者の画面で、子1つの行と「他に N 件のネストされたセッション」の行にまとまった。
3. ピン留めは `set_pinned` で AI からできるので、利用者がするのは PL の行を畳むことだけになる。
4. `archive_session` はピン留めしたセッションを閉じないので、閉じる前にピン留めを外す手順が要る。
5. 利用者が目にする行を、話す相手だけに絞ると、利用者が AI の出力をつかむときの認知負荷が下がる。
