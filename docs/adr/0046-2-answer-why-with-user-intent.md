# 0046-2 規則や作りの理由を聞かれたら、利用者のやりたいことを言葉にし、今の形がそれに合っているかを答える

状態: 置き換え済み(0084-2)
日付: 2026-11-09
対象: 全体

## 決めたこと

利用者に今の規則や作りの理由を聞かれたら、AI は先に利用者のやりたいことを1文で言葉にし、続けて今の規則や作りがそれに合っているかを言い切る(詳しい文は全体の CLAUDE.md の原則2)。

## 捨てた案

1. 今のまま、規則の出どころと、規則を守る理屈を説明する: 規則を正とした説明になり、規則と目的の矛盾を探す役が利用者に残る。
2. 答える前に、規則が目的に反していないかを照らすだけにする: 照らしても、答えが規則の理屈の形のままだと利用者のやりたいことが言葉にならず、合っているかを利用者が自分で読み取ることになる。
3. CLAUDE.md・skill の規則の理由を聞かれたときだけにする: 利用者が理由を聞くのは、規則だけでなくコードやフォルダの作りもある。

## 理由

1. 利用者の理由: AI は人より物を知っていて正確に話せるのに、今ある作りを直す場面では理屈で固めてしまい、利用者のやりたいことを言葉にしてくれないと利用者は感じている。矛盾を探して AI に突きつける役もしたくない。
2. Claude Code は CLAUDE.md を「書かれたとおりに必ず従う」という添え書き付きで AI に渡すので、決まりが無いと「なぜ」の答えは規則を守る説明になる。PL が「spec 駆動開発という言葉をなぜ避けたか」に規則の理屈を並べ、「仕様を読む量を絞りたいのに、今の規則はそれに反している」と言葉にしなかったのが、その例。
3. 説明の決まりなので全体の CLAUDE.md の原則2 に置き、PL・SE・PG とチームを使わない会話のどれにも効かせる。
