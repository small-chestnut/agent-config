# 0076-1 全体の CLAUDE.md の量を、行の数でなく字の数で測り、8,000 字を上限にして、中のテストで止める

状態: 提案
日付: 2026-11-13
対象: 全体

## 決めたこと

全体の CLAUDE.md(`claude/CLAUDE.md`)の長さの上限を「200 行以内」から「8,000 字以内(改行も1字)」に替え、安全の原則の節の目安も「10行前後」から「800 字前後」に替え、全体の字数を中のテスト `tests/medium_test_global_claude_md_length.py` で数えて止める(詳しい文は `.claude/rules/global-claude-md.md`)。

## 捨てた案

1. 行の数(200 行)のままにする: Claude Code のドキュメントの目安は行の数だが、2行を1行にまとめるだけで、読まれる量を減らさずに上限に収まる。0074 では、同じ ADR の付いた2行ずつを1行にまとめた組を3つ作り、行の数だけを合わせた。
2. トークンの数で測る: 読まれる量を一番正しく測れるが、数えるには Anthropic の API とその鍵が要る。テストが localhost の外に触って大になり、マージの前に流す小と中に入らない。鍵をリポジトリに置くこともできない。
3. 上限を今の量ちょうど(7,615 字)にする: 言い方を直すだけの変更でも、毎回ほかの行を消すことになる。8,000 字は今の量より 5% ほど多いだけで、上限を超えたときの減らし方(ADR 0076-2)がすぐ効く余地のまま。
4. 字数をフック(`check_rule_length.py`)で、保存のたびに数える: 保存の時点で気づけるが、フックを変えるのは利用者に頼まれたときだけ(全体の CLAUDE.md の安全の原則)で、利用者は頼んでいない。このリポジトリは、マージの前に小と中のテストを全部流すので、テストでも上限を超えたままマージされない。
5. 目安を書くだけで、数えない: 今の「200 行以内」は誰も数えておらず、0074 の SE が手で数えた。「短く」と書くだけでは通る長い行をフックで止めたのと同じく、数えて止める。

## 理由

1. 守りたいのは、毎回読まれるコンテキストの量で、1項目の効きが薄まらないこと。Claude Code のドキュメントも、長いファイルは「コンテキストを多く使い、守られにくくなる」を理由に挙げている(https://code.claude.com/docs/en/memory.md の「Write effective instructions」節)。行の数は、その量の代わりにしかならない。
2. 字の数は、行をまとめても減らず、手元のテストで数えられる。返答の長さも、既に行の数でなく字の数で区切っている。
3. 8,000 字は、利用者がこれまで「200 行以内」で受け入れてきた量(2026-11-13 に 200 行・7,615 字と数えた)を元にした区切りのよい数。
4. 安全の原則の節も、行の数で目安を書くと同じずれが起きる。今の節は 769 字(2026-11-13 に数えた)。
