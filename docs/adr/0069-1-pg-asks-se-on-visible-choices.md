# 0069-1 PG は、設計が決めていない所で利用者に見える動きを左右する所を判断せず、「設計への問い」にして SE に聞く

状態: 採用
日付: 2026-11-12
対象: task-team-pg・task-team-se

## 決めたこと

PG は、設計が決めていない所で利用者に見える動きを左右する所では手を止めて「設計への問い」にし、設計の節には「設計への問い」のほかを書き足さない。SE は問いに答えて設計の節を直し、直した所を問いの下に書く(詳しい文は skill `task-team-pg`・`task-team-se`)。

## 捨てた案

1. 今のまま、PG が判断して、設計の節を同じコミットで直す: 利用者が合意した中身から外れた判断が、聞かれずに入る。設計の節まで書き換わるので、QA が照らす相手もずれる。
2. PG が判断した所を「実装」の節に書き、QA が実装レビューで見る: 判断が入ったあとで止めることになり、実装のやり直しが増える。利用者に見える動きを決めるのは、利用者の目的と「なぜ」を持ち、分からないことを利用者に聞く SE の仕事(skill `task-team-se`)。
3. 設計が決めていない所は、利用者に見えない所(内部の名前や置き方)も含め、みな SE に聞く: 往復が増える。利用者が怖れているのは、合意した中身からのずれで、利用者に見えない所はそれに当たらない。

## 理由

1. 利用者は、SE のやり方に納得した後で、PG が解釈のずれから誤った実装をし、それが見つからずに通るのを怖れている(利用者の言葉。タスクの文)。
2. 今の skill `task-team-pg` は、見出し「設計を変える判断は、PG がしていない」の下で、設計どおりに作れない所では止めると決めている。一方で別の見出しで、設計が決めていない所を判断して利用者に見える動きが変わったら設計の節を直す、とも決めていて、利用者に見える判断を PG が聞かずにする入口が開いている。
3. 問いを SE に返す道(「設計への問い」)は、設計どおりに作れない所と、テスト一覧に無いテスト(ADR 0005-1)で既にある。新しい道を作らずに、当てる所を広げるだけで済む。
4. SE が直した所を問いの下に書けば、合意した後に変わった設計の節のうち、問いに答えた直しを、QA が見分けられる(ADR 0069-2)。
