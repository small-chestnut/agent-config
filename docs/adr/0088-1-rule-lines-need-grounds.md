# 0088-1 規則の行を置く根拠を3つに限り、根拠を言えない行を消す

状態: 採用
日付: 2026-11-17
対象: 全体
置き換える: 0035-1 の、済んだ印を確かめて言い切れる事実にする所・0035-4 の、済んだ印を利用者が見る画面に出るものにする所

## 決めたこと

規則の行を置く根拠を、AI が知りえない事実・ほかの仕組み(セッション・スクリプト・フック・ページ)が読む形・AI の答えと違う利用者の決定の3つに限り、どれも言えない行を全体の CLAUDE.md と skill から消す(詳しい文は skill `prompt-structure`)。

## 捨てた案

1. 完了条件の規則だけを消す: 害が出たのは完了条件の規則だが、目指す状態から導ける行と、形・数・順だけを決めた行は、ほかの文書にもある。利用者は、規則全体を見直すことを選んだ。
2. 規則を字面どおりに当てはめないよう求める規則を足す: 足す行そのものが、守らせる行を増やす。規則を目的に照らさせる規則は、置いても働かなかった(ADR 0084-2)。
3. 意味の無い行だけを消す: どの行にも何かの意味はあるので、ほとんどの行が残る(利用者の理由)。タスク 0084 でも、SE は利用者が消したい規則を「残す」と見立てた(ADR 0084-2 の理由2)。
4. 消す前と後の AI の振る舞いを、場面を再現するテストで比べてから消す: 害は、長い実作業の中で規則を字面どおりに当てはめて出た。短い場面では元の規則でも再現する見込みが薄く、テストが通っても消してよい根拠にならない。
5. 文書ごとにタスクを分けて、少しずつ消す: 消す行は、文書をまたいでも互いに依存しない。分けると、タスクごとにチームと利用者のターンが要り、利用者が確かめる単位にもならない。
6. 安全の原則の節の行も見直す: 安全は命題の制約条件で、行が無くて起きる損失は取り返しがつかない。この節は、deny とフックに届く前に安全な行動を選ばせる文だけを置くと決めてある(リポジトリの CLAUDE.md)。
7. 目指す状態の見出しも、同じ基準で消す: 命題・原則・目的・目指す状態は、利用者が合意した段(skill `prompt-structure`)。消す見出しは、害の元になった「画面のあるシステムでは、完了条件が利用者の画面に出るもの」1つだけにする。

## 理由

1. 利用者の理由: モデルの動きを指示で細かく固めると、逆効果になる。実害が出ている以上、「どの行も無意味ではないから残す」としてはいけない。それは、ほとんどどの行にも言えてしまう。「完了条件は、画面に出る件数で書く」と書かなくても、モデルの精度を信頼してよい。決まりに例外をいちいち書き足すのは、融通が利かない。
2. 出た害: LogiFee の取り込みのタスクで、SE(Opus 5.5)が、先方が誤りと答えた行を、直しても画面の未消込の数が減らないという理由で、直す予定から外した。完了条件を件数や画面に出るものにする規則(ADR 0035-1・0035-4)を、終わったかを確かめる物差しでなく、やることの中身として当てはめた。
3. Anthropic の手引きは、新しいモデルは指示を字面どおりに取ること、細かな手順より一般的な指示を勧めること、理由を添えればモデルが自分で広げて当てはめることを書いている(https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/claude-prompting-best-practices 。2026-11-17 に読んだ)。
4. 同時に守らせる指示が増えるほど、守れる割合は落ちる。最良のモデルでも、500 個で 68%(IFScale, https://arxiv.org/abs/2507.11538)。見直す前の規則の行は、全体の CLAUDE.md と skill を合わせて 638 行。
5. 3つの根拠は、どれも、目指す状態を読んだ AI が自分では導けないもの。事実と、ほかの仕組みが読む形は、その場からは分からない。AI の答えと違う利用者の決定は、書かなければ AI の答えの方になる。この3つに当たらない行は、目指す状態から AI が導けるので、消しても状態は保たれる。
6. 消した行は git の履歴にある。消した後に AI が状態を守れなかった所は、「規則は、状態だけでは AI が守れなかった所にだけある」(skill `prompt-structure`)のとおり、その行を足し直せる。残した害は続くが、消しすぎは1回の誤りで気づいて戻せる。
7. ADR 0035-4 のうち、済みにする前に利用者が見るのと同じ画面を開いて確かめること(skill `task-team`)は、形を決める行でなく、確かめる行動なので残す。ADR 0035-1 のうち、進捗の節の形と、子セッションが印を付けることも残す。
