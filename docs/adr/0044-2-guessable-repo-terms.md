# 0044-2 IT の用語が無い概念にリポジトリだけの言葉を作るときは、初めて見た人が言葉から意味を推測できる名前にし、名前に入らない条件は仕様に書く

状態: 採用
日付: 2026-11-07
対象: 全体

## 決めたこと

IT の用語が無い概念にリポジトリだけの言葉を作るときは、初めて見た人が言葉そのものから意味を推測できる名前にし、名前に入らない条件は仕様に書く。

## 捨てた案

1. 短い呼び名を作り、意味は用語集に任せる(今の形): 利用者は初めて見た言葉を用語集で引かず、言葉から推測する。「置き場の手順の文書」は、言葉から意味が推測できなかった。
2. 条件を全部名前に入れる(例: `docs/` を除いた作業ツリーのハッシュ値): 名前が長くなり、かえって読めない。

## 理由

1. リポジトリだけの仕様には言葉が要るが、利用者はその言葉を初めて見たとき、言葉そのものから意味を推測するしかない。
2. 名前で何の話かが分かれば、細かい条件は仕様の1行で足りる。
