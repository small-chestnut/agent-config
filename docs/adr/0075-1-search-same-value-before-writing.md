# 0075-1 事実を表す値を書く前に、同じ値を全体から grep し、あればそれを使う

状態: 提案
日付: 2026-11-13
対象: 全体

## 決めたこと

全体の CLAUDE.md で、新しい仕組みを作る前に全体を探す規則(ADR 0068-1)の対象に、事実を表す値(期間・率・境目の値・接続先など)を足す。値を書く前に同じ値を全体から grep し、あれば新しく書かずにそれを使う(DRY)(詳しい文は全体の CLAUDE.md)。

## 捨てた案

1. 「1つの事実を表す値は、名前を付けて1か所に置く(DRY)」を、規則として新しく足す: LogiFee の七海の取り込みスクリプトでは、どのセッションも自分のファイルの中では値に名前を付けていて、DRY を知らずに破ったのではない。重なりは、別のセッションが書いたファイルをまたいだときにだけあった。守れなかったのは「ほかのファイルの同じ値を探す」所なので、規則はそこにだけ置く(skill `prompt-structure` の「規則は、状態だけでは AI が守れなかった所にだけある」)。
2. 「実行ごとに変わる値は、コードの外(引数・環境変数・設定ファイル)から渡す(Twelve-Factor App の Config)」を足す: 利用者の「なぜ」は、事実が変わったときに直す所が1か所で済むこと。値が1か所にまとまれば、それが定数でも引数でも「なぜ」は満たせる。どちらにするかは、全体の CLAUDE.md の「進め方・仕組みは、決める前に定石を調べ、あれば沿っている」で決まる。全体の CLAUDE.md は今200行で、上限(`.claude/rules/global-claude-md.md` の「全体は 200 行以内」)に達していて、守れていない所の無い行を足す余地も無い。
3. 「今ない使い道に向けた設定や引数は作らない(YAGNI)」を足す: 起きたことは汎用化のしすぎでなく足りなさで、AI が YAGNI を守れなかった例は無い。
4. 値の元を文書(skill・チケット)に置かず、コードか設定ファイルを正にして、文書はその場所を指す: 文書に書かれた値は、値そのものの grep でコードの中の同じ値にも当たるので、決めたことの規則で、文書から写す前に既にあるコードの値にたどり着く。文書は利用者の決定と「なぜ」の記録でもあり、値を消すと記録が読めなくなる。
5. ADR 0068-1 を置き換える新しい ADR にする: 0068-1 の決めたこと(新しい仕組みの前に探す)は変えず、探す対象を足すだけなので、別の決定として並べる。

## 理由

1. 根本原因は、同じ値の重なりがセッションをまたいで生まれ、どのセッションにも見えなかったこと。LogiFee の `scripts/lib/nnm_import2551/` で日付を持つ8ファイルは、7つの管理番号の別々のセッションが 2026-10-30〜11-12 に足した(git の履歴で確かめた・2026-11-13)。全体の CLAUDE.md は、読むものをモジュールと import でたどったファイルに絞り、全体の検索を、変更の影響・外の原因と呼び出し元・新しい仕組みの前に絞っている。値を書く前に探す規則があれば、2つ目のセッションは1つ目の値にたどり着く。
2. 値そのもので grep すれば、名前が違っても当たる。LogiFee では、帳簿の開始日に `LEDGER_START`・`FISCAL_START`・`MARKS_FROM` など5つの名前があり、名前の grep では1つから残りにたどり着かない。`2026-04-01` の grep なら、`datetime.date(2026, 4, 1)` の1か所を除いて当たる。
3. DRY は、コードの見た目でなく知識の重なりを問う定石で、同じ事実の値は2か所目でまとめる(The Pragmatic Programmer の DRY。https://www.artima.com/articles/orthogonality-and-the-dry-principle)。利用者は、汎用化の範囲を定石に沿わせると決めた。
4. ADR 0068-1 の行を書き換えるだけなので、全体の CLAUDE.md の行は増えず、200行の上限を守れる。
