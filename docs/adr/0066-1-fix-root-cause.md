# 0066-1 問題への案は、根本原因を取り除く恒久対応を主にし、回避策は暫定対応として並べる

状態: 採用
日付: 2026-11-12
対象: 全体

## 決めたこと

全体の CLAUDE.md の人間側の最適化に、問題への案が根本原因を取り除いている目指す状態を置き、回避策は暫定対応と言って恒久対応と並べて出す(詳しい文は全体の CLAUDE.md)。

## 捨てた案

1. skill `task-team-se` の壁打ちにだけ置く: SE を通さない会話(デバッグ・CI の調査など)では読まれず、効かない。
2. 全体の CLAUDE.md と skill `task-team-se` の両方に置く: 同じ規則は文書をまたいでも1か所にだけ置く(skill `prompt-structure`)。全体の CLAUDE.md は SE の会話でも読まれる。
3. 回避策を出さない: 急ぐ場面で症状を先に止めるのはやむを得ない(利用者の答え)。
4. 台数・並列・キャッシュなどの手を名指しで避ける: 利用者が嫌うのは回避策で済ませることで、特定の手ではない(利用者の言葉)。名指しにすると、名指ししていない回避策が残る。
5. AI 側の最適化の、定石に沿う目指す状態の下に置く: その状態は言葉とやり方を広く使われるものに揃えるためのもので、案が根本原因に効くかは見ない。

## 理由

1. 根本原因を残すと、回避策はすぐ追い越される。LogiFee の UI テストは、2週間でファイルが 44 から 114 に増え、実行時間が1日約1.7分ずつ伸びていて、台を分けても6週間で約31分に戻る見込みだった(LogiFee の SE 2873 の報告)。
2. 回避策で済ませた案は、利用者が見抜いて突き返すまで残り、利用者は判断を誤るか、AI の出力を疑って見張ることになる。README の「なぜ」の、利用者が AI の出力をつかむ認知負荷を増やす。
3. 障害対応の定石は、原因に触らず症状を止める暫定対応(workaround)と、原因を取り除く恒久対応を分け、暫定対応のあとに恒久対応を追う(ITIL のインシデント管理と問題管理)。利用者も、急ぐ場面の回避策は暫定対応で、本対応(恒久対応)ではないと答えた。
4. 全体の CLAUDE.md は、どの会話でも読まれる。
