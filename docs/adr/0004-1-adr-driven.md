# 0004-1 設計の決定を ADR に提案し、利用者が採用してから実装する

状態: 提案
日付: 2026-10-31
対象: 全体

## 決めたこと

1. 設計の決定のうち Nygard の5つ(構造・非機能の特性・依存・インターフェース・作り方の技法)に効くものは、SE が ADR に「提案」で書き、利用者が「採用」にしてから PG が実装する。
2. ADR は対象のリポジトリの `docs/adr/` にまとめて置き、番号は `<タスクの番号>-<そのタスクの中の連番>`。タスクの番号は PL が振る4桁の連番。
3. task-team を通さない会話では ADR を書かず、タスクにして PL に回す。

## 捨てた案

1. ADR の番号を、リポジトリの中の通し番号にする(Nygard の定石)。
2. ADR を、モジュールごとのフォルダに置く。
3. task-team を通さない会話でも、`0000-<連番>` の番号で ADR を書く。

## 理由

1. 番号: タスクから、対応する ADR をすぐ引けるようにするため。定石(通し番号)からは外れる。
2. 置き場: 人が一覧で見渡せ、AI にとっての差は小さいため。
3. 書く対象と状態は、Nygard の定石に沿う(https://www.cognitect.com/blog/2011/11/15/documenting-architecture-decisions)。
