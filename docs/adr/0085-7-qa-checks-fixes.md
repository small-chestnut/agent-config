# 0085-7 レビューの指摘の直しは、QA が直した所を確かめてから先へ進める

状態: 採用
日付: 2026-11-14
対象: task-team-se・task-team-pg・task-team-qa・task-team-lead
置き換える: 0007-1 の決めたことのうち「指摘があれば直した SE が採用にする」・0069-2 の決めたことのうち「PG が作り直して PL に知らせ、QA はもう一度は見ない」

## 決めたこと

設計レビューと実装レビューの指摘を SE か PG が直したら、QA が、code-review をかけずに直した所だけを確かめ、指摘が残らなければ、ADR を採用にするか実装を通す。

## 捨てた案

1. 今のまま、直した役割が自分で先へ進める(SE が ADR を採用にして PG に頼み、PG が直して PL に知らせる): 作業をした役割が、自分の直しを自分で承認することになる。RACI チャートで設計と実装の A を QA にしたことと合わない(ADR 0085-3)。
2. 直した後に、レビューを初めからもう一度する(code-review をもう1回かける): 往復が重くなる。確かめるのは、QA が指摘の文で決めた所が直ったかだけで足りる。

## 理由

1. このタスク(0085)で、SE が設計レビューの指摘6件を直して自分で ADR を採用にし、その直しの誤り(SE を Fable に替える行の A)が、PG が実装した後の実装レビューで見つかった。
2. 利用者は、前に決めた「レビューは設計と実装に1回ずつ。何往復もするのは本末転倒」(ADR 0067-3 の理由5・ADR 0069-2 の捨てた案6)を撤回し、直しを QA が見る形を選んだ。
3. 兼務のような曖昧な分担は AI の逃げ道になる、という利用者の「なぜ」(ADR 0085-3)に効くのは、作業をした役割と別の役割が確かめること。
