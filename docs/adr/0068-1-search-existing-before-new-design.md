# 0068-1 新しい作りを設計する前に、同じことをする既にある機能と反する決まりを、利用者の語と作るものの名前で全体から grep して探す

状態: 提案
日付: 2026-11-12
対象: 全体
置き換える: 0006-1 の、SE が読む ADR の範囲

## 決めたこと

新しい作り(機能・データ・処理の種類)を設計する前に、チケットに出る利用者の語と新しく作るものの名前で、仕様・skill・CLAUDE.md・コードをリポジトリ全体から grep し、同じことをする機能と反する決まりを探す。当たった所に付いた番号の ADR も読む(詳しい文は全体の CLAUDE.md と skill `task-team-se`)。

## 捨てた案

1. 今のまま、SE は書き換える所に付いた番号の ADR だけを読み、既にあるものとの重なりは QA の設計レビュー(ADR 0067-3)に任せる: 新しい作りには書き換える所が無いので、反する決まりにも既にある機能にもたどり着かない。R-0718 では、SE が ADR-2842-3 に反する案と、入出金の組(`create_pair`)を作り直す設計を出し、QA の設計レビューも通した。間違った設計を書いてから止めるより、書く前に探す方が、設計と直しの往復が少ない。
2. `docs/adr/` を語で grep して当たった ADR を読む: ADR の数に比例して当たりが増え、却下・置き換え済みの ADR も当たる(ADR 0006-1 の理由1)。今の決まりは、ADR の番号が付いた仕様・skill・CLAUDE.md・コードの行にあるので、そこを探せば番号にたどり着く。LogiFee の ADR-2842-3 は、仕様 `docs/specs/accounting/消込の流し込み.md` の行に付いていて、「消込」で当たる(2026-11-12 に grep で確かめた)。
3. 設計のたびに、関係するモジュールの仕様とコードを全部読む: 読む量がモジュールの大きさに比例し、全体の CLAUDE.md の「1つの作業で読むものが、その作業に要るものに絞られている」に反する。grep なら、読むのは当たった行とその周りだけ。
4. 探した語と当たったものを、設計の節に書く: 設計の節は、置くファイルと名前・データだけ(skill `task-team-se`)。探した結果は設計そのものに出る(既にある機能を使う設計・決まりに沿う設計)。QA は ADR 0067-3 のとおり自分で grep する。
5. task-team の SE の skill にだけ足し、全体の CLAUDE.md は変えない: 全体の CLAUDE.md は、リポジトリ全体の検索を、影響を調べるときと、原因や呼び出し元がモジュールの外のときに絞っている。skill にだけ足すと全体の規則とぶつかり、task-team を通さない会話で新しい作りを作るときには探さないままになる。

## 理由

1. R-0718 で、既にある入出金の組(`create_pair`)は、Fable に替えた SE が、利用者の語「組にしていく」から仕様とコードを grep して見つけた(LogiFee の SE の記録)。LogiFee の仕様 `docs/specs/accounting/入出金.md` には「入出金の組」「組にする」があり、利用者の語で当たる(2026-11-12 に grep で確かめた)。既にある機能は利用者の語から探せる。
2. 探すのは新しく作るものの語だけなので、読む量は、その作りに関わる行の数で決まり、ADR の総数にもリポジトリの大きさにもよらない。ADR 0006-1 の理由(読む ADR がタスクの数に比例して増えない)は保たれる。
3. QA の設計レビューの同じ見る所(ADR 0067-3)は、SE が見落としたときに止める2つ目の所として残る。0067-3 の捨てた案5 のとおり、SE 1つに頼らない。SE が先に探せば、QA まで本質的におかしな設計が流れる数が減る。
4. 反する決まりは、利用者が決めたことと「なぜ」の形。設計が沿えないときは、置き換えるかを利用者に聞く(全体の CLAUDE.md の「モジュールの「なぜ」と逆向きの依頼は、前の理由を撤回するかを1回だけ聞いてから始めている」と同じ向き)。
