# 0047-3 まだ始めていないタスクは、PL の会話でなく、ステータス「未着手」か「検討待ち」のチケットとして既定のブランチに残す

状態: 提案
日付: 2026-11-09
対象: 全体

## 決めたこと

やると決めたがまだチームを起こしていないタスクはステータス「未着手」、あとで1つずつ考えたいタスクはステータス「検討待ち」のチケットにし、`small-chestnut` のリポジトリでは既定のブランチに直接コミットして push し、チームを起こすときはそのチケットをチームのチケットにする(詳しい文は skill `task-team-lead` と全体の CLAUDE.md の原則1)。

## 捨てた案

1. 今のまま、PL の返答の最後に「バックログ」として並べ、`/compact` の1行で残すよう頼む: 圧縮の要約に頼って残すので、会話の状態によって消えうる。skill `task-team-lead` の「進捗は、PL の会話ではなく、アプリとチケットにある」にも反する。
2. チケットにするが、コミットせずにその PC の作業ツリーに置く: 利用者が選ばなかった。ほかの PC の PL から見えない。
3. Notion の ✅ Todo など、リポジトリの外の一覧に置く: チケットと別の置き場が増え、チームを起こすときに写し替えが要る。

## 理由

1. 利用者の理由: 利用者は、やると決めたことも、あとで考えたいことも、AI の会話の状態によらず、タスクとして確かめたい。
2. 定石: Jira や GitHub Issues でも、バックログは別の一覧ではなく、まだ始めていないチケットの集まり。
3. 既定のブランチに置くのは、どの PC の PL からも見え、チームの作業ブランチがそのチケットを持って始まるから。終わったら今どおり作業ブランチで消す(ADR 0022-2)ので、マージで既定のブランチからも消える。
4. `small-chestnut` 以外が所有するリポジトリでは、既定のブランチへの直接のコミットと push を持ち主が望むか分からないので、コミットせずに置く。チームを起こすときは、SE がそのチケットを自分の作業ブランチの置き場へ移すので、本体の作業ツリーには残らない。
5. 既定のブランチへの直接のコミットは、全体の CLAUDE.md 原則1 の「作業は作業用のブランチで」の除外に足す。まだ始めていないチケットは作業の結果ではなく、コミットしたものは git から戻せる。
