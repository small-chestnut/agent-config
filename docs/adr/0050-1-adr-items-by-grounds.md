# 0050-1 ADR の捨てた案と理由は、行数でなく、案ごと・根拠ごとに1項目で書く

状態: 提案
日付: 2026-11-09
対象: task-team-se

## 決めたこと

ADR の捨てた案は、案ごとに1項目で、案と選ばなかった根拠を書き、理由は、根拠ごとに1項目で、決めたことを選んだ根拠だけを書き、項目の数と行数に上限を置かない(詳しい文は skill `task-team-se`)。

## 捨てた案

1. 今のまま「各1〜3行」にする: 「1項目が1〜3行」とも「節ぜんたいで3行まで」とも読め、後の読み方では、根拠が4つある決定でも1つ削られる。行数そのもの以上の理由が残っていない。
2. 上限の数を増やす(例: 各5行まで): 数を選ぶ根拠が無いのは今と同じで、根拠がその数を超える決定では、また削られる。
3. 行数を上限から目安に下げて残す: 目安も上限として読まれうるうえ、中身の基準と行数の目安が並ぶと、どちらで決めるかで迷う。

## 理由

1. 利用者の理由: 「3行まで」に、「3行まで」以上の理由がないなら、見直すべき規則。元は 2026-10-15 のコミット abe32d0 で全体の CLAUDE.md に入った「書くこと: 日付・決めたこと・捨てた案・理由、各1〜3行。」で、参考は Claude Code 公式の CLAUDE.md の目安と LogiFee の形だけ。ADR の番号も付いていない。
2. ADR は、後で同じ所を設計する人が、決定とその根拠を読むためのもの(全体の CLAUDE.md 原則3「利用者が決めたことと、利用者の「なぜ」が、リポジトリに残っている」)。行数で削ると、本当にある根拠が消える。agent-config の ADR 47件のうち10件は、理由が4項目以上ある。
3. 短さは中身で保つ。根拠ごとに1項目にし、根拠でない背景を書かなければ、要らない行は入らない。別のリポジトリのタスク 0012 で消された4つ目の理由(3分けの出どころ)も、根拠でない背景なので、この形でも書かない。
4. 定石: Nygard の ADR は文書全体を1〜2ページとし、節ごとの行数は決めていない(https://cognitect.com/blog/2011/11/15/documenting-architecture-decisions)。MADR も、案の数と良い点・悪い点の数は決まっていないとしている(https://adr.github.io/madr/)。
