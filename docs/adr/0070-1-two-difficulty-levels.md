# 0070-1 仕事の難しさを低と高の2段にし、高には Opus 5.5 の high を割り当てる

状態: 提案
日付: 2026-11-12
対象: task-team-se・task-team-lead
置き換える: 0059-1 の3段の分け方・0069-3

## 決めたこと

役割の仕事の難しさは、低(書いてあるとおりにやれば済む仕事)と高(自分で選ぶ所がある仕事。枠そのものを決める仕事も含む)の2段にし、高には、PL の仕事も含め、Opus 5.5 の high を割り当てる(詳しい文は skill `task-team-se`・`task-team-lead`)。

## 捨てた案

1. 低・中・高の3段のまま残す(ADR 0069-3 の形): 中と高は割り当てが同じで、区別が効くのは、Fable を始めから使う条件の1つ目と、PG の仕事を高にしない決まりだけ。どちらも段の名前を使わずに「枠そのものを決める仕事」と書けば、今と同じ範囲になる。区別を残すと、SE が見分ける手間と見分けの誤りが残り、利用者は使われない区別を読むことになる。
2. 2段の名前を「低」と「判断がある」にする: 利用者が、その名前は使わないと答えた。同じ物差しの上と下として対にならない。
3. Fable を始めから使う条件の1つ目を「役割の難しさが高であること」のまま残す: 高が、自分で選ぶ所がある仕事に広がる。判断のある PG の仕事も、残りの2つの条件がそろえば始めから Fable になる。利用者は、PG を始めから Fable にしないことに同意した。
4. Fable を始めから使う条件の1つ目を消し、残りの2つだけにする: 案3 と同じく、判断のある PG の仕事が当たりうる。

## 理由

1. ADR 0069-3 で、中と高は同じ Opus 5.5 の high になり、モデルの割り当てでは分ける意味が無くなった(PL のタスクの文)。
2. 中と高の区別を使っていた4つの所のうち、QA の難しさを設計レビューと実装レビューの高い方にする決まりと、PL の仕事を high にする決まりは、2段でもそのまま効く。Fable の1つ目の条件と、PG の仕事を高にしない決まりは、「枠そのものを決める仕事」と書けば今と同じ範囲になる(skill `task-team-se` の SKILL.md・skill `task-team-lead` の CLAUDE.md)。
3. 割り当ての変わらない区別は、SE が見分ける手間と見分けの誤りだけを生み、チケットの「難しさ」の節と用語集を読む利用者に、使われない区別を覚えさせる(README の「なぜ」の認知負荷)。利用者は、中と高の区別が何のためにあるのか分からなかった(PL のタスクの文)。
4. 「高」は、SE の段(ADR 0067-1)と、QA の設計レビューの段として、今も使われている。低と高の対にすると、書き直す行が少ない。
