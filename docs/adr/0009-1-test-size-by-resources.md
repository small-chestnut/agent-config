# 0009-1 テストの大きさの既定は、テストが使う資源で分け、画面を動かすテストと速さの計測は大に入れる

状態: 採用
日付: 2026-10-31
対象: 全体

## 決めたこと

リポジトリに決まりが無ければ、小は1つのプロセスで終わりファイル・DB・ネットワーク・sleep を使わないもの、中は1台のマシンで終わり localhost の外へ通信しないもの、大はそれ以外と、画面を動かすテストと速さの計測とし、この既定をグローバルの CLAUDE.md 原則3 に置く。

## 捨てた案

1. 大きさの中身を、各リポジトリの CLAUDE.md に書く(いまのやり方)。
2. Software Engineering at Google の定義をそのまま使い、localhost で画面を動かすテストを中にする。
3. 大きさを、確かめる範囲(単体・結合・端から端まで)で分ける。

## 理由

1. 案1では、新しいリポジトリの CLAUDE.md にはまだ書かれておらず、大きさが決まらない。グローバルの CLAUDE.md は、どのセッションでも読まれる。リポジトリに決まりがあれば、そちらが勝つ(ADR 0004-1)。
2. 資源で分けるのは Software Engineering at Google 11章(https://abseil.io/resources/swe-book/html/ch11.html)の定石。何を使ったかで決まるので、書いた人によって大きさが割れない。案3の範囲は同じ章が大きさと別のものとしており、線を引く人によって割れる。
3. 案2から外れるのは、画面を動かすテストと速さの計測が遅く、マージ前に CI が流す小・中の10分に収まらないため。いまのパイプライン(README)と ADR 0005-1 も、画面から通すテストを大にしている。
