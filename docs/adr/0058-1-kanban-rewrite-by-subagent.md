# 0058-1 PL は、かんばんの書き直しをサブエージェントに任せ、返ってきたリンクだけを受け取る

状態: 採用
日付: 2026-11-10
対象: task-team-lead・team-kanban

## 決めたこと

PL は、かんばんを書き直すとき、自分で道具を呼ばず、Agent の道具で起こしたサブエージェントに skill `team-kanban` の手順を任せ、PL の会話には頼む1回と返ってくるかんばんのリンク1行だけを入れる。

## 捨てた案

1. カードの行を組むスクリプトをリポジトリに置き、PL が呼ぶ: かんばんに上げる・指し替える・古いファイルを消すのは Claude の道具(Artifact・ArtifactData)で、スクリプトからは呼べない。PL が呼ぶ回数は 6〜7 回から 5 回ほどにしか減らず、読んだデータのファイルの中身も PL の会話に残る。
2. データのファイルをリポジトリごとに分け、ほかの PL の行を読まずに済ませる: かんばんのページは、読むデータを id で書いておく作りなので、リポジトリが増えるたびにページを直すことになる。上げる・指し替える・消すの呼び出しは残る。
3. カードの行を、ファイルでなくかんばんの保存先の文書に直に置き、1回の書き込みで済ませる: Data 型のページが読めるのは、ファイルか接続先の問い合わせだけで、行を直に置く形(`kind: "rows"`)は読み込めない(Data 型の `artifact-type/reference/sources.md` の「Files, and older forms」)。
4. 書き直す回数を、ステータスが変わったときだけに減らす: サブタスクの済みの数が変わっても、かんばんがチケットの今とずれる(skill `team-kanban` の原則1)。1回の書き直しの重さは変わらない。

## 理由

1. サブエージェントが呼んだ道具の出力と読んだファイルは、サブエージェントの会話にだけ入り、PL の会話には最後の返答だけが戻る(Claude Code の Agent の道具の説明)。読む量の多い作業を任せて結論だけを受け取るのは、Agent の道具の使い方の定石。
2. 書き直しの手順は skill `team-kanban` のままで、読む人が PL からサブエージェントに替わるだけなので、かんばんとデータの形は変わらない。
3. 書き直しは決まった手順で、PL ほどのモデルが要らないので、モデルを下げて使用量も減らせる。
