# 0101-1 task-team を「プロジェクト」機能に統合する

状態: 却下
日付: 2026-11-25
対象: 全体
置き換える: 0100-1

## 決めたこと

task-team の手順と規則を Claude の「プロジェクト」機能に肩代わりさせて減らす統合は、見送り、実際のタスクでの試しもしない。

## 捨てた案

1. 仕事をクラウドのスレッドに移す: 肩代わりされると言える規則は、258 行のうち 30 行(12%)。使えるのは、2026-10-25 からの会話の約 26% のリポジトリで、残りの仕事のために、今の行は消せない。
2. 仕事をローカルのスレッドに移す: どの仕事にも使える見込みだが、肩代わりされると言える規則は 13 行(5%)。スレッドごとに、利用者がフォルダを使う許可を答える手間が増える。ローカルだけにする設定は、公式文書に見つからなかった。
3. 実際のタスク1つをクラウドのスレッドで試してから決める(ADR 0100-1): 肩代わりされるか言い切れない 39 行(かんばん 32・利用者待ち 7)が肩代わりされると分かっても、案1の、今の行を消せないことは変わらない。

## 理由

1. 利用者が統合で一番得たいのは、規則を減らすこと(ADR 0100-1 の理由1)。減る規則は少なく、残りの仕事のために2本立てになる。
2. 利用者は、移る価値があるかを調べ、無ければ移行を一旦見送ると言い、調査を見て見送ると答えた。
3. 調査は公式文書と手元の記録からの見立てで、動かしては確かめていない(`git show db7abda:docs/tasks/0101-run-task-in-claude-projects/value-research.md`)。
4. 見直すのは、次のどちらかのとき。規則の数よりも、PC を閉じても仕事が進むことを優先する。または、ローカルのスレッドを標準にでき、スレッドどうしがやりとりでき、未着手のタスクも一覧に出るようになる。
