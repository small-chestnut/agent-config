# 0091-2 受け入れ条件を作ったときに確かめることと、残すテストを分ける

状態: 提案
日付: 2026-11-24
対象: task-team-test-list・task-team-se・task-team-pg

## 決めたこと

受け入れ条件は、どれも作ったときに確かめ、残すテストにするのは ADR 0091-1 に当たるものだけで、ほかは動かして確かめる。

## 捨てた案

1. 受け入れ条件ごとに、残すテストを作る(今のやり方): 一度きりの確かめがすべてテストとして残る。受け入れ条件は要件の数だけ増え、表の値を言う受け入れ条件もテストになる。
2. 受け入れ条件の数を減らす: 受け入れ条件は、合意した内容が作ったものに入ったかを確かめるもので、減らすと漏れる。

## 理由

1. 受け入れ条件は、作ったものが合意どおりかをその時に確かめるもの。テストを残すのは、後の変更で壊れたときに気づくため。目的が違う。
2. gemini の 0082・0094 などでは、受け入れ条件1つにテスト1つ以上の決まりで、表の値や断る場合がそのままテストになった。
