# 0087-5 コードから作る仕様は、分野の定義と違っても今の動きを書き、違いはチケットの決まっていない問いにする

状態: 提案
日付: 2026-11-15
対象: task-team-se
置き換える: 0087-3 の、違いを仕様に写さない所

## 決めたこと

skill `task-team-se` で、仕様の無い機能の仕様をコードから作るときに、コードの業務の状態が業務の分野の定義と違っても、仕様にはコードの今の動きを書き、違いはチケットの「決まっていない問い」にする。

## 捨てた案

1. ADR 0087-3 のまま、違いを仕様に写さない: 仕様は機能の今の動きを書く文書(ADR 0045-2)で、今の動きを書かない仕様は、利用者が答えるまで、コードの今の動きをどこにも残さない。K4 の試しでは、入れた後の3回とも、今の動きを仕様に書いたうえで、違いを決まっていない問いにした。
2. 違いのある状態を、仕様に書いたうえで「要確認」などの印を付ける: 印の付いた行と決まっていない問いの2か所に同じことを書くことになる。チケットの問いに利用者が答えれば、仕様の直しはそのタスクでする。

## 理由

1. 取り違えが仕様に残って見つからないのを防ぐのは、違いを利用者に問うことで、仕様から今の動きを外すことではない(要件 R1 の受け入れ条件 R1-1 も、違う所を決まっていない問いにすることだけを言う)。
2. 仕様に今の動きを書き、違いを問いにすれば、利用者がコードを直すと答えたときも、名前や定義を直すと答えたときも、直す元の動きが仕様にある。
