# 0067-1 SE は、難しさを決めずに、最初のターンから Opus 5.5 の high で動かす

状態: 採用
日付: 2026-11-12
対象: task-team-lead・task-team-se
置き換える: 0059-1 の SE の割り当て

## 決めたこと

SE の難しさは決めずにいつも高(`claude-opus-5-5` の high)とし、PL は SE を、skill を読んで待つ prompt で起こし、high に替えてからタスクを送る。PG と QA は、ADR 0059-1 のとおり SE が決めた難しさで割り当てる(詳しい文は skill `task-team-lead`・`task-team-se`)。

## 捨てた案

1. 難しさの物差しに、本番のデータに触る重さと、既にある機能を知らないと設計できない度合いを足し、SE が自分の難しさを決めるのは残す: R-0718 の誤り9件のうち、1・3・6・7・8 は、全体の CLAUDE.md に既にある規則(聞くのは目的と「なぜ」だけ・事実は確かめてから書く・結論から短く)を守れなかったもので、仕事の難しさによらず、利用者と話すどの SE の仕事でも起きる。物差しを足しても、この誤りは見込めず、当てはめるのも medium の SE 本人のまま。
2. SE を high で起こし、high の SE が自分の難しさを中と決めたら、PL が medium に下げる: 案1 と同じく、中と決めた仕事でも、利用者と話す規則の誤りは減らない。
3. SE を xhigh にする: Anthropic の測定で、Opus 5.5 の xhigh は high より、SWE-bench Pro で約 1.4 ポイント上で費用は 2.5 倍、エージェントのコードの作業で 2.7 ポイント上で費用は約 3 倍。その費用では Fable 5.2 と並び、Fable は ADR 0065-1 の上げ先として既にある。
4. SE を初めから Fable 5.2 にする: 調べものの課題(DeepResearch Bench II)で、Fable 5.2 は low で 54.5、high で 57.7 と、Opus 5.5 の medium の 59.6 より下。SE の壁打ちと設計は調べものに近い(ADR 0059-1 の捨てた案4)。R-0718 で Fable に替えた直後に既にある機能(`create_pair`)が見つかったが、1件で、替える前に利用者がその語を出していた。
5. `start_session` の effort で、起こすときから high にする: `start_session` の effort は、起こす PL の effort までしか選べない(道具の説明)。PL は medium なので、起こしたあとに替えるしかない。替えた値は次のターンから効くので、タスクを渡す前に替える。
6. PL が SE の難しさを決める: PL はタスクの中身を読まない(ADR 0056-1・0059-1 の捨てた案6)。
7. 利用者が手で effort を上げる(今回のやり方): 利用者が誤りに気づくまで上がらず、気づくまでの誤りは利用者が止めることになる。根本原因に触らない暫定対応で、恒久対応ではない(ADR 0066-1)。
8. 設計レビューをする QA も、いつも high にする: QA の難しさを決めるのは QA 本人でなく SE で、high の SE が決める形になる。ADR を出す設計のレビューは、今の物差しでも枠を決める仕事を見るので高になる。R-0718 の QA の effort は記録に無く、QA が通した2件(段階に合わない・既にある機能との重なり)は、設計の節に code-review をかける今のレビューの仕方が見ない所で、effort では直らない見込み(ADR 0067-3 で直す)。

## 理由

1. SE は利用者と直に話し、誤りが利用者に直に届く。R-0718 では、SE を Opus 5.5 の medium で回した間に判断の誤りが9件起き、利用者が止めたのは8件。利用者は Opus の medium が「だいぶ信頼できない」と見た(LogiFee の SE の記録・PL のタスクの文)。
2. 難しさを決める判断が、浅い判断をする本人に任されていると、誤りが続いても割り当てが上がらない。R-0718 の SE は、最初に自分の難しさを「中」と決めた。
3. Anthropic の勧めは、Opus 5.5 の medium から始め、Opus 5.5 の高い effort でも足りないときに Fable 5.2 にすること。medium で足りなかったので、次は high で、その先は ADR 0065-1 の Fable(https://platform.claude.com/docs/en/about-claude/models/optimizing-for-cost-and-intelligence.md 。2026-11-12 に読んだ)。
4. 同じページの測定で、Opus 5.5 の medium から high で、SWE-bench Pro の1件の費用は $0.21 から $0.29、解けない割合は 7.2% から 4.7%。欠陥を探す課題では 0.827 から 0.850。上がるのはタスクごとに SE 1つだけで、PG と QA は変えない。
5. 利用者の Max プランの全部のモデルの週の枠は、2026-11-12 に `get_usage` で引いて、週の 38% が過ぎたところで 31% を使っていた。SE 1つを high にする増え方は、この枠に収まる見込み。
