# 0084-5 「なぜ」は、リポジトリの命題と ADR にだけ置き、「なぜ」の文書を置かない

状態: 提案
日付: 2026-11-14
対象: 全体
置き換える: 0020-1

## 決めたこと

「なぜ」は、リポジトリが何のためにあるかの不変の「なぜ」(命題。リポジトリの目的を書く文書の冒頭)と、決定の理由(ADR)と、その修正で用が済む理由(コミットメッセージ)にだけ置き、モジュールの CLAUDE.md や `.claude/rules/` の「なぜ」の文書を置かない。agent-config の「なぜ」の文書8つ(`.claude/rules/` の3つと、skill の CLAUDE.md の5つ)は消し、その中で規則として働いている行は規則の文書に移す(詳しい文は全体の CLAUDE.md)。

## 捨てた案

1. 今のまま、後で同じ機能を変えるときにも守る理由を、モジュールの CLAUDE.md(agent-config では `.claude/rules/`)に置く(ADR 0020-1): ADR のある決定の理由が、ADR と「なぜ」の文書の二重管理になる。片方だけを直すと食い違い、0084 の設計でも、消す規則の理由を両方から消す手順が要った。
2. ADR の無い規則の理由を残すため、「なぜ」の文書を残す: 利用者は、過去に ADR を付けなかったために残っているだけの文書は消すと決めた。その規則は ADR の番号なしのままにし、後で直したときに、そのときの ADR が付く。
3. 「なぜ」の文書を消す前に、ADR の無い規則の理由を、ADR に書き起こす: 利用者が決めていない過去の決定を、後から ADR の形で作ることになる。

## 理由

1. 利用者の理由: リポジトリそのものの「なぜ」は常に読みたいので、命題としていつも読まれる文書に置く。ADR は、その決定が関わる所を触るときにだけ読む、一つ下の「なぜ」。ADR が「なぜ」のためのものなのに、同じ理由を別の文書にも書く二重管理はしない。
2. 二重管理の害は 0084 で起きた: 「なぜ」の文書には理由と規則が混ざり、消す前に1行ずつ規則かどうかを調べ直すことになった。全体の CLAUDE.md の「なぜ」の文書には、ADR 0076-1・0076-2 の上限と減らし方の手順が、詳しい文として置かれていた。
3. 規則として働いていた行の移し先: ADR 0076-1・0076-2 の上限と減らし方は、上限を超えたときにだけ要るので、字数のテストの失敗メッセージに置く。settings の操作の分け方と `extraKnownMarketplaces` を残すことは、settings の仕様(`docs/specs/user-settings.json.md`)に置く。Fable のほかのモデルの格上げは利用者がすること(PL の skill)と、プロンプトが仕様のリポジトリで QA が照らす相手(QA の skill。ADR 0069-2 の捨てた案1)は、それぞれの skill に置く。
4. install は skill の CLAUDE.md と `.claude/rules/` を配っていないので、消してもほかの設定ディレクトリに残るものは無い。
