# 0055-2 例の並びの問いを、消せる語の問いと同じ知らせに入れる

状態: 提案
日付: 2026-11-10
対象: ask_about_written_lines.py・check_rule_documents_changed_by_shell.py

## 決めたこと

書いた行を問い返すフックは、消せる語の問いと、決まりや事実を1文で言わずに具体例や出来事を並べている所の問いを、1つの知らせで問い、名前を `ask_removable_words.py` から `ask_about_written_lines.py` に替える。

## 捨てた案

1. 例の並びだけを問う新しいフックを足す: 同じ行の並びが、保存のたびに2回 Claude に返り、コンテキストを2倍使う。
2. 名前を `ask_removable_words.py` のまま、問いを足す: 名前が中身の半分しか言わず、例の問いを grep で探しても見つからない。
3. 例の並びを、文字列のパターン(「・」の数・「など」)で見つけて止める: 並べ方は書き方ごとに違い、パターンもまた書いた形しか捕まえない。止めると、言い換えて通す道ができる(atcoder では、字数のフックを行を分けて通した)。
4. 全体の CLAUDE.md か prompt-structure に、例を並べない規則を足す: prompt-structure には既に「プロンプトは、一般の文だけで書く」があり、それでも並べた。メモリを書くときには prompt-structure は読み込まれない。
5. 日付で始まる行を、経緯として問う: Claude Code は、`project` の種類の自動メモリに絶対の日付を書くよう決めている。日付があるだけでは経緯と言えず、問うべき出来事の並びは日付が無くても起きる。

## 理由

1. 具体例は、書いた例にしか効かない。書いていない場面は、書いていないから構わないと読まれ、その穴を例で塞ぐと規則の束ができる。決まりは、例がみなそこから出てくる状態を1文で言う。これは書いた本人がその場で見直せば直せるので、書いた行を指して問い返すのが合う。
2. 自動メモリでは、例の並びは、失敗のたびに既にあるメモリへ出来事の段落を書き足す形で育つ(Gemini の PL のメモリで、教訓の1文の下に失敗の日付と出来事が足され続け、毎回読まれていても同じ失敗が2回起きた)。出来事も、言いたい決まりの例の1つなので、同じ問いで問う。
3. 消せる語の問いと同じ行を見て、同じ時に返す。1つの知らせにすれば、行の並びは1回で済む。
4. シェルで書いたプロンプトにも同じ2つの問いを掛けるため、問いの文は `ask_about_written_lines.py` の1か所に置き、`check_rule_documents_changed_by_shell.py` はそれを使う。
