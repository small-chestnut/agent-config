# 0096-1 1つのタスクのことで動いたときは、そのタスクのカードだけを書き直す

状態: 採用
日付: 2026-11-24
対象: task-team-lead・team-kanban

## 決めたこと

PL は、子セッションの知らせ・タスクを始めた・終えた・まだ始めていないチケットを作ったときは、そのタスクのチケットの保存先をサブエージェントに渡して、そのタスクのカードだけを書き直させ、リポジトリの全部のカードを書き直すのは、利用者に進み具合を聞かれたときだけにする。

## 捨てた案

1. 今のまま、知らせのたびにリポジトリの全部のカードを書き直す: 知らせの来ていないタスクのカードは、そのタスクの知らせが来たときに動かせば足りる(利用者の理由)。2026-11-24 の記録で、LogiFee は1回の書き直しで開いているチケットを1件ずつ全部読み、7分36秒かかった。agent-config も、カード1枚のためにリモートのブランチ約90本を調べ、1分〜1分40秒かかった。
2. 全部のカードを書き直すのをやめ、進み具合を聞かれたときも、かんばんのリンクだけを出す: チームの知らせを通らない変化(LogiFee の開発者コンソールに入った新しい報告・ほかの PC の PL がしたこと)が、かんばんに入る時が無くなる。
3. サブエージェントを通さず、PL が自分でそのカードの行を書き直す: カードが1枚でも、かんばんのデータのファイルを読み、上げ、指し替え、古いファイルを消す呼び出しが PL の会話に入る(ADR 0058-1 の理由のまま)。

## 理由

1. 利用者の理由: チーム A から知らせが来たら A のカードを、チーム B から知らせが来たら B のカードを動かすのが自然。
2. 定石: GitHub Projects の組み込みのワークフロー(Item closed など)は、イシューやプルリクエストが閉じたとき、そのアイテムの Status だけを替え、ほかのアイテムは触らない(GitHub Docs「Using the built-in automations」)。
3. カードが変わるのは、チケットが変わるときで、チケットを変えるのは子セッションか PL。子セッションはターンを終えるたびに PL に知らせが届き、PL は自分でチケットを作る・消すので、そのたびにそのカードを書き直せば、かんばんはチケットの今とずれない。
4. 全部の書き直しを、利用者が進み具合を聞いたときに残すので、知らせを通らない変化も、利用者が見るときには入る。
