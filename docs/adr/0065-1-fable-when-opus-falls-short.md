# 0065-1 Opus 5.5 の high で仕上がらないと見込める仕事と、その印が出た仕事は、SE が Fable 5.2 の high に決める

状態: 提案
日付: 2026-11-11
対象: task-team-se・task-team-lead

## 決めたこと

ADR 0059-1 の3段の割り当てに加えて、始める前に見分けられる3つの特徴がそろう仕事と、1つの会話に収まらないと見込める仕事と、途中で決定の撤回が重なった仕事は、SE が Fable 5.2 の high に決め、PG と QA は SE が、SE は PL が替える(詳しい文は skill `task-team-se`)。

## 捨てた案

1. 前に同じ種類の仕事が Opus で破綻した記録があるかで決める: 破綻したことと、利用者が出力をつかめなくなったことは、リポジトリの記録に残らない(LogiFee の七海の移行の記録に、どちらも無かった)。
2. 難しさが高の仕事を、みな Fable にする: ADR 0059-1 の捨てた案4 のとおり、調べものに近い壁打ちと設計では、Fable 5.2 は Opus 5.5 より費用 2.9 倍で点が低い。
3. 今のまま、利用者が手で上げるだけにする: 途中の印(決定の撤回の重なり)は ADR とチケットに出るが、利用者はそれを読まない。利用者が始める前に見込んだ 2856 の特徴も、SE がチケットとリポジトリから読み取れる。
4. ADR の枝番の多さを途中の印にする: Fable で進んで破綻しなかった 2856 も、ADR を7件出した。枝番の多さだけでは、破綻と、決めることの多い仕事を分けられない。
5. Fable にした仕事は、レビューも Fable にする: 2856 では、Opus 5.5 の medium の QA が、Fable の設計に5回のレビューで15件の食い違いを見つけ、どれも本当の食い違いだった。
6. Fable の effort を low にする: 同じページで、Fable 5.2 の low は SWE-bench Pro を $0.39 で 94.6% 解き、Opus 5.5 の high($0.30 で 95.5%)を越えない。Fable にするのは、Opus 5.5 の high で足りないときなので、Opus 5.5 の high を越える effort にする。
7. 途中で Fable にするとき、新しいセッションに移す: PL が会話ごと写して起こせるのは、PL 自身の会話だけ。同じセッションのモデルを替えれば、SE の会話が残り、キャッシュを失うのは替えた1回だけ。

## 理由

1. Opus で仕上がらない仕事は、その場かぎりの対応が積み重なって破綻し、利用者が AI の出力をつかめなくなる。README の「なぜ」の、利用者の認知負荷を壊す(利用者の答え)。
2. Anthropic のページは、Fable 5.2 を、難しい推論と長いエージェントの作業、1つのコンテキストに収まらない作業、Opus 5.5 の高い effort でも足りないときに勧めている(https://platform.claude.com/docs/en/about-claude/models/optimizing-for-cost-and-intelligence.md 。2026-11-11 に読んだ)。
3. 利用者が始める前に Fable にした 2856 は、SE の難しさが高、利用者が会計の中身を確かめられない、決定どうしがつながり1つ変えるとほかの数字が合わなくなる、の3つがそろっていた(2856-migration-plan-se (fork) の答え)。
4. その前の七海の移行では、破綻の前に、同じ日に入れた決定を消す(ADR-2842-2 → 2842-5)、同じ決まりを4回変える(立替金の分け方)が、ADR に出ていた(同じ答え)。この作業は Opus で進めていた(利用者の答え)。
5. 利用者の Max プランには、全部のモデルの週の枠とは別に、Fable の週の枠がある(2026-11-11 に `get_usage` で引いた)。
