# 0009-3 テストは、どのセッションでもデプロイパイプラインの段で流し、CI が無ければマージ前に手元で流す

状態: 採用
日付: 2026-10-31
対象: 全体

## 決めたこと

task-team でも1つだけのセッションでも、書いている間は変えた所の小、マージ前に小と中の全部、マージ後に大を流し、CI があれば小・中・大は CI が流して緑を待ち、CI が無ければマージ前に小と中の全部と変えた使い方の大を手元で流す。

## 捨てた案

1. 1つだけのセッションでは、終わる前に小・中・大を全部、手元で流す。
2. 1つだけのセッションでは、変えた所の小だけを流す。
3. CI が無ければ、中と大は流さない(いまの task-team-pg と task-team-lead の書き方では、こうなる)。

## 理由

1. 継続的デリバリーの定石: マージの前に流す分は10分ほどで終え、遅いテストは後の段で流す(Martin Fowler「Continuous Integration」の Keep the Build Fast、https://martinfowler.com/articles/continuousIntegration.html)。セッションの数で段を変える理由が無いので、1つだけのセッションも同じ段にする。案1は、同じ PC で動くほかのセッションと互いに遅くなる(task-team でテストを減らした理由と同じ)。
2. 同じ記事は、マージの前に手元でビルドとテストを通すことを、マージの条件にしている。CI が無いときにそれを担うのは手元だけなので、案2・案3では中と大が一度も流れない。
3. CI が無いときの大を、変えた使い方の分に絞るのは、大は利用者の主な使い方1本につき1つまで(ADR 0005-1)で、変えていない使い方は前のマージで確かめてあるため。
