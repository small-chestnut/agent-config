# 0056-1 タスクの中身の話は SE の会話でし、PL は話題の振り分けと進み具合だけを受け持つ

状態: 採用
日付: 2026-11-10
対象: task-team-lead・task-team-se
置き換える: 0034-2

## 決めたこと

利用者が最初に話しかける入口は PL 1つのままにし、タスクの中身の話(壁打ち・質問・子セッションが待つ問いへの答え)はそのタスクの SE の会話でして、PL は、話題がどのタスクに当たるかを決めて SE の会話へのリンクを出すことと、進み具合を見せることだけを受け持つ。SE は、会話で分かった前提をチケットに書き足す。

## 捨てた案

1. チケットに無い前提の問いだけを SE に回し、ほかは PL が答える(0034-2 の形): 壁打ちと、チケットから答えられる問いが PL の会話に積もり、ほかのタスクの話と混ざって、PL が説明を誤る。
2. 入口を置かず、利用者がタスクごとに子セッションを探して話す: どの話題がどのタスクに当たるかを、利用者が覚えておくことになる。
3. 壁打ちは PL のままにして、PL の会話をこまめに圧縮する: 圧縮は利用者が1行を送ったときにしか起きず、圧縮の後の PL は、そのタスクの中身を持っていない。

## 理由

1. 入力が長くなるほど、また、話題は似ているのに問いには答えていない話が混ざるほど、LLM の答えは当てにならなくなる(Chroma「Context Rot」2025: https://research.trychroma.com/context-rot)。
2. 同じ課題を何往復にも分けて渡すと、1回でまとめて渡すより正確さが平均 39% 落ち、早い往復で持った思い込みから戻れない(Laban ほか「LLMs Get Lost In Multi-Turn Conversation」2025: https://arxiv.org/abs/2505.06120)。
3. タスクにした後、そのタスクの中身を持っているのは SE で、PL が持っているのは、進行中であることとチケットの置き場だけ。PL が中身に答えると、その中身がまた PL の会話に入る。
4. 利用者は、PL が持つのは、話題がどのタスクに当たるかが分かる程度の理解まで、と決めた。
