# 0049-1 利用者しか使わないリポジトリでは、agent-config の規則をリポジトリの決まりより先にし、ぶつかった決まりを agent-config に合わせて書き直す

状態: 提案
日付: 2026-11-09
対象: 全体
置き換える: 0004-1 の3

## 決めたこと

agent-config の規則(全体の CLAUDE.md・skill)が作業するリポジトリの決まりとぶつかったら、利用者しか使わないリポジトリ(リモートが無いか、`small-chestnut` が所有し、フォークでなく、ほかにコラボレーターがいないもの)では agent-config に従って、ぶつかったリポジトリの決まりをその作業で agent-config の形に書き直し、ほかのリポジトリではリポジトリの方に従い、どちらも利用者に1行で伝える(詳しい文は全体の CLAUDE.md の冒頭)。

## 捨てた案

1. 今のまま、どのリポジトリでもリポジトリの決まりを先にする(ADR 0004-1 の3): 理由の「ほかの人も触る」が当たらないリポジトリにまで効き、README の目的に反する。
2. 作業を始めるたびに、リポジトリの決まり全体を agent-config と照らして合わせる: 利用者が選ばなかった。作業に要らない所まで読むことになる(ADR 0048-1 と同じ向き)。
3. リモートの無いリポジトリは、`small-chestnut` の所有を確かめられるまでリポジトリの決まりを先にする: 利用者が選ばなかった。まっさらから作り始めたばかりのリポジトリが外れる。

## 理由

1. 利用者の理由: agent-config は、利用者が AI 駆動開発のためにチューニングした規則。リポジトリの決まりを先にしたのは、利用者の私的な規則で、複数の人間が触るリポジトリの規則を逸脱するわけにはいかないため(ADR 0004-1 の理由3)で、利用者しか使わないリポジトリには当たらない。
2. まっさらから作り始めたリポジトリの決まりは、AI が agent-config に沿って書き写したもの。リポジトリの決まりが勝つと、agent-config を直しても前の写しが勝ち、AI はどちらに従えばよいか迷う。ぶつかった所を書き直せば、写しが agent-config に揃い続ける。
3. 見分け方の `small-chestnut` の所有は、利用者が選んだもので、全体の CLAUDE.md 原則1 で既に使っている。コラボレーターが入ったら、ほかの人も触るので、そこから理由1 の前提が当たらなくなる。フォークは、ほかの人が決めた決まりを持ち、変更を元のリポジトリに返すことがあるので外す。
4. 所有とコラボレーターは、外部サービスから引けば分かる値なので、ぶつかったときに GitHub から引く(全体の CLAUDE.md 原則3)。引けなければ、ほかの人も触るかもしれないので、今までどおりリポジトリの決まりを先にする。
5. リモートが無いのは、利用者がその場で作り始めたリポジトリ。clone したリポジトリには必ずリモートがあるので、ほかの人のリポジトリはまず当たらない。
6. 外のツールや枠組みが求める形(`.git` の置き場など)は、書き直すと動かなくなるので、どのリポジトリでもそのまま従う。
