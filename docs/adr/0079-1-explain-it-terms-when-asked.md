# 0079-1 IT の用語がある概念はその用語で書き、意味を添える時を、AI に見分けられない条件で決めない

状態: 採用
日付: 2026-11-13
対象: 全体
置き換える: 0044-1

## 決めたこと

IT の用語がある概念は、例えや作った呼び名に置き換えずにその用語で書き、意味を添える時を、利用者がその用語を知っているかや初めて出すかで決める規則を置かない(詳しい文は全体の CLAUDE.md)。

## 捨てた案

1. 今のまま、知らない人には初めて出すときに意味を添える(ADR 0044-1): 利用者がどの用語を知っているかは、どこにも残っていない。初めて出すかも、会話を圧縮した後と、ほかのセッションで利用者が読んだものは見えない。AI は条件を推測で当て、毎回添えて返答が長くなるか、推測で省くかになる。
2. 意味を添えずに使い、問い返されたら意味を説明する規則を置く: 問い返されたら答えるのは、規則が無くても AI がすること。「意味を添えずに」は、書く文をその分野を知らない人にも分かりやすくすることとぶつかりうる。
3. IT の用語を出すたびに意味を添える: 利用者が知っている用語にも添えるので返答が長くなり、1ターンの返答をスクロールせずに読み切れる、に逆らう。
4. 利用者が知っている用語を自動メモリに書き溜めて当てる: 記録は増え続け、ほかの PC とほかのアカウントの設定ディレクトリでは揃わない。

## 理由

1. 見分けられない条件の規則は、AI ごとに推測で当て方が変わる。
2. 意味を添えるかは、全体の CLAUDE.md の原則2の目指す状態「書く文は、その分野を知らない人にも分かりやすい」に任せれば足りる。
3. IT の用語は、画面やエラーメッセージにも同じ語で出て(例: メーラの IMAP 設定)、利用者が調べることもできる。言い換えると、画面の語と結びつかない。
4. 利用者は、根にある求めは分かりやすく説明することの一点で、問い返されたら説明するは本質ではないと言った。
