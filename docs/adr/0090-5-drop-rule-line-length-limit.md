# 0090-5 決まりの1行を 60 字までにする上限をやめる

状態: 採用
日付: 2026-11-17
対象: check_rule_length.py・check_rule_documents_changed_by_shell.py・ask_about_written_lines.py
置き換える: 0055-1 の、自動メモリの行の字数を数える所

## 決めたこと

決まりの1行を 60 字までにする上限(保存したときに知らせるフック `check_rule_length.py`・シェルのフックの字数の知らせ・SKILL.md の行の字数のテスト)をやめる。

## 捨てた案

1. 上限を 60 字より長くする: 何字にしても、収まらない決まりは行を分けることになり、全体の量は減らない。

## 理由

1. 利用者の理由: 文章の量を減らすつもりで入れたが、減らなかった。行だけを読んでも意図が分からない行が出てきたのも、この上限のため。利用者の意図は、意味を変えず、行を分けずに、60 字に収まるよう圧縮させることだった。フックの知らせは「短くしてください」だけで、Claude は行を分けるか言葉を省いて上限を通した。
2. 上限は1行ごとで、全体の量には掛からない。収まらない決まりは、複数の行に分かれた(タスク 0090 で、118 字の1行が4行になった)。全体の CLAUDE.md と skill の規則の行 424 行のうち 28 行は、「その」「そのとき」のように、前の行を読まないと意味が決まらない書き出しだった(2026-11-17 に数えた)。
3. 60 字に収めるために言葉を省いた行が、意図と違う意味に読まれたことがある(ADR 0087-2 の理由3)。
4. 入れたときの理由は、「短く」と書くだけでは Claude の判断で長い文が通ること(2026-10-22 のコミット b3346e5)。その役は、行を足したときの問い(消しても意味が変わらない語は消す。`ask_about_written_lines.py`)と、3つの新しいセッションに読ませる確かめ(ADR 0087-1)が持つ。全体の量は、全体の CLAUDE.md の字数のテスト(ADR 0076-1)で止める。
5. プロンプトと自動メモリを見分けて足した行を取る処理は、残る2つのフックが使うので、`rule_document_added_lines.py` に名前を替えて残した。
