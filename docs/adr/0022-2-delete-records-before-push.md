# 0022-2 PL がマージするタスクの記録は、作業ブランチを push する前に消し、CI が赤なら戻す

状態: 採用
日付: 2026-11-01
対象: task-team-lead
置き換える: 0022-1

## 決めたこと

PL が自分でマージするタスクの記録(と記録のフォルダ)は、作業ブランチを push する前に消し、CI が赤なら消したコミットを戻してから PG に直しを頼む。`small-chestnut` が所有しないリポジトリと、記録だけのリポジトリでは消さない。

## 捨てた案

1. 終わった記録を残す: リポジトリ全体の検索に、古くなった設計の文が混ざる。
2. 次のタスクを始めるときに、その作業ブランチで消す: 利用者がマージの前を選んだ。
3. CI が緑になった後、マージの直前に消す(0022-1): 消すコミットが CI を通らずにマージされる。
4. 消したあと、もう一度 push して CI の緑を待つ: CI を1つのタスクで2回待つ。
5. 記録だけのリポジトリでも消す: 利用者が、そこでは残すと決めた。
6. `small-chestnut` が所有しないリポジトリでも消す: PR が squash でマージされると、記録を足したコミットが main の履歴に残らず、タスクの番号がまた振られる。

## 理由

1. 残す価値のあるものは、マージの時点でほかの置き場(ADR・仕様・各モジュールの CLAUDE.md・コミットメッセージ)にあり、終わった記録は SE・PG・QA の受け渡しを終えて読まれない。
2. 2026-11-01 の `docs/tasks` は22件・3,439行・約29万字で、リポジトリ全体を「用語集」で検索すると当たる24ファイルのうち20ファイルが終わった記録だった。
3. push の前に消せば、消すコミットも CI を通ってからマージされる(ADR 0009-3)。CI が赤のときは、戻せば PG が記録を読み書きできる。
4. 消した記録は git の履歴から取り出せる。タスクの番号は main の履歴にある記録の名前から振るので、消しても重ならない。
