# 0089-1 読む場面が限られる規則の行は、その場面の skill に分け、元の文書にはその skill に従う1行を残す

状態: 採用
日付: 2026-11-17
対象: 全体

## 決めたこと

役割の skill の規則のうち、1つの会話で読む場面が来ないことがあるか、ほかの役割やセッションも読む行は、その場面を名前にした別の skill に分け、元の文書にはその場面でその skill に従う1行だけを残す(分ける行と skill の名前は、タスク 0089 の設計)。

## 捨てた案

1. skill のフォルダの補助ファイル(`reference.md` など)に分ける: Claude Code の文書が勧める形だが、補助ファイルは、呼んだ skill の「Base directory」からしかたどれない。全体の CLAUDE.md と、PG・QA の skill からは、名前で指せない(設定ディレクトリは `CLAUDE_CONFIG_DIR` で変わる)。
2. PL の、チームを作る・タスクを終える行も分ける: PL の会話は何タスクも続き、どちらの場面もタスクごとに来る。読んだ skill は会話の終わりまで残り、圧縮の後も付け直される。分けても同時に読む行は減らず、skill の一覧の説明が、どのセッションにも1つずつ増えるだけ。
3. 元の文書に1行を残さず、skill の説明だけで Claude が呼ぶのに任せる: 説明に当たるかは Claude が判断し、呼ばれないことがある。既にある `ui-mockup` と同じく、元の文書から名前で指す。
4. 分けた skill を読ませる指示をフックで入れる(ADR 0071-1 の形): 読む場面は、ADR を書くと決めたときなど、道具を使った直後とは限らない。
5. 分ける代わりに行を消す: 残る行は、ほかの仕組みが読む形か利用者の決定で、根拠がある(ADR 0088-1)。消すことと分けることを同時に入れると、後で AI の動きが変わったときに、どちらのせいか見分けられない(チケット 0089 の R1)。

## 理由

1. 0088 の後も、SE が同時に読む規則の行は約 256 行(全体の CLAUDE.md 98・skill `task-team` 27・skill `task-team-se` 131)。同時に守らせる指示が増えるほど、守れる割合は落ちる(IFScale, https://arxiv.org/abs/2507.11538)。
2. 読んだ skill の中身は会話の終わりまで残り、自動の圧縮の後も付け直される(https://code.claude.com/docs/en/skills の「Skill content lifecycle」。2026-11-17 に読んだ)。分けて減るのは、その場面が来ない会話か、来るまでの間に読む行だけ。だから、分けるのは、その場面が来ないことがある行(ADR を書く・仕様を直す・書き方の文書がある)と、ほかの役割も読む行(テスト一覧・モデルの割り当て・書き方の文書)に限る。
3. 今は、PG と QA と全体の CLAUDE.md が、skill `task-team-se` の一部の決まりを指していて、その数行のために SE の skill の全部(131 行)を読む。分けた skill なら、その場面の行だけを読む。
4. skill の名前は、Skill の道具でどのセッションからも呼べる。今の skill も、ほかの skill を名前で指している(`ui-mockup`・`prompt-structure`)。
