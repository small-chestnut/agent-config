# 0044-1 IT の用語がある概念は、知らない人に向けた文でも、作った呼び名や例えに置き換えず、IT の用語に意味を添えて書く

状態: 採用
日付: 2026-11-07
対象: 全体

## 決めたこと

IT の用語がある概念は、利用者に向けた文でもリポジトリの文書でも、作った呼び名や例えに置き換えずにその用語で書き、知らない人には初めて出すときに意味を添える。

## 捨てた案

1. 作った呼び名を残し、用語集に IT の用語を書き添える: 用語集を引かない読み手には伝わらず、AI は文書の作った呼び名を返事でも使い続ける。
2. 原則2(知らない人が一度読めば分かる)を原則3 より先にするまま、利用者に向けた文だけ平易な呼び名にする: 利用者は、説明の無い作った呼び名の意味が分からず、まともに説明する気が無いと受け取った。
3. 作った呼び名をフックで見つけて止める: 作った呼び名は前もって一覧にできず、文字列で見分けられない。

## 理由

1. 全体の CLAUDE.md の原則2 は原則3 より先で、「知らない人が一度読めば分かる」を守ろうとした AI が、IT の用語(ハッシュ値・進捗・依存など)を作った呼び名(中身の印・進み具合・前など)に置き換えていた。
2. IT の用語なら、利用者は調べれば意味が分かり、AI も既に意味を持っている。意味を添えれば、知らない人も一度読めば分かるので、原則2 も守れる。
3. 採用した ADR の本文は書き換えないので、古い ADR には作った呼び名が残る。今の言葉は skill と CLAUDE.md にある。
