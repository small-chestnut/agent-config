# 0069-3 難しさが中の仕事にも、高と同じ Opus 5.5 の high を割り当てる

状態: 提案
日付: 2026-11-12
対象: task-team-se
置き換える: 0059-1 の中の割り当て

## 決めたこと

難しさが中の仕事は、Opus 5.5 の medium でなく、高と同じ Opus 5.5 の high で動かす。低は Sonnet 5.5 の medium のまま(詳しい文は skill `task-team-se`)。

## 捨てた案

1. PG の中だけを high にし、QA の中は medium のままにする: 判断する余地があれば SE と同じ思考量が要る、という利用者の理由は、役割によらない。
2. 低も含めて、PG をいつも high にする: 利用者は、SE が全手順を決めきっているなら今の割り当てでよいと答えた。低は、書いてあるとおりにやれば済む仕事(skill `task-team-se`)。
3. 中を xhigh か Fable 5.2 にする: Opus 5.5 の xhigh は、high より SWE-bench Pro で約 1.4 ポイント上で、費用は 2.5 倍(ADR 0067-1 の捨てた案3)。Fable 5.2 は、Opus 5.5 の high で仕上がらない仕事の上げ先として既にある(ADR 0065-1)。
4. 中と高を1つの段にまとめる: 中と高の分け目は、PG の仕事が高にならないように設計を足す決まりと、QA の難しさを高い方にする決まりで使っている(skill `task-team-se`)。割り当てが同じでも、段を消すとそれらを書き直すことになる。

## 理由

1. 利用者は、PG 自身に判断する余地があるなら、SE と同じくらいの思考量が要ると見た(タスクの文)。中は、決まった枠の中で、自分で選ぶ所がある仕事(skill `task-team-se`)。
2. Opus 5.5 の medium は、LogiFee の R-0718 で、SE の判断の誤りが9件起きた設定(ADR 0067-1 の理由1)。
3. Anthropic の測定で、Opus 5.5 の medium から high では、SWE-bench Pro の1件の費用が $0.21 から $0.29(約1.4倍)、解けない割合が 7.2% から 4.7%(ADR 0059-1 の理由2・0067-1 の理由4)。
4. 2026-11-12 に `get_usage` で引いて、全部のモデルの週の枠は 36% で、週の約 38% が過ぎたところ。上がるのは、難しさが中の仕事だけ。
