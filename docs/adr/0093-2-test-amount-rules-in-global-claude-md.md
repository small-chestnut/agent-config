# 0093-2 テストの量の決まりを、いつも読まれる全体の CLAUDE.md に置き、skill `task-team-test-list` を消す

状態: 採用
日付: 2026-11-24
対象: 全体
置き換える: 0089-1 の、テスト一覧の決まりを skill に分ける所

## 決めたこと

作るテストと残すテストを決める決まり(目指す状態「テストは、適正な量になっている」とその下の行)を、全体の CLAUDE.md(`claude/CLAUDE.md`)に置き、skill `task-team-test-list` を消す。

## 捨てた案

1. skill `task-team-test-list` に置く(今のやり方): 読むのは、task-team の SE と QA と、今あるテストを減らすセッションだけ。task-team を通さない会話と、読まなかったセッションは、基準を知らずにテストを作る。
2. テストのファイルを読むか書いたときに読み込まれる `paths` 付きの規則(ADR 0090-2)に置く: どのテストを作るかは、テストのファイルを開く前(テスト一覧を書くとき)に決める。
3. コードを変えるときに消す行も、全体の CLAUDE.md に置く: どれを消すかは SE が設計で決める(ADR 0091-3)。SE のいない会話が、頼まれていない変更のついでに、ほかの人のテストまで消す。この行は SE の skill に移す。
4. 全体の CLAUDE.md と skill の両方に置く: 同じ規則は1か所にだけ置く(skill `prompt-structure`)。

## 理由

1. 利用者の理由: どのリポジトリのテストも、適正な量になること(ADR 0093-1 の理由1)。見るべき時に見るべき規則を参照できていないのは、読む量を減らすことより前の問題(ADR 0092-1 の理由1)。
2. 今の全体の CLAUDE.md だけを読んだセッションは、決まりを足した全体の CLAUDE.md を読んだセッションより、gemini 0094 の要件で約1.6倍、LogiFee の源泉の要件で約2倍のテストを書いた(ADR 0093-1 の理由5の表)。
3. ADR 0089-1 は、その場面が来ない会話のある行を skill に分けた。テストを作るか残すかは、コードを変えるどの会話にも来る。
4. 全体の CLAUDE.md は 4,274 字が 4,420 字になる(上限 5,000 字。ADR 0090-6)。skill 1つが無くなる。
