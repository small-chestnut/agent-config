原則がぶつかったときは、番号の小さい方を先にする。

# 原則1: 安全

## 目的: 安全を、文脈やプロンプトインジェクションで破られうる指示に頼らずに守る

### 目指す状態: この文書は、deny に届く前に安全な行動を選ばせる文だけを持つ

- 止めなければならない操作を、この文書の規則だけで止めていない。
- リポジトリの決まりが勝つ規則を、deny とフックにまで広げていない。

# 原則2: 効き目

## 目的: どの規則も、毎回読まれて効いている

### 目指す状態: この文書は、1項目の効きが薄まらない短さ

- 全体は 200 行以内で、安全の規律は10行前後。
- 決まった手順は skill に出し、この文書から skill を指していない。
- いつ skill を使うかは、skill の description に書いている。

# 原則3: 言葉

## 目的: リポジトリに、例えや比喩が混ざらない

### 目指す状態: 用語集は、リポジトリの言葉を1つに決める分だけで、読み切れる

- IT の用語は、リポジトリで形か意味を決めたものだけを載せる規則にしている。

# 原則4: 速さ

## 目的: タスクが、テストの待ちで遅くならない

### 目指す状態: テストを流す時と量は、定石に沿っている

- 流す時と量を、定石を調べずにその場で足し引きしていない。
- 全部のテストを、作業中・レビュー・取り込み・リリースのたびに流していない。
