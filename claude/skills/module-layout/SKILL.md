# 原則1: AI 側の最適化 ― Claude が、どのリポジトリでも、要るものだけを読み、手戻りなく、作業を終えられる

## 目的: 業務の画面・処理・データの読み書きがその業務のモジュールにあり、1つの作業で開くファイルが1つのフォルダに集まっている(ADR 0012-1)

- モジュールは、利用者が画面のナビやメニューで選ぶ行き先ごとに作り、画面の無いシステムでは、扱うデータのまとまりごとに作る。
- モジュールのフォルダは `modules/<モジュール>/` に置き、どのモジュールのものでもないものは `shared/` に置く。
- ファイルの置き場所は、次の順に当てはめて決める。
  1. 画面と、その画面のための API のエンドポイント → その画面のモジュール
  2. 名前の先頭がその業務の語のもの・その業務のデータを扱うもの → その業務のモジュール。ほかのモジュールから使われていても、その業務のモジュールに置いたままにする
  3. どの業務のものでもないもの → 使うモジュールが1つならそのモジュール、2つ以上なら `shared/`

## 目的: `shared/` には、どの業務のものでもないものだけがある

- `shared/` のファイルに業務の語の名前を書き足すことになったら、その処理をその業務のモジュールへ移す。

## 目的: ほかのモジュールからは公開インターフェースだけが使われ、モジュールの中を変えてもほかのモジュールが壊れない(ADR 0012-2)

- 公開インターフェースは、モジュール直下の1つのファイル。
- 公開インターフェースのファイル名は、言語の慣例(`index.ts`・`__init__.py`)があればそれにし、慣例の無い言語では `<モジュール>Api` にする。

## 目的: モジュールの中で、ファイルの役割が名前か場所で分かる

- 役割がファイル名の末尾で分かるときは、モジュールの中にフラットに置く。
- 役割の違うファイルが同じ名前になるときは、役割の名前のフォルダを作る。

## 目的: テストは、確かめる対象と同じ名前のモジュールのフォルダにある

- モジュールのテストは `tests/modules/<モジュール>/` に、`shared/` のテストは `tests/shared/` に置く。

## 目的: 新しいプロジェクトは、最初からモジュールのフォルダでできている
