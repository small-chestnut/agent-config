# 原則1: 局所性

## 目的: 1つの作業で開くファイルが、1つのモジュールのフォルダに集まっている(ADR 0012-1)

### 目指す状態: 業務の画面・処理・データの出し入れが、その業務のモジュールにある

- モジュールのフォルダは `modules/<モジュール>/` にあり、どのモジュールのものでもないものは `shared/` にある。
- ファイルの置き場所は、次の順に当てて決めている。
  1. 画面と、その画面のための API のエンドポイント → その画面のモジュール
  2. 名前の先頭がその業務の語のもの・その業務のデータを扱うもの → その業務のモジュール。ほかのモジュールから使われていても、その業務のモジュールに置いたままにしている
  3. どの業務のものでもないもの → 使うモジュールが1つならそのモジュール、2つ以上なら `shared/`
- その業務の作業で開くファイルがモジュールのフォルダの外にあるときは、置き場所を見直している。

### 目指す状態: `shared/` には、どの業務のものでもないものだけがある

- `shared/` のファイルに業務の語の名前を書き足すことになったら、その処理をその業務のモジュールへ移している。

### 目指す状態: ほかのモジュールからは、公開の入口だけが使われている(ADR 0012-2)

- ほかのモジュールが使うものは、公開の入口から出している。
- 公開の入口は、モジュール直下の1つのファイル。
- 入口の名前は、言語の慣例(`index.ts`・`__init__.py`)があればそれ。
- 慣例の無い言語では、`<モジュール>Api` にしている。
- 入口の外(内部のクラス・関数・テーブル)は、ほかのモジュールから直接使っていない。

### 目指す状態: モジュールの中で、ファイルの役割が名前か場所で分かる

- 役割がファイル名の末尾で分かるときは、モジュールの中にフラットに置いている。
- 役割の違うファイルが同じ名前になるときは、役割の名前のフォルダを切っている。

### 目指す状態: テストは、確かめる対象と同じ名前のモジュールのフォルダにある

- モジュールのテストは `tests/modules/<モジュール>/` に、`shared/` のテストは `tests/shared/` にある。

### 目指す状態: 新しいプロジェクトは、最初からモジュールのフォルダでできている

- 最上位に、役割の名前のフォルダ(`models/`・`views/`・`controllers/` など)を作っていない。
