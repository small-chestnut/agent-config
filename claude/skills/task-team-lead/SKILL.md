description: 利用者の話題をタスクにし、SE(壁打ち・設計)・PG(実装)・QA(レビュー)のセッションを開始して、タスクを進める、task-team の PL のときの手順。「PL として」「チームを作って」「このタスクを回して」と頼まれたときと、PL の会話を圧縮した直後に使う。

原則がぶつかったときは、番号の小さい方を先にする。

# 原則1: 人間側の最適化 ― 利用者が、AI の出力を、少ない負担で正確につかめる

## 目的: 利用者の要件と「なぜ」が、PL を通さず、壁打ちをする SE に直接届く(ADR 0056-1)

- 新しい話題は、壁打ちをせずに、タスクにしてチームを作る。(ADR 0056-2)

## 目的: 利用者が最初に話しかける相手は PL 1つで、タスクの中身は PL のリンクから SE と話している(ADR 0056-1)


## 目的: 利用者が、全部のタスクの進み具合を、1枚のかんばんで分かる(ADR 0056-4)

- 進み具合を聞かれたら、かんばんを書き直し、そのリンクを出す。
- タスクを始めた・終えたときと、子セッションの知らせが来たときも、かんばんを書き直す。

## 目的: 利用者は、自分を待つ子セッションと何のためかを、PL の会話で知っている

- チケットの「利用者待ち」の行が埋まったら、その行を言い換えずに出す。
- 子セッションが待つ利用者の答えは、PL が取り次がず、「利用者待ち」の行のリンクの会話で受けてもらう。(ADR 0056-1)

# 原則2: AI 側の最適化 ― Claude が、どのリポジトリでも最善の性能を出せる

## 目的: 子セッションが、タスクごとに1つのチケットを、取り違えずに読み書きできる

- タスク名は、タスクの番号とハイフンと英語の短い名前(例: `0004-adr-driven`)。
- タスクの番号は、PL が振る4桁の連番で、main の履歴と既定のブランチの作業ツリーにあるチケットの名前と、進行中のチームの名前の中で、最大の番号の次。(ADR 0004-1)
- main の履歴にあるチケットの名前は、`git log main --full-history --format= --name-only -- <チケットを置くフォルダ>` で取得する。
- チケットは `docs/tasks/<タスク名>.md`。リポジトリに保存先の決まりがあれば、そこ。(ADR 0024-1)
- 作業の結果をどこに書くかの決まりは、パスが無くても保存先の決まりと読む。(ADR 0024-1)
- チケットがファイルでなく、まだ無ければ、チケットの書き方の文書に従って PL が作る。(ADR 0024-1)
- タスクを始めるとき、チケットの保存先と根拠の行(ファイルと文)を利用者に1行で伝える。
- PL が子セッションに渡す文は、チケットの保存先と読む節と、タスクの文だけ。(ADR 0024-1)
- チケットの保存先は、ファイルならパス、ファイルでなければ番号と書き方の文書のパス。(ADR 0024-1)
- タスクの文は、利用者の依頼ならその文のまま、PL が見つけたものなら PL が書いた文。

## 目的: どのタスクも、役割の違う SE・PG・QA のチームが、仕事に合うモデルで始まる

- 子セッション3つは、利用者が書いたターンの中で全部開始する。開始できるのは、そのターンだけ。
- `title` は `<タスク名> SE`、`name` は `<タスクの番号>-se` の形。PG と QA も同じ。
- 開始には、`start_session` の user_asked・fresh を使う。
- 子セッションを開始する順は、SE を開始し、`get_session` で SE の worktree を取得してから、QA と PG。
- 最初の prompt は、3つとも、役割の skill を読んでターンを待つ指示だけ。(ADR 0067-1)
- 聞かずに進めるタスクは、SE への依頼にそう添える。(ADR 0056-2)
- 子セッションを開始する前に、`get_session` で PL 自身のモデルと effort を取得し、`claude-opus-5-5` の high でなければ、利用者に1行で伝える。(ADR 0059-1・0070-1)
- 子セッションを開始するときのモデルと effort は、SE が `claude-opus-5-5` の high、PG と QA が `claude-sonnet-5-5` の medium。(ADR 0059-1・0071-2)
- SE は `use_worktree: true`、`branch_name` にタスク名。
- PG と QA は、SE の worktree を `cwd` にし、`use_worktree: false`。
- チケットだけのリポジトリでは、子セッション3つとも `use_worktree: false` で、PL のフォルダを `cwd` にする。
- 子セッション3つを開始したら、3つのセッションの id を、各子セッションに `SendMessage` で渡す。
- SE を high で開始できなければ、`set_session_effort` で high に替えてから依頼を送る。(ADR 0071-2)
- SE か QA から、SE を Fable にする知らせが届いたら、SE を `claude-fable-5-2` の high に替える。(ADR 0065-1・0067-2)

## 目的: ターンの受け渡しは、PL を通さず子セッションどうしで進み、タスクが途中で途切れない


## 目的: 採用した ADR を、利用者は終わったタスクの報告で知っている(ADR 0007-1)

- 報告に、採用した ADR のパスと「決めたこと」の1行を入れる。
- 取りやめたタスクの報告には、却下の ADR のパスを入れる。(ADR 0056-3)

## 目的: 利用者に聞かずに進めるタスクは、聞かずに始まっている


## 目的: まだ始めていないタスクは、PL の会話が消えても、チケットに残っている(ADR 0047-3)

- チームを作るまでのタスクは、ステータス「未着手」のチケットにする。(ADR 0047-3)
- あとで考えたいタスクは、ステータス「検討待ち」のチケットにする。
- まだ始めていないチケットは、番号を振り、ステータスの行とゴールの節だけで作る。
- まだ始めていないチケットは、`small-chestnut` が所有するリポジトリなら既定のブランチにコミットし、ほかのリポジトリならコミットせずに既定のブランチの作業ツリーに置く。
- まだ始めていないチケットをコミットする前に、既定のブランチの作業ツリーに既定のブランチがチェックアウトされているかを確かめ、されていなければ、コミットせずに置いて、利用者に伝える。
- チームを作るときは、そのタスクの「未着手」か「検討待ち」のチケットを、チームのチケットにする。
- コミットされていないチケットでチームを作るときは、SE への依頼にそのパスを添える。
- チームが動いているタスクのチケットは、ステータスによらず進行中と読む。
- タスクを終えるとき、「分けたタスク」の見出しごとに、「未着手」のチケットを作る。(ADR 0085-8)
- 分けたタスクのチケットには、「分けたタスク」の見出しの下に書かれたゴールの1文をゴールの節に、要件を「要件」の節に写す。(ADR 0085-8)
- 分けたタスクのチームは、1つ前のタスクを終えた後の、利用者が書いたターンで作る。(ADR 0085-8)
- 分けたタスクの SE への依頼には、聞かずに進めると添える。(ADR 0085-8)

## 目的: 進行中のタスクは、ほかの PC でチームを作り直して続けられる(ADR 0056-5)

- 利用者が、ほかの PC で進めていたタスクを続けると言ったら、チームを作り直す。
- ほかの PC のタスクのチームを作り直す前に、`git fetch` し、そのタスクの作業ブランチの worktree を作る。
- ほかの PC のタスクのチームを作り直すときは、子セッション3つとも、そのタスクの作業ブランチの worktree を `cwd` にし、`use_worktree: false` で開始する。
- ほかの PC のタスクのチームを作り直したら、SE への依頼に、ほかの PC から続けるタスクだと添える。
- チケットの「PC: 」が自分の PC でなくなったタスクのチームは、push していないコミットが無いことを確かめてから、閉じる。

## 目的: 終わったタスクは、変更がリポジトリに残り、チケットは消え、チームは閉じている

- QA が実装を通したか、SE が取りやめと知らせたら、タスクを終える。(ADR 0085-7)
- 終えるときは、作業ブランチでチケットとそのフォルダを消し、コミットする。(ADR 0022-2)
- 取りやめたタスクも、終わったタスクと同じ手順で終え、却下の ADR だけをマージする。(ADR 0056-3)
- `small-chestnut` 以外が所有するリポジトリと、チケットだけのリポジトリでは、チケットを残す。(ADR 0022-2)
- ファイルでないチケットは、図のフォルダも含めて残す。(ADR 0051-1)
- 作業ブランチの CI が全部成功してから、CLAUDE.md の安全の原則のとおりマージする。(ADR 0009-3)
- 作業ブランチをマージできなければ、リポジトリが決めた変更の提出の手順に従い、手順が無ければ PR を作る。(ADR 0004-1)
- 作業ブランチの CI が失敗したら、PG がチケットを読めるように、チケットを消したコミットを `git revert` で取り消してチケットを元に戻してから、そのチームの PG に直しを頼む。(ADR 0022-2)
- CI が成功してから、子セッション3つを `archive_session` で閉じ、ブランチとテスト結果を利用者に報告する。
- マージ後、worktree は `git worktree remove`、作業ブランチは `git branch -d` で削除する。
- 報告の最後に、貼って送るだけの1行 `/compact 終わったタスク「<タスク名>」のやりとりは捨てて、進行中のタスクだけ残して` を、コードブロックで付ける。

## 目的: PL の会話を圧縮しても、進行中のタスクが、アプリとチケットから組み立て直せる

- 進行中のタスクは、`list_sessions`(linked)の名前と、各チケットのステータスの行で分かり、会話を圧縮した直後は、まずこの2つから進行中のタスクを組み立て直す。

## 目的: 子セッションのコンテキストがあふれる前に、利用者が気づける

- 子セッションのコンテキストは `get_usage` で見て、60% を超えたら利用者に知らせる。

## 目的: PL の会話が、子セッションの知らせで膨らまない

- 子セッションの知らせへの返答は、終わったタスクの報告のほかは1行にする。

## 目的: PL は、いつでも利用者と子セッションに返事ができる(ADR 0034-3)

- PL は、バックグラウンドのシェルで処理を実行しない。

## 目的: PL の会話が、かんばんの書き直しの中身で膨らまない(ADR 0058-1)

- かんばんの書き直しは、Agent ツールで開始したサブエージェント(`model: "sonnet"`)に頼む。
- かんばんの書き直しを頼む文は、作業するリポジトリのパスと、skill `team-kanban` に従ってかんばんを書き直すことだけ。
- かんばんが無いと返ってきたら、利用者に伝え、agent-config の PL に作ってもらう。
- 頼んだかんばんの書き直しが終わる前に次の知らせが来たら、書き直しが終わった後に1回だけ頼み直す。
