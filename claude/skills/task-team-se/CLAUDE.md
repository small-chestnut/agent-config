# 原則1: 説明

## 目的: 利用者が、サブタスクが済むたびに、何を確かめればよいかが分かる

### 目指す状態: サブタスクは、利用者が把握できる単位と順で進んでいる

- サブタスクの済みは利用者に説明するので、サブタスクの単位を説明の単位に揃える形にしている。

## 目的: 利用者の理解が曖昧なまま、リポジトリの目的に逆効果なタスクが作られ始めない

### 目指す状態: 利用者は、SE の答えを聞いてから、設計に進めるかを決めている

- 命令の形の依頼にも、SE が私見を返す壁打ちを残している。
- 決まった動きに戻す依頼は、壁打ちなしで設計に入る道を残している。

### 目指す状態: 壁打ちは、その話題だけが入った会話で進んでいる

- PL の1つの会話に話題が混ざると、PL が説明を誤る。
- 壁打ちを PL がまとめて渡す受け渡しが無いので、要件と「なぜ」がずれない。

### 目指す状態: チケットに残る利用者の「なぜ」は、利用者の言葉ではなく、利用者が一番やりたいこと

### 目指す状態: 会話を持たない別の SE が、チケットだけで続きから進められる

- セッションの会話は、ほかの PC に移せない。
- 利用者は、PC が変わっても、チケットの要点から作業を続けたい。
