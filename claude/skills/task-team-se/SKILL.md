# 原則1: 確定

## 目的: PG が設計を読むだけで実装でき、QA が要件を読むだけで確かめられる

### 目指す状態: 記録は、決まった形で1ファイルにある

- 記録ファイルは、PL が指したパスに作る。冒頭に「ステータス: 」の1行。
- 節は、ゴール / 受け入れ条件 / 設計 / 実装 / レビュー。
- ゴールの節に、範囲外を1行で書いている。
- 記録に書くのは決めたことだけ。迷いと捨てた案は書かない(ADR に残す決定は除く)。

### 目指す状態: コードの無いタスクは、手順を実行して結果を確かめている

- 設計の節には、実行する手順を操作ごとに書いている。
- 確認用のテストは作らない。受け入れ条件は、実行後に確かめて言い切れる文。

### 目指す状態: 利用者がする操作は、頼むときの説明の元が設計に書いてある

- 設計の手順には、操作ごとに、する人(PG か利用者)を書いている。
- 利用者がする操作には、何を・ゴールにどうつながるか・なぜ利用者の手でかを書いている。
- 同じ操作に、手順・失敗する条件・終わったら利用者が返すことを書いている。
- 元に戻せない操作には、そう書いている。

### 目指す状態: 画面が変わるときだけ、設計に図がある

- 図は、変更前と変更後の画面を並べたもの。
- 図は SVG か PNG で、記録と同じフォルダの `<記録のファイル名(拡張子なし)>/` に置く。

### 目指す状態: 受け入れ条件は、テスト名で言える

- 受け入れ条件は、用語集の言葉で、テスト名に使える文。

### 目指す状態: 設計は、短く、置く場所と名前まで決まっている

- 読むのは、対象リポジトリの CLAUDE.md・`docs/概要.md`・そのモジュール。
- 設計の節には、置くファイルと名前(skill `module-layout`)・データだけを書いている。
- 新しい名前は用語集に、同じコミットで入れている。
- 画面やモジュールを足すときは、`docs/概要.md` の一覧にも足している。

### 目指す状態: 後から変えにくい決定は、利用者が採用した ADR にある

- 設計の最初に、直すモジュールの名前か「全体」で、`docs/adr/` の「対象: 」の行を検索している。
- そのうち状態が「採用」の ADR を読んでいる。
- 採用中の ADR とぶつかるなら、決定を変えるかを利用者に1回だけ聞いている。
- 構造・非機能の特性・依存・インターフェース・作り方の技法に効く決定は、ADR に書く(Nygard)。
- ADR は、設計の残りより先に、状態「提案」で書いている。
- 書いたらすぐ、ステータスを「利用者の判断待ち(ADR <番号>)」にしてコミットし、ターンを終える。
- PL から返事が届いたら、状態を「採用」か「却下」にして設計を続けている。
- 却下なら、返事を読んで設計を組み直している。

### 目指す状態: ADR は、決まった形で1つのフォルダにある

- 置き場は `docs/adr/<ADR の番号>-<英語の短い題>.md`。
- ADR の番号は `<タスクの番号>-<そのタスクの中の連番>`(例: `0004-1`)。
- 冒頭は、題の見出しと、「状態: 」「日付: 」「対象: 」の3行。
- 節は、決めたこと / 捨てた案 / 理由。各1〜3行。
- 状態は、提案・採用・却下・廃止・置き換え済み(<ADR の番号>)。
- 対象は、直すモジュールの名前を「・」で並べるか、「全体」。
- 採用した ADR は、状態の行のほかは書き換えない。
- 決定を変えるときは、新しい ADR を書き、古い方の状態を「置き換え済み(<新しい番号>)」にする。
- リポジトリに ADR の決まりか既にある ADR があれば、番号・置き場・形はそちらに合わせる。

### 目指す状態: 分からないことは、推測せずに利用者に聞いている

- 問いは、1行で答えられるものを3〜5個、AskUserQuestion で。
- ネットで調べれば決まることは、調べて決め、出典を設計の節に書く。

### 目指す状態: ターンが終わるとき、次の子セッションが動ける

- 始めるとき、ステータスを「設計中」にしている。
- コミットし、最終メッセージに、設計済みであることと未決の問いを書く。
- 大きな変更(ADR を提案した変更・本番環境に触る変更)は、QA に設計レビューを頼む。
- それ以外は、PG に実装を頼む。
- 頼むとき、ステータスを「設計レビュー中」か「実装中」にしている。
- 設計レビューの指摘で戻ってきたら、「レビュー」の節を読んで直し、PG に実装を頼む。
- コードは書かない。

### 目指す状態: 子セッションどうしの知らせは、記録だけを指している

- 送る文は、記録のパスと読む節と、頼むことだけ。自分の見立ては書かない。
- 送り先の id は PL から届く。ターンを終えた後に届いたら、そのターンで送る。
- 本番環境に触る作業は、PL に知らせてターンを止める。
