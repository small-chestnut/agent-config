# 原則1: AI 側の最適化 ― Claude が、どのリポジトリでも、要るものだけを読み、手戻りなく、作業を終えられる

## 目的: モデルと effort が足りずにやり直すことも、費用をかけすぎることも無い(ADR 0059-1)

- 役割の仕事ごとの難しさを、理由と一緒に、チケットの「難しさ」の節に書く。
- 難しさは、やることが仕様・設計・規則でどこまで決まっているかで決める。
- 低は、書いてあるとおりにやれば済む仕事。
- 高は、自分で選ぶ所がある仕事。仕様・設計・規則に答えが無く、それらそのものを決める仕事も含む。(ADR 0070-1)
- SE の難しさは、いつも高。(ADR 0067-1)
- PG と QA の難しさは、設計を書き終えたときに決める。
- PG に、仕様・設計・規則そのものを決める所が残るなら、設計を足す。
- 低は `claude-sonnet-5-5` の high。(ADR 0070-2)
- 高は `claude-opus-5-5` の high。(ADR 0070-1)
- 設計を書き終えたら、頼む前に、PG と QA のモデルと effort を替える。

## 目的: Opus では仕上がらない仕事で、やり直しを重ねず、使う費用に見合う出来になる(ADR 0065-1)

- Fable は `claude-fable-5-2` の high。
- 次の3つがそろう仕事は、始める前に、モデルを Fable にすると決めている: (1) 仕様・設計・規則そのものを決める仕事か、その設計レビューである。(2) 利用者が中身を確かめられない分野の知識が要る。(3) 決定どうしがつながり、1つ変えるとほかが合わなくなる。(ADR 0070-1)
- タスクに分けても1つの会話に収まらないと見込める仕事も、始める前に、モデルを Fable にすると決める。(ADR 0085-8)
- 同じタスクで入れた決定を消すか、同じ決まりを3回変えたら、その仕事のモデルを Fable にすると決める。
- 入れた決定を消すとは、このタスクの ADR を、却下・廃止・置き換え済みにするか消すこと。(ADR 0067-2)
- 設計レビューの指摘に応えて提案を却下にしたものは、入れた決定に数えない。(ADR 0067-2)
- 同じ決まりを変えるとは、このタスクの ADR の決めたことを書き換えるか、置き換えること。(ADR 0067-2)
- コミットするたびに、このタスクの ADR の `git log -p` で、入れた決定を消したか、同じ決まりを3回変えたかを確かめる。(ADR 0067-2)
- SE のモデルを Fable にすると決めたら、PL に知らせる。
- PG と QA のモデルを Fable にすると決めたら、仕事を頼む前に、モデルを替える。
