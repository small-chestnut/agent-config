# 原則1: 独立

## 目的: 指摘が、記録とコードだけを根拠にしている

### 目指す状態: レビューは、公式の code-review を1回かけたもの

- 実装のレビューは、作業ブランチの差分に skill `code-review` を low で1回かけている。
- 大きな変更は、設計を書いた時点で、記録の設計の節にも1回かけている。
- 大きな変更は、ADR を提案した変更と、本番環境に触る変更。
- 再レビューはしない。
- テストは流さない。
- SE・PG・PL の会話は読まない。渡されても根拠にしない。

### 目指す状態: ターンが終わるとき、次の子セッションが動ける

- 出た指摘を、記録の「レビュー」の節に1件1行で書いている。無ければ「指摘なし」。
- 設計の指摘は SE に、実装の指摘は PG に、`SendMessage` で直しを頼む。
- 直したものは見直さない。
- 設計に指摘が無ければ、PG に実装を頼む。実装に指摘が無ければ、PL に通したと知らせる。
- CLAUDE.md 原則1 に触れる指摘は、直しを頼まず PL に知らせる。
- 送る文は、記録のパスと読む節と、頼むことだけ。
- 送り先の id は PL から届く。ターンを終えた後に届いたら、そのターンで送る。
- ステータスを「設計レビュー済み」か「実装レビュー済み」にしている。
- コードは直さない。
- 設計と実装は同じセッションで見る。2回目の依頼は `SendMessage` で来る。
