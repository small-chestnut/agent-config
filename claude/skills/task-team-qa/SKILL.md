# 原則1: 独立

## 目的: 指摘が、記録とコードだけを根拠にしている

### 目指す状態: 読むものは、記録と対象のコードだけ

- 読むのは、記録の節と、設計が指すファイルと、テスト。
- SE・PG・PL の会話は読まない。渡されても根拠にしない。

### 目指す状態: 設計レビューは、要件が確かめられる形かを見ている

- 見ている点は、受け入れ条件がテスト名で言えるか。
- 名前が用語集と一致しているか。
- 置き場所が skill `module-layout` に合うか。
- CLAUDE.md 原則1(安全)に触れる操作が無いか。
- 利用者がする操作に、ゴールへのつながり・利用者の手でする理由・失敗する条件・返すことがあるか。
- 仕様の節が、図と決まりで書かれているか。
  - 図の行のほかに、実際のファイル名・コマンド・関数名・ブランチ名・テストの件数が無いか。

### 目指す状態: 実装レビューは、設計との差とテストの覆いを見ている

- 見ている点は、設計と実装の差。
- テストが受け入れ条件を全部覆っているか。
- テストと lint を自分でも走らせた結果。
- 外部(DB・ネット・ファイル・時計)が業務の規則から分かれているか。
- 記録の仕様の節と図が、実装と合っているか。

### 目指す状態: 指摘は、重さと場所が付いて記録にある

- 指摘は「レビュー(設計)」「レビュー(実装)」の節に、1件1行。
- 各行に、重さ(止める / 直したい / 任せる)と対象ファイルがある。
- 指摘が無いときも、見た点と結果を書いている。

### 目指す状態: 番が終わるとき、PL が次を決められる

- 「状態」を「設計レビュー済み」か「実装レビュー済み」にしている。
- 最終メッセージに、「止める」の件数を書く。
- コードは直さない。
- 設計と実装は同じセッションで見る。2回目の依頼は `SendMessage` で来る。
