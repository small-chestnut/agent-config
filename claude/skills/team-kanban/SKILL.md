# 原則1: 一致

## 目的: 利用者が、かんばんを見るだけで、全部のタスクの今が分かる

### 目指す状態: かんばんは、利用者のアカウントに1枚で、どの PC からも同じものが開く(ADR 0056-4)

- かんばんは、名前が「チームかんばん」の Artifact。
- かんばんは、Artifact の一覧から名前で探している。
- 無ければ、利用者に伝え、agent-config の PL に作ってもらっている。
- 利用者に出すリンクは、かんばんの URL に `#<リポジトリの名前>` を付けたもの。

### 目指す状態: カードは、チケットの今と同じ

- カードは、チケット1つに1枚。
- カードは、`git fetch` の後の、既定のブランチとリモートの作業ブランチのチケットから作っている。
- まだ始めていないチケットは既定のブランチに、進行中のチケットは作業ブランチにある。
- 書き直すのは、自分のリポジトリのカードだけ。

### 目指す状態: カードのデータは、チケットの行をそのまま写している

- データは、かんばんの `datasets/cards` が指す JSON のファイルで、カード1枚が1行。
- 1行の項目は、`repo`・`machine`・`task`・`goal`・`status`・`done`・`total`・`waitingLine`。
- `repo` は、リモートのリポジトリの名前。リモートが無ければ、フォルダの名前。
- `task` はタスク名、`status` はステータスの行、`goal` はゴールの節の1行目。
- `machine` は「PC: 」の行。無ければ空。
- `done` と `total` は、進捗の節の、済みのサブタスクの数と全部の数。無ければ null。
- `waitingLine` は、利用者待ちの行から会話へのリンクを除いた文。「なし」なら空。
- どの列に出すかは、かんばんのページが `status` から決めている。

### 目指す状態: 書き直しは、ほかの PL が書いたカードを消さない

- 書き直す前に、今のデータのファイルを読んでいる。
- 自分のリポジトリの行だけを入れ替え、新しいファイルをかんばんに上げている。
- `datasets/cards` の `source.url` を新しいファイルに替え、古いファイルを消している。
- 同じ書き込みで、`updated` の `at` を今の時刻にしている。
- `datasets/cards` を書くときは、読んだ `version` を `if_version` に付けている。
- 書き込みが断られたら、読み直してやり直している。
