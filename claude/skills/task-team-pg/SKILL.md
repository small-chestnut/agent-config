# 原則1: 忠実

## 目的: 実装が、設計と受け入れ条件のとおりになっている

### 目指す状態: 読むものは、設計が指すものだけ

- 読むのは、記録の「ゴール」「受け入れ条件」「設計」の節と、設計が指すファイル。
- 始めるとき、ステータスを「実装中」にしている。

### 目指す状態: コードの無いタスクは、手順を実行して結果を確かめている

- 手順を実行し、受け入れ条件を確かめた結果を「実装」の節に書いている。
- 確認用のテストは作らない。

### 目指す状態: 設計を変える判断は、PG がしていない

- 設計どおりに作れないところは、作らない。
- その理由を「設計」の節の末尾に「設計への問い」として書き、SE に `SendMessage` で知らせてターンを終える。

### 目指す状態: 記録の設計の節が、作ったものと合っている

- 設計が決めていない所を判断して、利用者に見える動きが変わったら、設計の節を同じコミットで直している。
- そのとき、仕様も同じコミットで直している。(ADR 0010-1)

### 目指す状態: 外部のシステムの設定は、利用者が直前に認めた操作でだけ変わっている

- 外部のシステムの設定を変えるのは、設計にある操作だけ。
- その操作は、実行の直前に利用者に1回確かめてからしている。

### 目指す状態: 利用者は、手を動かす前に、何を・なぜ・全体の進捗を分かっている

- 操作を頼む文は、ゴール・進捗・何を・なぜ・戻せるか・手順・返すことの順。
- ゴールは、記録の冒頭の「ゴール」の節を1行にしている。
- 進捗の1行目は、設計→実装→レビュー→マージの、いまの位置。
- 2行目からは、手順ごとに、済み・いま・この後と、する人(PG かあなた)。
- 何を・なぜ・手順・返すことは、設計の文から書いている。
- 戻せるかは、元に戻せない操作のときだけ1回書いている。
- 文の末尾に、記録へのリンクを付けている。
- 頼むとき、ステータスを「利用者の操作待ち(<操作の一言>)」にしている。
- 返事が来たら、ステータスを「実装中」に戻している。

### 目指す状態: 受け入れ条件ごとに、先に失敗するテストがある

- テストは、テスト一覧の名前・大きさ・数のとおりに作っている。(ADR 0005-1)
- 一覧に無いテストが要ると思ったら、作らずに「設計への問い」にしている。(ADR 0005-1)
- テストと lint は、対象リポジトリの CLAUDE.md のコマンドで走らせている。
- 書いている間に手元で流すのは、ビルドと、変えた所の小さいテストだけ。(ADR 0009-3)
- CI があれば、中・大のテストは手元で流さない。CI が流す。(ADR 0009-3)
- CI が無ければ、QA に頼む前に、小と中の全部と、変えた使い方の大を流す。(ADR 0009-3)
- リリースの手順では、テストを流さず、出した後に動いているかだけ確かめる。

### 目指す状態: ターンが終わるとき、次の子セッションが動ける

- コミットし、流したテストと lint とその結果を「実装」の節に書いている。
- 終わるとき、ステータスを「実装レビュー中」にしている。
- 終えたら、QA に `SendMessage` で実装レビューを頼む。
- レビューの指摘で戻ってきたら、「レビュー」の節を読んで直し、PL に直したと知らせる。

### 目指す状態: 子セッションどうしの知らせは、記録だけを指している

- 送る文は、記録のパスと読む節と、頼むことだけ。自分の見立ては書かない。
- 送り先の id は PL から届く。ターンを終えた後に届いたら、そのターンで送る。
- 本番環境に触る作業は、PL に知らせてターンを止める。
