# 原則1: 意図

## 目的: AI が、規則に無いことでも、利用者の意図どおりに動けるようにする

### 目指す状態: どの規則も、親の段を読めば、なぜあるかが分かる

- 段は「原則 → 目的 → 目指す状態 → 規則」の入れ子で書く。
- 見出しは原則が `#`、目的が `##`、目指す状態が `###`、規則は箇条書き(この skill と同じ形)。
- 理由は、親の段に任せる。
- 原則は体言1つで、下に置く目的すべてと適合するものにする。
- 目的は、下の状態がそろえば達成したと言える文にする。
- 目指す状態は、AI の振る舞いかプロンプトを見て、保たれているかを言い切れる文にする。
- プロンプトは、一般の文だけで書く。
- 利用者の発言の引用は、プロンプトに置かず、コミットメッセージに書く。

### 目指す状態: 手法を書いた段に、意味の定まった IT の用語が添えてある(ADR 0045-1)

- 手法を書いた段には、意味が1つに定まった IT の用語を末尾に括弧で添える。
- 段全体の手法なら目指す状態に、1つの規則の手法ならその規則に添える。
- 出典ごとに定義が割れる用語と、規則と定義が違う用語は、添えない。

### 目指す状態: 原則どうしがぶつかっても、どちらを先にするかが決まっている

- 原則には番号を付け、2つ以上あれば冒頭に「原則がぶつかったときは、番号の小さい方を先にする。」を置く。

### 目指す状態: AI の態度が一貫している

- 規則は「〜でいる」の形(保つ状態)で書く。

## 目的: 利用者が、全部を見張らなくても、プロンプトを思いどおりに保てるようにする

### 目指す状態: 原則・目的・目指す状態は、利用者が合意したものだけ

- Claude は、この3段を提案までにとどめる。

### 目指す状態: 規則は、状態だけでは AI が守れなかった所にだけある

- Claude が規則に手を入れるのは、「違う」と言われたときと、規則が目的に反するときだけ。(ADR 0046-1)
- 直すときは、守れなかった状態を先に決め、その状態の下で規則を足す・直す・消す。
- 規則は、することを肯定形で書く。(ADR 0027-1)
- 足しても振る舞いが変わらなかった規則は消す。
- 2つの状態にまたがる規則は、主な方の下に1回だけ置く。
- 同じ規則は、文書をまたいでも1か所にだけ置く。
