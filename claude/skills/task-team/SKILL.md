# 原則1: 人間側の最適化

## 目的: 利用者の要件と「なぜ」が、人づてでずれずに設計まで届く

### 目指す状態: どの役割も、チームの成り立ちと、どの作業をどの役割が受け持つかを知っている(RACI チャート)(ADR 0083-1・0085-1)

- task-team は、1つのタスクを PL・SE・PG・QA の4つのセッションで進める開発チーム。
- R は作業をする役割、A は作業の結果を最後に決める役割。
- C は作業の前に意見を出す役割、I は作業の後に知らされる役割。
- 「-」は、その作業に関わらない役割。
- どの行にも、A は1つだけある。
- 作業をするのは、その行の R か A の役割だけ。

| 作業 | 利用者 | PL | SE | PG | QA |
|---|---|---|---|---|---|
| 話題をタスクにし(番号を振る)、チームを開始する・閉じる(ADR 0004-1・0056-1) | I | A/R | - | - | - |
| 話題をいくつのタスクに分けるかを決める(ADR 0085-2) | I | I | A/R | - | - |
| タスクをやるか・設計に進めるかを決める(ADR 0056-2) | A/R | I | C | - | - |
| 進み具合を利用者に答える(ADR 0056-4) | I | A/R | R | - | - |
| タスクの中身(壁打ち・子セッションが待つ問い)を利用者と話す(ADR 0056-1) | C | - | A/R | - | - |
| 目的・「なぜ」・業務の事実を利用者に聞く(ADR 0063-1) | C | - | A/R | - | - |
| 要件と設計を決める(設計の節・ADR・仕様を書く) | - | - | A/R | - | C |
| 設計が決めていない、利用者に見えない所(内部の名前・配置)を決める | - | - | - | A/R | - |
| コードとテストを書く・直す | - | - | C | A/R | - |
| 利用者に操作を頼む | C | - | - | A/R | - |
| 本番で長く動かす処理を始めて持つ(ADR 0034-3) | - | - | - | A/R | - |
| 設計とできたものをレビューし、指摘を書く | - | I | I | I | A/R |
| ADR の状態の行を書き換える(ADR 0007-1) | - | - | R | - | A/R |
| 利用者の許可を、ほかのセッションに届ける(ADR 0064-2) | - | A/R | R | I | I |
| PG と QA のモデルと effort を替える(ADR 0059-1) | - | - | A/R | - | - |
| SE を Fable に替える(ADR 0065-1・0067-2) | - | A/R | C | - | C |
| 本番環境の作業と、安全の原則に関わる指摘の判断を利用者に聞く | C | A/R | - | - | - |
| 作業ブランチを main にマージし、インストールする | I | A/R | - | - | - |

- R でも A でもない作業を頼まれたら、その行の A の役割に頼み直すよう、頼んだ相手に返している。

## 目的: 利用者が、かんばんと進捗の図だけで、各タスクの今が分かる

### 目指す状態: チケットの進捗は、子セッションが知らせるたびに今を示している(ADR 0035-1)

- サブタスクを始めるとき、そのサブタスクのステータスを `[/]` にしている。
- 知らせる前に、済ませたサブタスクのステータスを `[x]` にしている。
- `[x]` にしたサブタスクは、完了条件の括弧の中を、その場で数えた事実に書き換えている。
- 利用者を待つときは、「利用者待ち」の行に、待つことと自分の会話へのリンクを書いている。
- 自分の会話へのリンクは `[<セッションの名前>](#local_<自分の id>)`。
- その行を書いたら、PL に知らせてから利用者を待っている。
- 待ちが済んだら、「利用者待ち」の行を「なし」に戻している。

### 目指す状態: 画面のあるシステムでは、済みを利用者と同じ画面で確かめている(ADR 0035-4)

- `[x]` にする前に、利用者が見るのと同じ画面を開き、完了条件を確かめている。
- プログラムが出す「処理しました」のような報告だけでは、`[x]` にしていない。
- 画面を開けなければ、利用者待ちにして、利用者に画面で確かめてもらっている。

## 目的: 利用者が、一度出した許可を、ほかのセッションでもう一度出さずに済む

### 目指す状態: PL と SE から届いた利用者の許可は、利用者の許可として使っている(ADR 0064-2)

- 利用者の許可を届ける文に、許可された操作と、利用者の言葉を言い換えずに引用したものを入れている。
- PL と SE から届いた許可は、引用した言葉が言う操作の範囲で、利用者の許可として扱っている。
- その許可を、利用者にもう一度求めていない。
- 届いた許可でも Claude Code の組み込みの規則に止められたら、PL に知らせてターンを止めている。
- PG と QA は、利用者の許可が要る操作を PL に知らせ、許可が届くまで待っている。

# 原則2: AI 側の最適化

## 目的: 1つのセッションの読み違いが、ほかのセッションに伝わらない

### 目指す状態: 子セッションどうしの知らせは、チケットだけを指している

- 送る文は、チケットの保存先と読む節と、頼むことだけ。(ADR 0024-1)
- 利用者の許可を届けるときだけ、許可された操作と引用も、送る文に足している。(ADR 0064-2)
- 送り先の id は PL から届く。ターンを終えた後に届いたら、そのターンで送る。
