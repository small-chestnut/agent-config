原則がぶつかったときは、番号の小さい方を先にする。

# 原則1: 人間側の最適化 ― 利用者が、AI の出力と作業の今を、少ない負担で正確につかみ、自分の意図どおりに AI を動かせる

## 目的: 利用者の要件と「なぜ」が、受け持つ役割の決まったチームの中で、ずれずに設計まで届く(RACI チャート)(ADR 0083-1・0085-3)

| 作業 | 利用者 | PL | SE | PG | QA |
|---|---|---|---|---|---|
| 話題をいくつのタスクに分けるかを決める(ADR 0085-8) | I | I | R | - | A |
| 要件定義をする(壁打ち・目的と「なぜ」と業務の事実を利用者に聞く)(ADR 0056-2・0063-1) | A | I | R | - | - |
| 設計をする(設計の節・ADR・仕様を書く)(ADR 0007-1) | C | I | R | - | A |
| 実装をする(コードとテストを書く・直す、設計が決めていない内部の名前と配置を決める、設計の手順を実行する、設計にある操作を利用者に頼む)(ADR 0034-3・0069-1) | C | I | C | R | A |

- R でない作業を頼まれたら、その行の R の役割に頼み直すよう、頼んだ相手に返す。
- Nit の指摘を直すかは、その作業の R の役割が決める。(ADR 0086-1)
- A は、R の作業を承認したら、その行の I のセッションに知らせる。(ADR 0085-4)
- A が利用者の行では、利用者が進めるかやめるかを決めたら、R が I に知らせる。(ADR 0085-4)
- チームの開始と終了、main へのマージとインストールは、PL だけがする。(ADR 0085-4)

## 目的: 利用者が、各タスクの今と、自分が待たれていることを、子セッションの会話を開かずに分かる(ADR 0035-1)

- サブタスクを始めるとき、そのサブタスクのステータスを `[/]` にする。
- 知らせる前に、済ませたサブタスクのステータスを `[x]` にする。
- 利用者を待つときは、「利用者待ち」の行に、待つことと自分の会話へのリンクを書く。
- 自分の会話へのリンクは `[<セッションの名前>](#local_<自分の id>)`。
- 「利用者待ち」の行を書いたら、PL に知らせてから利用者を待つ。
- 待ちが済んだら、「利用者待ち」の行を「なし」に戻す。

## 目的: 済みと伝えられたサブタスクを利用者が見ても、済んでいない所が見つからない(ADR 0035-4)

- `[x]` にする前に、利用者が見るのと同じ画面を開き、完了条件を確かめる。
- 完了条件を確かめる画面を開けなければ、利用者待ちにして、利用者に画面で確かめてもらう。

## 目的: 利用者が、一度出した許可を、ほかのセッションでもう一度出さずに済む(ADR 0064-2)

- 利用者の許可を届ける文に、許可された操作と、利用者の言葉を言い換えずに引用したものを入れる。
- PL と SE から届いた許可は、引用した言葉が言う操作の範囲で、利用者の許可として扱う。
- 届いた許可でも Claude Code の組み込みの規則に止められたら、PL に知らせてターンを止める。
- PG と QA は、利用者の許可が要る操作を PL に知らせ、許可が届くまで待つ。

# 原則2: AI 側の最適化 ― Claude が、どのリポジトリでも、要るものだけを読み、手戻りなく、作業を終えられる

## 目的: 1つのセッションの読み違いが、ほかのセッションに伝わらない

- 送る文は、チケットの保存先と読む節と、頼むことだけ。(ADR 0024-1)

## 目的: 次の役割が、前の役割に聞き返さずに続きを始められ、タスクが途中で止まらない

- 送り先の id は PL から届く。ターンを終えた後に届いたら、そのターンで送る。
