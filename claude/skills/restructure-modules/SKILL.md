# 既存のプロジェクトをモジュールのフォルダに組み替える手順

置き場所の決め方は `~/.claude/CLAUDE.md` の「モジュールの分け方」に従う。
この手順は、動かすときに壊れる所を先に塞ぐためのもの。

## 手順

1. **動かす前に、動きの記録を取る。**
   例: テストを走らせて結果をファイルに保存する / 登録される URL の一覧・テーブル定義の一覧を書き出す。
   後で同じ記録を取り、突き合わせる。

2. **ファイルの中身を変えずに、場所だけ動かす(`git mv`)。**
   git が名前の変更として扱うので、合流前のブランチの変更が新しい場所へそのまま載る。
   言語が場所を書かせる所(Python の import など)だけを同じ作業で直し、
   それ以外(C# の名前空間をフォルダに合わせる、など)は別の作業にする。

3. **型やファイルを名前空間・パッケージ名で探して登録する仕組みを、検索して直す。**
   例: DI(クラスを自動で作って渡す仕組み)の自動登録・プラグインの読み込み・ORM のモデル検出。
   場所を動かすと、ビルドは通るのに登録から黙って漏れる。

4. **ファイルの場所から相対でパスを組んでいる所を、検索して直す。**
   例: Python の `__file__`・`os.path.dirname` から組んだパス、`../../config` のような相対パス。
   フォルダの深さが変わると、別の場所を指す。

5. **動かした後に 1 と同じ記録を取り、機械で突き合わせる。**
   差があれば、その差を直してから次のモジュールへ進む。

## 失敗する条件

- 1 を飛ばすと、3 や 4 の漏れに気づく手段が無い。
- 中身の変更と移動を同じコミットに混ぜると、git が名前の変更として扱えず、合流のときに衝突する。
