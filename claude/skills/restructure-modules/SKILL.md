原則がぶつかったときは、番号の小さい方を先にする。

# 原則1: 安全

## 目的: ファイルを動かしても、動きが変わらない

### 目指す状態: 動かす前と後の動きを、比べて確かめられる

- 動かす前に、動きの記録(テストの結果・登録される URL の一覧・テーブル定義の一覧)を取って、ファイルに保存している。
- 動かした後に同じ記録を取り、diff で比べている。差があれば、その差を直してから次のモジュールへ進んでいる。

### 目指す状態: 移動の変更が、ほかのブランチの変更とぶつからない

- ファイルは、中身を変えずに `git mv` で場所だけ動かしている。
- 移動と同じコミットで直すのは、場所が変わるとビルドや実行が通らなくなる所(import の行)だけ。場所に合わせたそれ以外の書き換えは、別のコミットにしている。

### 目指す状態: ファイルの場所を前提にした仕組みが、動かした後も同じものを指している

- 型やファイルを名前空間・パッケージ名で探して登録する仕組み(DI の自動登録・プラグインの読み込み・ORM のモデル検出)を検索して、直している。
- ファイルの場所から相対でパスを組んでいる所(`__file__`・`os.path.dirname` から組んだパス、`../` で始まるパス)を検索して、直している。
