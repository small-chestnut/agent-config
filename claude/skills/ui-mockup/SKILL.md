# 実装後の画面の絵の描き方

利用者は、提案を文章で読むより、実装後の画面を見て判断する。だから絵は文章より先に出す。

## 置き方

- 絵は返答の冒頭に置く(tl;dr の枠があればその直後)。
- 会話の中にそのまま表示される形(HTML か SVG の描画)で出す。それができない環境では、
  HTML ファイルに書き出し、ブラウザで開くためのパスを示す。
- 文章の説明は絵の後に書く。絵に見えている文字(ボタン名・見出しなど)か、絵に振った番号で、
  どの部分の話かを示す。

## 描き方

- 実装後にその画面を開いたときと同じ見た目に近づける。色・文字の大きさ・部品の形は、
  そのプロジェクトの既存画面に合わせる。
- 見本の値は、その業務で実際にありそうな値にする。
- 画面のどこにあるかが分かる範囲まで描く。
- 既存の画面を変えるときは、変更前と変更後を並べ、変わる箇所に印を付ける。
- 画面が複数あるときは、利用者が操作する順に並べる。
