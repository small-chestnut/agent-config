# 原則1: 人間側の最適化

## 目的: 利用者が、実装を待たずに、提案を正しく判断できる

### 目指す状態: 図は、実装後に開いたときと同じ見た目になっている

- 色・フォントサイズ・コンポーネントの形は、そのプロジェクトの既存の画面に合わせている。
- サンプルデータは、その業務で実際にありそうな値になっている。
- 画面のどこにあるかが分かる範囲まで描いている。

### 目指す状態: 何が変わるかが一目で分かる

- 既存の画面を変えるときは、変更前と変更後を並べ、変わる箇所に印を付けている。
- 画面が複数あるときは、利用者が操作する順に並べている。
