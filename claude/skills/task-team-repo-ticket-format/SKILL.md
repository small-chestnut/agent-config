# 原則1: AI 側の最適化 ― Claude が、どのリポジトリでも最善の性能を出せる

## 目的: PG が設計を読むだけで実装でき、QA が要件を読むだけで確かめられる

### 目指す状態: チケットは、決まった形で1か所にある

- チケットに同じ節か「ステータス: 」の行が2つ以上あれば、いちばん新しいものを読む。(ADR 0051-1)
- 書き方の文書の決まりと skill `task-team-se` のテンプレートがぶつかったら、書き方の文書の方に従う。(ADR 0085-5)

### 目指す状態: 進捗の節から、サブタスクのつながりと今の状態が分かる(ADR 0035-1)

- 書き方の文書の進捗の形でも、依存と作業中のステータスは、skill `task-team-se` の進捗の節の形で足している。
- 書き方の文書の進捗の形で書くときは、利用者待ちの行を「PC: 」の次の行に置いている。

### 目指す状態: 画面が変わるときだけ、設計に図がある

- チケットがファイルでなく、書き方の文書に添付の仕方も無ければ、図と画像は `docs/tasks/<タスク名>/` に置き、チケットから指す。(ADR 0051-1)
